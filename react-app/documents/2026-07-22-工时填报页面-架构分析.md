## 五、核心模块详解

### 5.1 类型定义 (types.ts)

**职责**：定义数据模型和类型约束

**核心类型**：
- `TimesheetStatus`：联合类型，表示工时状态（待提交/已提交/已审批）
- `TimesheetItem`：工时记录接口，包含 id、date、project、task、hours、status、description
- `TimesheetFormData`：表单输入接口，hours 为字符串类型，提交时转换
- `TimesheetContextValue`：Context 值接口，定义状态和操作方法

**工具函数**：
- `generateId()`：基于时间戳 + 随机数生成唯一 ID
- `INITIAL_DATA`：3 条示例数据，用于页面初始化

### 5.2 状态管理 (TimesheetContext.tsx)

**职责**：全局状态管理与数据操作

**核心实现**：
```typescript
// 创建 Context，初始值为 null
const TimesheetContext = createContext<TimesheetContextValue | null>(null)

// 自定义 Hook：封装 useContext + 空值校验
function useTimesheet(): TimesheetContextValue {
  const context = useContext(TimesheetContext)
  if (!context) throw new Error('useTimesheet must be used within TimesheetProvider')
  return context
}

// Provider 组件：管理 records 状态，提供操作方法
function TimesheetProvider({ children }) {
  const [records, setRecords] = useState<TimesheetItem[]>([])
  // addRecord, deleteRecord, toggleStatus
}
```

**关键特性**：
- 使用 `useState` 管理 records 数组
- 函数式更新：`setRecords(prev => ...)` 确保基于最新状态
- 状态不可变更新：`[...prev, newRecord]`、`prev.filter()`、`prev.map()`
- `toggleStatus` 实现状态循环切换：pending → submitted → approved → pending

### 5.3 页面入口 (TimesheetPage.tsx)

**职责**：页面布局与 Provider 包裹

**组件分层**：
- `TimesheetPage`：用 `TimesheetProvider` 包裹 `TimesheetPageContent`
- `TimesheetPageContent`：页面布局，使用 `useEffect` 初始化示例数据

**布局结构**：
```
┌──────────────────────────────┐
│      工时填报 (标题)          │
├──────────────────────────────┤
│   TimesheetForm (表单)       │
├──────────────────────────────┤
│   TimesheetStats (统计)      │
├──────────────────────────────┤
│   工时记录 (标题)            │
│   TimesheetList (列表)       │
└──────────────────────────────┘
```

### 5.4 表单组件 (TimesheetForm.tsx)

**职责**：工时数据录入与验证

**核心特性**：
- **受控组件**：所有输入通过 `value + onChange` 绑定
- **表单验证**：日期必填、项目名称必填、任务描述必填、工时范围 0.5-12
- **动态样式**：`inputStyle(field)` 根据错误状态动态生成红色边框
- **错误管理**：`Record<string, string>` 存储字段级错误信息
- **useRef 聚焦**：提交后自动聚焦日期输入框

**数据流**：
```
用户输入 → handleChange → setFormData → 清除对应错误
                              │
                              ▼
                         用户提交 → validate → addRecord → 清空表单
```

### 5.5 列表组件 (TimesheetList.tsx)

**职责**：工时记录展示与行级交互

**组件结构**：
- `TimesheetList`：表格容器，空状态处理，map 遍历渲染
- `TimesheetRow`：单行组件，接收 props，处理切换状态和删除

**交互功能**：
- 鼠标悬停高亮行
- 切换状态按钮：显示下一个状态 tooltip
- 删除按钮：红色边框样式

### 5.6 统计面板 (TimesheetStats.tsx)

**职责**：工时数据汇总展示

**计算方法**：
- `reduce` 累加总工时：`records.reduce((sum, r) => sum + r.hours, 0)`
- `filter` 统计各状态数量：`records.filter(r => r.status === 'pending').length`

**展示布局**：4 列 CSS Grid 等宽网格，每个统计卡片包含图标、标签、数值

### 5.7 状态标签 (StatusBadge.tsx)

**职责**：根据状态值渲染不同颜色的标签

**实现方式**：
- 使用 `Record<TimesheetStatus, {label, color, bgColor}>` 配置映射
- 三种状态对应三种颜色：橙色(待提交)、蓝色(已提交)、绿色(已审批)

## 六、关键技术点

### 6.1 状态管理方案

| 维度 | 方案 | 原因 |
|------|------|------|
| 状态存储 | `useState` | 数据量小，结构简单 |
| 状态共享 | `createContext` + `Provider` | 避免 prop drilling |
| 状态消费 | 自定义 Hook `useTimesheet()` | 封装 useContext + 空值校验 |

### 6.2 数据更新模式

```typescript
// 追加记录：展开运算符创建新数组
setRecords(prev => [...prev, newRecord])

// 删除记录：filter 返回新数组
setRecords(prev => prev.filter(r => r.id !== id))

// 更新状态：map 返回新数组
setRecords(prev => prev.map(r => {
  if (r.id !== id) return r
  return { ...r, status: nextStatus }
}))
```

### 6.3 TypeScript 类型系统

- **接口 (interface)**：定义对象结构，如 `TimesheetItem`、`TimesheetFormData`
- **联合类型**：`TimesheetStatus = 'pending' | 'submitted' | 'approved'`
- **Record 泛型**：`Record<TimesheetStatus, Config>` 实现类型安全的映射
- **FormEvent 类型**：`e: FormEvent` 类型化的表单事件处理
- **ChangeEvent 类型**：`React.ChangeEvent<HTMLInputElement | HTMLTextAreaElement>`

### 6.4 组件通信方式

| 通信方向 | 方式 | 示例 |
|---------|------|------|
| 父 → 子 | Props | `TimesheetProvider` → `TimesheetPageContent` |
| 父 → 子 | Context | `TimesheetProvider` → 所有子组件 |
| 子 → 父 | 回调函数 | `TimesheetRow` → `TimesheetList` (onDelete, onToggleStatus) |
| 兄弟组件 | Context | `TimesheetForm` 与 `TimesheetList` 通过 Context 共享数据 |

## 七、设计模式总结

### 7.1 Provider-Consumer 模式

通过 `createContext` 创建全局状态容器，`TimesheetProvider` 作为数据源，所有子组件通过 `useTimesheet()` 消费数据，实现跨组件状态共享。

### 7.2 自定义 Hook 模式

`useTimesheet()` 封装 `useContext` 调用，添加空值校验逻辑，提供类型安全的状态访问方式，避免在每个组件中重复编写 `useContext` 和错误处理。

### 7.3 单向数据流

数据从 `TimesheetProvider` 单向流向子组件，操作通过回调函数或 Context 方法触发，状态变更后重新渲染，符合 React 的单向数据流原则。

### 7.4 组件分层架构

```
页面层 (TimesheetPage)
    │ 负责：Provider 包裹、页面布局
    ▼
功能组件层 (TimesheetForm, TimesheetStats, TimesheetList)
    │ 负责：业务逻辑、数据操作、列表渲染
    ▼
展示组件层 (TimesheetRow, StatusBadge)
    └─ 负责：UI 渲染、样式展示、接收 props
```

### 10.1 React Hooks 核心概念

**Hook 是什么？**

Hook 是 React 16.8 引入的新特性，让你在不编写 class 组件的情况下使用 state 和其他 React 特性。简单说，Hook 就是"在函数组件里用的特殊函数"。

**Timesheet 中用到的 Hook：**

| Hook | 作用 | 使用位置 |
|------|------|---------|
| `useState` | 管理组件内部状态 | TimesheetContext, TimesheetForm |
| `useContext` | 消费 Context 提供的数据 | TimesheetContext, TimesheetPageContent |
| `useEffect` | 处理副作用（如初始化数据） | TimesheetPage |
| `useRef` | 获取 DOM 元素引用 | TimesheetForm |

### 10.2 useState - 状态管理

**作用**：在函数组件中添加状态变量，使组件能够"记住"数据并响应变化。

**核心概念**：
- 状态（State）是组件的"记忆"，存储可能变化的数据
- 状态变化时，React 自动重新渲染组件，更新 UI
- 没有状态 = 纯展示组件，状态变化 = 响应式 UI

**基本语法**：
```typescript
const [状态变量, 更新函数] = useState(初始值)
```

**示例 - 管理工时记录列表**：
```typescript
// 在 TimesheetContext.tsx 中
const [records, setRecords] = useState<TimesheetItem[]>([])
```

**解读**：
- `records`：当前状态值，初始为空数组 `[]`
- `setRecords`：更新状态的函数，调用后会触发组件重新渲染
- `<TimesheetItem[]>`：TypeScript 类型注解，表示 records 是 TimesheetItem 类型的数组

**示例 - 管理表单数据**：
```typescript
// 在 TimesheetForm.tsx 中
const [formData, setFormData] = useState<TimesheetFormData>({
  date: '',
  project: '',
  task: '',
  hours: '',
  description: '',
})
```

**解读**：
- `formData`：保存表单所有字段的数据
- `setFormData`：更新表单数据
- 初始值是一个对象，所有字段为空字符串

**示例 - 管理错误信息**：
```typescript
// 在 TimesheetForm.tsx 中
const [errors, setErrors] = useState<Record<string, string>>({})
```

**解读**：
- `errors`：存储字段级错误信息，如 `{ date: '请选择日期', hours: '请输入有效数字' }`
- `Record<string, string>`：键和值都是字符串的对象类型

**useState 执行流程**：
```
首次渲染：
  useState(初始值) → 返回 [初始值, 更新函数]
  组件渲染 → 显示初始状态

用户操作（如提交表单）：
  调用 setRecords(newData) → 标记组件需要重新渲染
  React 重新执行组件函数
  useState(newData) → 返回 [newData, 更新函数]
  组件渲染 → 显示新状态
```

**重要规则**：
1. **不要直接修改状态**，始终使用 `setXxx` 函数
   ```typescript
   // 错误：直接修改不会触发渲染
   records.push(newRecord)
   
   // 正确：通过 setRecords 更新
   setRecords(prev => [...prev, newRecord])
   ```

2. **使用函数式更新**确保基于最新状态
   ```typescript
   // 错误：可能基于旧状态更新
   setRecords([...records, newRecord])
   
   // 正确：基于上一状态更新
   setRecords(prev => [...prev, newRecord])
   ```

3. **状态更新是异步的**，调用 `setRecords` 后 `records` 不会立即变化
   ```typescript
   setRecords(prev => [...prev, newRecord])
   console.log(records)  // 仍显示旧值！
   // 新值在下一次渲染时才可用
   ```

4. **对象状态更新需要展开运算符**，否则会用新对象完全替换
   ```typescript
   // 错误：丢失其他字段
   setFormData({ date: '2026-07-22' })  // project, task 等字段丢失
   
   // 正确：保留其他字段
   setFormData(prev => ({ ...prev, date: '2026-07-22' }))
   ```

### 10.3 useContext - 跨组件共享数据

**作用**：在组件树中共享数据，避免"prop drilling"（逐层传递 props）。

**核心概念**：
- 传统方式：父组件 → 子组件 → 孙组件，props 逐层传递（prop drilling）
- 问题：中间组件不需要数据，但必须透传 props
- Context 方案：在顶层提供数据，任意深层子组件直接消费

**使用场景**：
- 全局主题（light/dark）
- 用户认证信息
- 全局状态管理（如 timesheet 的工时记录）
- 多语言国际化

**两步使用流程**：

**第一步：创建 Context 并提供数据**
```typescript
// TimesheetContext.tsx
const TimesheetContext = createContext<TimesheetContextValue | null>(null)

function TimesheetProvider({ children }) {
  const [records, setRecords] = useState<TimesheetItem[]>([])

  return (
    <TimesheetContext.Provider value={{ records, addRecord, deleteRecord, toggleStatus }}>
      {children}
    </TimesheetContext.Provider>
  )
}
```

**解读**：
- `createContext(null)`：创建一个空的 Context 容器
- `<TimesheetContext.Provider>`：包裹子组件，通过 `value` 传入数据
- `value` 包含状态数据（`records`）和操作方法（`addRecord` 等）
- `children`：被 Provider 包裹的所有子组件

**第二步：在子组件中消费数据**
```typescript
// TimesheetPageContent.tsx
function TimesheetPageContent() {
  const { addRecord } = useTimesheet()  // 自定义 Hook 内部使用了 useContext
  // ...
}
```

**解读**：
- 通过 `useTimesheet()` 获取 Context 中的 `addRecord` 方法
- 调用 `addRecord(formData)` 即可更新全局状态，所有消费该 Context 的组件都会重新渲染

**Context 数据流图**：
```
┌──────────────────────────────────────────┐
│           TimesheetProvider               │
│  ┌────────────────────────────────────┐  │
│  │  createContext 创建 Context         │  │
│  │  useState 管理 records 状态        │  │
│  │  addRecord/deleteRecord/toggleStatus│ │
│  └──────────────┬─────────────────────┘  │
│                 │ Provider 提供 value     │
│  ┌──────────────┴─────────────────────┐  │
│  │  TimesheetPageContent              │  │
│  │  ┌──────────┬──────────┬────────┐ │  │
│  │  │  Form    │   Stats  │  List  │ │  │
│  │  │(消费)    │ (消费)    │ (消费) │ │  │
│  │  └──────────┴──────────┴────────┘ │  │
│  └────────────────────────────────────┘  │
└──────────────────────────────────────────┘
```

**为什么需要自定义 Hook useTimesheet？**

直接在每个组件中写 `useContext(TimesheetContext)` 有安全隐患：如果组件不在 Provider 内部，会拿到 `null`。自定义 Hook 可以统一处理空值校验。

**实现**：
```typescript
// TimesheetContext.tsx
function useTimesheet(): TimesheetContextValue {
  const context = useContext(TimesheetContext)
  if (!context) {
    throw new Error('useTimesheet must be used within a TimesheetProvider')
  }
  return context
}
```

**解读**：
- 以 `use` 开头是 React 的约定，表示这是一个 Hook
- 内部调用 `useContext` 获取数据
- 如果 context 为 `null`（不在 Provider 内），抛出错误，方便调试
- 返回完整 Context 值，调用方按需解构：`const { records, addRecord } = useTimesheet()`

**使用**：
```typescript
// 任何子组件都可以直接使用
function TimesheetForm() {
  const { addRecord } = useTimesheet()  // 获取添加记录的方法
  const { records } = useTimesheet()    // 获取记录列表
}
```

**对比：不使用 Context 的问题**：
```typescript
// 没有 Context 时，props 需要逐层传递
<TimesheetPage
  records={records}
  addRecord={addRecord}
  onDelete={handleDelete}
>
  <TimesheetPageContent
    records={records}
    addRecord={addRecord}
  >
    <TimesheetForm
      addRecord={addRecord}  // 深层组件需要这么多层传递！
    />
  </TimesheetPageContent>
</TimesheetPage>
```

**使用 Context 后**：
```typescript
// 任意深层组件直接获取，无需中间组件传递
function TimesheetForm() {
  const { addRecord } = useTimesheet()  // 直接获取
}
```

### 10.4 useEffect - 处理副作用

**作用**：在组件渲染后执行副作用操作，如数据获取、DOM 操作、订阅等。

**核心概念**：
- 副作用（Side Effect）：组件渲染过程中的"外部操作"
- 纯渲染：根据 props/state 生成 JSX，不操作外部世界
- 副作用：操作 DOM、发起网络请求、订阅事件、设置定时器
- React 原则：渲染是纯函数，副作用应在 useEffect 中处理

**常见副作用场景**：
- 数据获取（API 调用）
- 订阅事件（如 window resize）
- 操作 DOM（如聚焦输入框）
- 设置定时器（setTimeout/setInterval）
- 日志记录、埋点统计

**基本语法**：
```typescript
useEffect(回调函数, 依赖数组)
```

**示例 - 页面初始化数据**：
```typescript
// TimesheetPage.tsx
useEffect(() => {
  INITIAL_DATA.forEach((data) => addRecord(data))
}, [])  // 空依赖数组
```

**解读**：
- 回调函数：页面渲染后执行的代码
- `[]`：依赖数组为空，表示**仅在组件首次挂载时执行一次**
- 相当于 class 组件的 `componentDidMount`

**依赖数组的三种写法**：

| 写法 | 含义 | 执行时机 | 示例 |
|------|------|---------|------|
| `[]` | 仅首次执行 | 组件挂载时 | 页面初始化数据 |
| `[dep1, dep2]` | 依赖变化时执行 | 挂载 + 依赖变化时 | 监听某个变量变化 |
| 不传 | 每次渲染都执行 | 每次渲染后 | 一般不推荐 |

**示例 - 依赖数组为空的含义**：
```typescript
useEffect(() => {
  console.log('页面加载，初始化数据')
  INITIAL_DATA.forEach((data) => addRecord(data))
}, [])  // [] 表示不依赖任何变量
```

**执行时机**：
```
首次渲染：
  组件渲染 → 显示空状态
  useEffect 执行 → 加载 INITIAL_DATA
  setRecords 更新 → 触发重新渲染

重新渲染：
  useEffect 不执行（因为依赖数组为空）
```

**示例 - 依赖变量的含义**：
```typescript
useEffect(() => {
  console.log('userId 变化了，重新获取用户数据')
  fetchUser(userId)
}, [userId])  // 只有 userId 变化时才执行
```

**执行时机**：
```
首次渲染：
  userId = 1
  组件渲染 → 显示用户数据
  useEffect 执行 → fetchUser(1)

userId 变为 2：
  组件渲染 → 显示用户数据
  useEffect 执行 → fetchUser(2)（因为 userId 变化了）

其他状态变化（如 formData.date 变化）：
  组件渲染
  useEffect 不执行（因为 userId 没变）
```

**示例 - 清理函数（清理副作用）**：
```typescript
useEffect(() => {
  const timer = setInterval(() => {
    console.log('定时执行')
  }, 1000)

  // 清理函数：组件卸载时执行
  return () => {
    clearInterval(timer)  // 清除定时器，防止内存泄漏
  }
}, [])
```

**解读**：
- `return () => { ... }`：清理函数，在组件卸载或下次副作用执行前调用
- 作用：防止内存泄漏，清理定时器、订阅、事件监听等
- 类比：租房到期搬走时恢复房屋原状

**示例 - 聚焦输入框**：
```typescript
// TimesheetForm.tsx
useEffect(() => {
  dateRef.current?.focus()
}, [formData.date])  // date 变化时重新聚焦
```

**解读**：
- 当 `formData.date` 变化时，重新聚焦日期输入框
- `?.` 可选链：如果 `dateRef.current` 为 null 则不执行

### 10.5 useRef - 获取 DOM 引用

**作用**：获取或引用 DOM 元素，或保存一个不触发重新渲染的值。

**核心概念**：
- ref（reference）是"引用"，让你可以直接操作 DOM 元素
- 与 useState 的区别：修改 ref.current **不会**触发重新渲染
- 适合场景：操作 DOM、保存临时值、访问子组件实例

**两种主要用途**：

**用途一：获取 DOM 元素引用**
```typescript
// TimesheetForm.tsx
const dateRef = useRef<HTMLInputElement>(null)

// 在 JSX 中绑定到 input
<input ref={dateRef} type="date" name="date" />

// 在提交后聚焦
if (dateRef.current) {
  dateRef.current.focus()
}
```

**解读**：
- `useRef<HTMLInputElement>(null)`：创建一个 ref 对象，初始值为 null
- `ref={dateRef}`：将 ref 绑定到 DOM 元素
- `dateRef.current`：获取实际的 DOM 元素（类似 `document.getElementById`）
- `?.` 可选链操作符：如果 current 为 null 则不执行，避免报错
- `focus()`：使输入框获得焦点，光标出现在输入框中

**执行流程**：
```
首次渲染：
  useRef 创建 ref 对象，current = null
  <input ref={dateRef} /> 绑定 ref
  渲染完成后，dateRef.current = 实际的 DOM 元素

用户提交表单：
  dateRef.current.focus()  → 光标回到日期输入框
```

**常见 DOM 操作**：
```typescript
// 聚焦输入框
inputRef.current.focus()

// 设置输入框值
inputRef.current.value = '新值'

// 获取输入框值
const value = inputRef.current.value

// 滚动到元素
scrollRef.current.scrollIntoView({ behavior: 'smooth' })

// 操作 canvas
canvasRef.current.getContext('2d')
```

**用途二：保存不触发重新渲染的值**
```typescript
function Counter() {
  const [count, setCount] = useState(0)
  const prevCountRef = useRef(0)  // 保存上一次的 count 值

  useEffect(() => {
    prevCountRef.current = count  // 每次 count 变化时更新
  }, [count])

  return (
    <div>
      当前值: {count}
      上次值: {prevCountRef.current}  {/* 显示上次值，不触发重新渲染 */}
    </div>
  )
}
```

**解读**：
- `prevCountRef` 保存上一次的 count 值
- 修改 `prevCountRef.current` 不会触发重新渲染
- 可以访问"上一次"的状态值，绕过 React 的异步更新

**useRef vs useState 对比**：

| 特性 | useRef | useState |
|------|--------|----------|
| 修改后是否重新渲染 | 否 | 是 |
| 适用场景 | DOM 引用、临时值 | 影响 UI 的数据 |
| 读取值 | `ref.current` | 直接读取变量 |
| 初始值 | `useRef(初始值)` | `useState(初始值)` |
| 值变化通知 | 无通知 | 触发重新渲染 |

**示例对比**：
```typescript
// 使用 useState - 修改触发重新渲染
const [count, setCount] = useState(0)
setCount(count + 1)  // UI 更新，显示新值

// 使用 useRef - 修改不触发重新渲染
const countRef = useRef(0)
countRef.current = countRef.current + 1  // UI 不变，值已更新
```

**在 timesheet 中的使用场景**：
```typescript
// 场景：用户提交表单后，光标自动回到日期输入框
// 这样用户无需手动点击，可以继续输入下一条记录

const dateRef = useRef<HTMLInputElement>(null)

const handleSubmit = (e: FormEvent) => {
  e.preventDefault()
  addRecord(formData)
  setFormData({ date: '', project: '', ... })  // 清空表单
  
  // 重新聚焦日期输入框
  if (dateRef.current) {
    dateRef.current.focus()
  }
}
```

### 10.6 自定义 Hook - useTimesheet

**作用**：封装可复用的状态逻辑。

**为什么需要自定义 Hook？**

直接在每个组件中写 `useContext(TimesheetContext)` 有安全隐患：如果组件不在 Provider 内部，会拿到 `null`。自定义 Hook 可以统一处理空值校验。

**实现**：
```typescript
// TimesheetContext.tsx
function useTimesheet(): TimesheetContextValue {
  const context = useContext(TimesheetContext)
  if (!context) {
    throw new Error('useTimesheet must be used within a TimesheetProvider')
  }
  return context
}
```

**解读**：
- 以 `use` 开头是 React 的约定，表示这是一个 Hook
- 内部调用 `useContext` 获取数据
- 如果 context 为 `null`（不在 Provider 内），抛出错误，方便调试
- 返回完整 Context 值，调用方按需解构：`const { records, addRecord } = useTimesheet()`

**使用**：
```typescript
// 任何子组件都可以直接使用
function TimesheetForm() {
  const { addRecord } = useTimesheet()  // 获取添加记录的方法
  const { records } = useTimesheet()    // 获取记录列表
}
```

### 10.7 表单处理 - 受控组件

**什么是受控组件？**

表单输入的值由 React 状态控制，用户输入时更新状态，状态决定显示值。

**完整流程**：
```typescript
// 1. 定义状态
const [formData, setFormData] = useState({ date: '', project: '', ... })

// 2. 输入变化时更新状态
const handleChange = (e) => {
  const { name, value } = e.target  // 获取输入框的 name 和 value
  setFormData(prev => ({ ...prev, [name]: value }))  // 更新对应字段
}

// 3. JSX 中绑定 value 和 onChange
<input
  name="date"
  value={formData.date}
  onChange={handleChange}
/>
```

**解读**：
- `name="date"`：输入框的 name 属性，用于识别是哪个字段
- `value={formData.date}`：显示状态中的值
- `onChange={handleChange}`：用户输入时触发，更新状态
- `[name]`：计算属性名，根据 `name` 的值动态更新对应字段

**表单提交**：
```typescript
const handleSubmit = (e: FormEvent) => {
  e.preventDefault()  // 阻止表单默认提交行为（页面刷新）
  if (!validate()) return  // 验证失败则中断
  addRecord(formData)  // 调用 Context 方法添加记录
  setFormData({ date: '', project: '', ... })  // 清空表单
}
```

**解读**：
- `e.preventDefault()`：阻止表单默认提交（页面刷新）
- `FormEvent`：TypeScript 类型，表示 HTML 表单事件
- `e.target`：触发事件的 DOM 元素

### 10.8 表单验证

**验证逻辑**：
```typescript
const validate = (): boolean => {
  const newErrors: Record<string, string> = {}  // 存储错误信息

  if (!formData.date.trim()) {
    newErrors.date = '请选择日期'
  }
  if (!formData.project.trim()) {
    newErrors.project = '请输入项目名称'
  }
  const hoursNum = parseFloat(formData.hours)
  if (!formData.hours || isNaN(hoursNum)) {
    newErrors.hours = '请输入有效数字'
  } else if (hoursNum < 0.5 || hoursNum > 12) {
    newErrors.hours = '工时范围：0.5 - 12'
  }

  setErrors(newErrors)
  return Object.keys(newErrors).length === 0  // 无错误则返回 true
}
```

**解读**：
- `Record<string, string>`：类型，表示键值对都是字符串的对象
- `trim()`：去除字符串两端空格
- `parseFloat()`：将字符串转为浮点数
- `isNaN()`：判断是否为 NaN（非数字）
- `Object.keys(newErrors).length === 0`：如果错误对象没有键，说明验证通过

### 10.9 列表渲染 - map

**作用**：将数组转换为 JSX 元素列表。

**示例 - 渲染工时记录列表**：
```typescript
{records.map((record) => (
  <TimesheetRow
    key={record.id}
    record={record}
    onDelete={handleDelete}
    onToggleStatus={handleToggleStatus}
  />
))}
```

**解读**：
- `records.map(...)`：遍历数组，每个元素执行回调函数
- `key={record.id}`：**必须**提供唯一 key，帮助 React 识别哪些元素改变了
- `record`：当前遍历到的工时记录对象
- `onDelete` / `onToggleStatus`：回调函数，传递给子组件处理交互

**重要规则**：
1. 必须提供 `key`，且 key 在列表中唯一
2. 不要用数组索引作为 key（数据变化时会导致渲染错误）
3. `map` 返回新数组，不会修改原数组

### 10.10 数据计算 - reduce 和 filter

**reduce - 累加计算**：
```typescript
// 计算总工时
const totalHours = records.reduce((sum, r) => sum + r.hours, 0)
```

**解读**：
- `reduce`：将数组"折叠"为单个值
- `(sum, r) => sum + r.hours`：累加函数，sum 是累计值，r 是当前元素
- `0`：初始值，sum 从 0 开始
- 等价于：`0 + 记录1.hours + 记录2.hours + 记录3.hours = 总工时`

**filter - 筛选数据**：
```typescript
// 统计待提交数量
const pendingCount = records.filter(r => r.status === 'pending').length
```

**解读**：
- `filter`：筛选出符合条件的元素，返回新数组
- `r => r.status === 'pending'`：判断函数，返回 true 则保留
- `.length`：获取筛选后数组的长度

### 10.11 状态不可变更新

**为什么不能直接修改状态？**

React 通过比较引用判断状态是否变化。直接修改状态不会触发重新渲染。

**错误写法**：
```typescript
// 直接修改 - 不会触发重新渲染！
records.push(newRecord)
setRecords(records)
```

**正确写法**：
```typescript
// 创建新数组 - 触发重新渲染
setRecords(prev => [...prev, newRecord])
```

**三种不可变更新模式**：

| 操作 | 方法 | 示例 |
|------|------|------|
| 追加 | 展开运算符 | `setRecords(prev => [...prev, newItem])` |
| 删除 | filter | `setRecords(prev => prev.filter(r => r.id !== id))` |
| 更新 | map | `setRecords(prev => prev.map(r => r.id === id ? { ...r, status: 'submitted' } : r))` |

### 10.12 TypeScript 类型系统

**interface - 定义对象结构**：
```typescript
interface TimesheetItem {
  id: string       // 字符串类型
  date: string     // 日期字符串
  project: string  // 项目名称
  task: string     // 任务描述
  hours: number    // 工时数（数字）
  status: TimesheetStatus  // 状态（联合类型）
  description: string  // 详细说明
}
```

**解读**：
- `interface`：定义对象的结构，类似"模板"
- 每个字段格式：`字段名: 类型`
- 实现时对象必须包含所有字段，类型必须匹配

**联合类型 - 限制取值范围**：
```typescript
type TimesheetStatus = 'pending' | 'submitted' | 'approved'
```

**解读**：
- `type`：定义类型别名
- `|`：表示"或"，status 只能是三个字符串之一
- 好处：拼写错误时 TypeScript 会报错，IDE 会提示可选值

**Record 泛型 - 类型安全的映射**：
```typescript
const STATUS_CONFIG: Record<TimesheetStatus, { label: string; color: string }> = {
  pending: { label: '待提交', color: '#e67e22' },
  submitted: { label: '已提交', color: '#2980b9' },
  approved: { label: '已审批', color: '#27ae60' },
}
```

**解读**：
- `Record<Keys, Value>`：自动生成所有 Keys 到 Value 的映射
- 这里表示：每个 TimesheetStatus 都对应一个包含 label 和 color 的对象
- 好处：如果漏写某个状态，TypeScript 会报错

// 父组件传递

function TimesheetRow({ record, onDelete }: TimesheetRowProps) {

// TimesheetForm 调用 addRecord 更新状态

### 10.15 关键知识点速查表

| 知识点 | 代码示例 | 一句话解释 |
|--------|---------|-----------|
