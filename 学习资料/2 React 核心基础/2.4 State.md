# State 详解：状态管理与更新机制

---

## State 的定义

State 是组件的"记忆"，用于存储会随时间变化的数据。当 state 变化时，React 会自动重新渲染组件，更新 UI。

**核心特点：**
- State 是组件私有的，只能在组件内部访问和修改
- State 变化触发重新渲染
- State 应该是不可变的，通过创建新值而非修改原值来更新
- 使用 `useState` Hook 在函数组件中管理 state

## State 基本用法

### 1. 基本状态

```jsx
import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      你点击了 {count} 次
    </button>
  );
}
```

- **useState 调用**：`useState(0)` 创建 state，初始值为 0
- **解构赋值**：`count` 是当前 state 值，`setCount` 是更新 state 的函数
- **命名约定**：`[值, set值]`，如 `[count, setCount]`
- **事件绑定**：`onClick={() => setCount(count + 1)}` 点击时调用 setCount 更新 state

### 2. 多个状态变量

```jsx
function LoginForm() {
  const [username, setUsername] = useState('');
  const [password, setPassword] = useState('');
  const [isSubmitting, setIsSubmitting] = useState(false);

  return (
    <form>
      <input value={username} onChange={e => setUsername(e.target.value)} />
      <input type="password" value={password} onChange={e => setPassword(e.target.value)} />
      <button disabled={isSubmitting}>登录</button>
    </form>
  );
}
```

- **独立 state**：每个 `useState` 调用创建一个独立的 state 变量
- **受控组件**：`value={username}` 将 state 绑定到输入框
- **onChange 绑定**：`onChange={e => setUsername(e.target.value)}` 输入变化时更新 state
- **disabled 绑定**：`disabled={isSubmitting}` 将 state 值绑定到按钮禁用状态

### 3. 对象状态

```jsx
function UserForm() {
  const [user, setUser] = useState({ name: '', email: '' });

  return (
    <form>
      <input value={user.name} onChange={e => setUser({ ...user, name: e.target.value })} />
      <input value={user.email} onChange={e => setUser({ ...user, email: e.target.value })} />
    </form>
  );
}
```

- **对象展开**：`{ ...user, name: e.target.value }` 创建新对象，保留原属性并覆盖 name
- **不可变更新**：必须创建新对象，不能直接修改原对象
- **独立更新**：每个输入框调用 `setUser` 创建新对象，更新对应字段

### 4. 数组状态

```jsx
function TodoList() {
  const [todos, setTodos] = useState([]);

  const addTodo = () => {
    setTodos([...todos, { id: Date.now(), text: '新任务' }]);
  };

  const removeTodo = (id) => {
    setTodos(todos.filter(todo => todo.id !== id));
  };

  return (
    <div>
      <button onClick={addTodo}>添加</button>
      <ul>
        {todos.map(todo => (
          <li key={todo.id}>
            {todo.text}
            <button onClick={() => removeTodo(todo.id)}>删除</button>
          </li>
        ))}
      </ul>
    </div>
  );
}
```

- **数组展开**：`[...todos, {...}]` 创建新数组，追加新元素
- **数组过滤**：`todos.filter(todo => todo.id !== id)` 创建新数组，过滤指定元素
- **列表 key**：`key={todo.id}` 是列表渲染必需的 key 属性
- **箭头函数事件**：`onClick={() => removeTodo(todo.id)}` 点击时调用 removeTodo 并传入 id

## State 更新机制

### 1. 状态是快照

每次渲染都有自己独立的状态快照：

```jsx
function handleClick() {
  console.log(count);  // 0
  setCount(count + 1);
  console.log(count);  // 仍然是 0！
}
```

- **快照值**：`console.log(count)` 输出的是当前渲染的快照值
- **状态更新**：`setCount(count + 1)` 请求 React 用新值进行下一次渲染
- **不变性**：调用 set 函数后，当前渲染中的 count 值不会改变

### 2. 基于上一次状态更新

```jsx
// 错误：基于同一个旧值
setCount(count + 1);
setCount(count + 1);
setCount(count + 1);  // 结果：1

// 正确：使用更新函数
setCount(prev => prev + 1);
setCount(prev => prev + 1);
setCount(prev => prev + 1);  // 结果：3
```

- **闭包陷阱**：`setCount(count + 1)` 三次调用都基于同一个 count 快照值
- **更新函数**：`setCount(prev => prev + 1)` 传入更新函数，React 按顺序执行
- **参数 prev**：`prev` 是上一次 state 值，返回新的 state 值

### 3. 不可变更新原则

```jsx
// 错误：直接修改原对象
user.name = '新名字';
setUser(user);

// 正确：创建新对象
setUser({ ...user, name: '新名字' });

// 数组：创建新数组
setTodos([...todos, newTodo]);
setTodos(todos.filter(todo => todo.id !== id));
setTodos(todos.map(todo => todo.id === id ? { ...todo, done: true } : todo));
```

- **对象展开**：`{ ...user, name: '新名字' }` 创建新对象
- **数组展开**：`[...todos, newTodo]` 创建新数组
- **数组过滤**：`todos.filter(todo => todo.id !== id)` 创建新过滤数组
- **数组映射**：`todos.map(todo => ...)` 遍历数组，匹配项创建新对象
- **不可变原则**：所有更新方式都遵循不可变原则，创建新值而非修改原值

### 4. 惰性初始化

```jsx
const [todos, setTodos] = useState(() => {
  return JSON.parse(localStorage.getItem('todos')) || [];
});
```

- **惰性初始化**：`useState(() => {...})` 传入函数作为初始值
- **首次执行**：初始值函数仅在首次渲染时执行

## 常见陷阱与最佳实践

### 1. 异步更新中的闭包陷阱

```jsx
const [count, setCount] = useState(0);

useEffect(() => {
  const interval = setInterval(() => {
    setCount(prev => prev + 1);  // 使用更新函数
  }, 1000);
  return () => clearInterval(interval);
}, []);
```

- `setInterval` 内的闭包捕获的是初始渲染时的 count 值
- `setCount(prev => prev + 1)` 使用更新函数获取最新值

### 2. 最佳实践

1. **合理拆分状态**，不相关的状态分开存储
2. **遵循不可变更新**，使用展开运算符或数组方法
3. **派生状态在渲染时计算**，避免 useEffect 同步
4. **使用更新函数**处理基于上一次状态的更新

---

## 总结

State 是 React 组件的核心：

- **本质**：组件的记忆，存储随时间变化的数据
- **更新**：通过 setter 函数创建新值，不可变更新
- **快照**：每次渲染有独立的状态快照
