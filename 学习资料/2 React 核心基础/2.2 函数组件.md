# 函数组件详解：定义、渲染与生命周期

---

## 函数组件的定义

函数组件是 React 中最基础的组件形式，它是一个**纯 JavaScript 函数**，接收 props 作为参数，返回 JSX 描述 UI 结构。

**核心特点：**
- 本质是函数，输入 props，输出 JSX
- 代码简洁，易于理解和测试
- 配合 Hooks 拥有完整的能力（状态、副作用等）
- 是 React 官方推荐的主要组件编写方式

## 函数组件基本用法

### 1. 最简单的函数组件

```jsx
function Greeting() {
  return <h1>你好，React!</h1>;
}
```

- `function Greeting` 是函数组件定义，函数名使用大驼峰命名
- `return <h1>你好，React!</h1>` 返回 JSX 元素，描述要渲染的 UI
- 组件名首字母必须大写，否则 React 会将其当作 HTML 标签处理

### 2. 接收 props 的函数组件

```jsx
function Greeting({ name }) {
  return <h1>你好，{name}!</h1>;
}

// 使用
<Greeting name="小明" />
```

- `({ name })` 是参数解构，从 props 对象中提取 name 属性
- `{name}` 是 JSX 中的表达式，渲染 props.name 的值
- `<Greeting name="小明" />` 是使用组件的语法，`name="小明"` 是传递的 prop
- 组件使用时类似 HTML 标签，但首字母大写表示自定义组件

### 3. 箭头函数写法

```jsx
const Greeting = ({ name }) => <h1>你好，{name}!</h1>;
```

- `const Greeting =` 使用变量声明组件，组件名使用大驼峰
- `({ name }) =>` 是箭头函数参数，解构 props
- 箭头函数体只有一行 JSX 时，可以省略花括号和 return
- 箭头函数写法更简洁，是 React 中常用的组件定义方式

### 4. 组件命名规范

```jsx
// 正确：大驼峰命名
function UserProfile() {}
const UserProfile = () => {};

// 错误：小驼峰命名（会被当作普通 HTML 标签）
function userProfile() {}
```

- 组件名必须使用大驼峰（PascalCase），如 `UserProfile`、`TodoItem`
- 小驼峰（camelCase）如 `userProfile` 会被 React 当作 HTML 标签处理
- 文件命名建议使用 PascalCase，与组件名保持一致

**为什么必须大驼峰？** React 通过首字母大小写判断标签类型。小写标签（如 `div`、`span`）被当作内置 HTML 元素，大写标签（如 `UserProfile`）被当作自定义组件。

## 函数组件的渲染过程

### 1. 渲染流程

```
组件调用 → 执行函数体 → 返回 JSX → 构建虚拟 DOM → 差异对比 → 更新真实 DOM
```

```jsx
function Counter() {
  console.log('组件被调用（渲染）');
  return <h1>计数器</h1>;
}

// 每次渲染，Counter 函数都会被重新执行
```

- `console.log('组件被调用（渲染）')` 在每次渲染时执行
- 组件渲染时，函数体从头到尾执行一遍
- 渲染结果（JSX）会被 React 转换为虚拟 DOM，用于后续 diff 对比

### 2. 渲染触发条件

| 触发方式 | 说明 |
|---------|------|
| 父组件渲染 | 父组件重新渲染时，子组件自动重新渲染 |
| useState 变化 | 状态更新触发当前组件重新渲染 |
| useContext 变化 | Context 值变化触发消费组件重新渲染 |
| forceUpdate | 强制更新（不推荐） |

### 3. 纯函数要求

函数组件应该是**纯函数**——给定相同的 props，始终返回相同的 JSX：

```jsx
// 正确：纯函数
function Greeting({ name }) {
  return <h1>你好，{name}!</h1>;
}

// 错误：非纯函数，依赖外部可变状态
let count = 0;
function Counter() {
  count++;
  return <p>渲染了 {count} 次</p>;
}
```

- 纯函数：相同输入（props）始终产生相同输出（JSX）
- `let count = 0` 是组件外部的可变状态，违反纯函数原则
- `count++` 每次渲染都修改外部变量，导致不可预测的行为

**为什么要求纯函数？** React 依赖组件的纯函数特性进行优化。如果组件是纯的，React 可以安全地跳过不必要的渲染（如 `React.memo`）。非纯函数会导致不可预测的行为，如状态丢失、UI 不一致等。

## 函数组件深入思考

### 1. 每次渲染都是新函数

```jsx
function Counter() {
  const [count, setCount] = useState(0);
  
  // 每次渲染都会创建新的 handleClick 函数
  const handleClick = () => setCount(count + 1);
  
  return <button onClick={handleClick}>{count}</button>;
}
```

- `const handleClick = () => setCount(count + 1)` 在每次渲染时创建新函数
- 函数引用每次渲染都不同，可能导致子组件不必要的重渲染
- 使用 `useCallback` 可以缓存函数引用，避免这个问题

**为什么每次渲染创建新函数？** 函数组件本质是函数，每次渲染都会重新执行函数体，因此内部的变量和函数都会被重新创建。这通常不是问题，但如果将函数作为 props 传递给子组件，可能导致子组件不必要的重新渲染。使用 `useCallback` 可以缓存函数引用。

### 2. 渲染 vs 挂载

| 阶段 | 说明 | 对应 Hook |
|------|------|---------|
| 挂载（Mount） | 组件首次渲染 | useEffect(() => {...}, []) |
| 更新（Update） | 状态/props 变化触发重渲染 | useEffect(() => {...}, [dep]) |
| 卸载（Unmount） | 组件从 DOM 移除 | useEffect 的清理函数 |

### 3. 渲染优化

#### 3.1 React.memo

`React.memo` 包裹组件，在 props 未变化时跳过渲染：

```jsx
const ExpensiveList = React.memo(({ items }) => {
  return (
    <ul>
      {items.map(item => <li key={item.id}>{item.name}</li>)}
    </ul>
  );
});
```

- `React.memo(...)` 包裹组件函数，返回一个新的 memo 组件
- `({ items })` 是 props 解构，items 是传入的 prop
- `items.map(...)` 遍历数组渲染列表，`key={item.id}` 是列表必需的 key
- 当 props 未变化时，React 跳过渲染，直接复用上次结果

**适用场景：** 组件渲染成本高，且 props 变化不频繁。对于每次 props 都变化的组件，`React.memo` 的对比开销反而更大。

#### 3.2 避免内联对象和函数

```jsx
// 问题：每次渲染创建新对象，导致子组件重渲染
<Child style={{ color: 'red' }} />

// 优化：提取到组件外部或使用 useMemo
const defaultStyle = { color: 'red' };
<Child style={defaultStyle} />
```

- `<Child style={{ color: 'red' }} />` 每次渲染创建新对象，引用不同
- `const defaultStyle = { color: 'red' }` 提取到组件外部，引用稳定
- 使用 `useMemo` 也可以缓存对象引用，避免每次渲染创建新对象

### 4. 组件组合优于继承

```jsx
// 推荐：组合
function Card({ title, content, footer }) {
  return (
    <div className="card">
      <h2>{title}</h2>
      <p>{content}</p>
      <div>{footer}</div>
    </div>
  );
}

// 使用
<Card 
  title="标题" 
  content="内容" 
  footer={<button>操作</button>} 
/>
```

- `title`、`content`、`footer` 是三个独立的 prop
- `footer={<button>操作</button>}` 传递 JSX 作为 prop，实现内容定制
- 组合模式比继承更灵活，子组件可以传入任意 JSX

**为什么推荐组合？** 组合更加灵活，子组件可以通过 props 传入任意 JSX。继承在 React 中不是必要的，因为函数组件通过 props 和 Children 就能实现代码复用。

## 常见陷阱与最佳实践

### 1. 条件渲染的常见写法

```jsx
// 推荐：短路表达式
{isLoggedIn && <Dashboard />}

// 推荐：三元运算符
{isLoading ? <Spinner /> : <Content />}

// 不推荐：if/else 在 return 外部
let content;
if (isLoading) {
  content = <Spinner />;
} else {
  content = <Content />;
}
return content;
```

- `{isLoggedIn && <Dashboard />}` 当 isLoggedIn 为 true 时渲染 Dashboard
- `{isLoading ? <Spinner /> : <Content />}` 根据条件切换两个组件
- 避免在 return 外部声明变量，保持 JSX 声明式风格

### 2. 列表渲染必须提供 key

```jsx
// 正确：使用唯一 ID
{users.map(user => <UserCard key={user.id} user={user} />)}

// 错误：使用索引（列表动态变化时会导致问题）
{users.map((user, index) => <UserCard key={index} user={user} />)}
```

- `key={user.id}` 使用数据的唯一 ID 作为 key
- `user={user}` 将用户对象作为 prop 传递给子组件
- 避免使用索引作为 key，列表变化时会导致状态丢失和性能问题

### 3. 组件拆分原则

- **单一职责**：每个组件只做一件事
- **可复用性**：通用 UI 提取为独立组件
- **合理粒度**：不要太细（增加嵌套）也不要太粗（难以维护）
- **建议**：一个组件不超过 100-150 行

### 4. 最佳实践

1. **优先使用函数组件**，类组件已过时
2. **组件名使用大驼峰**，文件命名建议使用 PascalCase
3. **保持组件纯函数特性**，副作用放在 useEffect 中
4. **合理使用 React.memo** 优化性能，不要过早优化
5. **组件拆分遵循单一职责**，便于测试和维护
6. **默认 props 使用默认参数**：`function Component({ name = '默认' })`

---

## 总结

函数组件是 React 的核心构建块：

- **定义**：接收 props，返回 JSX 的纯函数
- **渲染**：每次渲染重新执行函数体，基于最新 props 和 state 生成 UI
- **优化**：使用 `React.memo`、避免内联对象、合理拆分组件
- **组合**：通过 props 组合组件，而非继承
