# React Hooks 详解：useState、useEffect、useContext、useRef

---

## Hook 的定义

Hook 是 React 16.8 引入的新特性，允许你在**不编写类组件**的情况下使用状态、副作用等其他 React 功能。

**核心特点：**
- 本质上是 JavaScript 函数
- 只能在函数组件或自定义 Hook 中调用
- 不能在循环、条件或嵌套函数中调用（Rules of Hooks）

**官方文档链接：**
- [React Hooks 中文文档](https://zh-hans.react.dev/reference/react)

## 一、useState

### 1. 概念与作用

`useState` 是 React 中最基础的 Hook，用于在**函数组件中添加状态变量**。它让函数组件拥有"记忆"能力，在多次渲染之间保存数据。

**中文官方文档链接：**
- [useState 参考文档](https://zh-hans.react.dev/reference/react/useState)
- [状态：组件的记忆](https://zh-hans.react.dev/learn/state-a-components-memory)

### 2. 基本用法

```jsx
import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      你点击了 {count} 次
    </button>
  );
}
```

- **返回值**：包含两个元素的数组——当前状态值（`count`）和更新函数（`setCount`）
- **命名约定**：`[something, setSomething]`
- **初始值**：仅在首次渲染时生效

### 3. 深入思考

#### 3.1 状态是"快照"

每次渲染都有自己独立的状态快照。调用更新函数**不会**改变当前执行代码中的状态变量：

```jsx
function handleClick() {
  console.log(count);  // 0
  setCount(count + 1);
  console.log(count);  // 仍然是 0！
}
```

- **闭包快照**：`console.log(count)` 输出的是当前渲染的快照值（0）
- **状态更新**：`setCount(count + 1)` 请求 React 用新值进行下一次渲染
- **不变性**：调用 set 函数后，当前闭包中的 count 值不会改变，仍然是 0

**为什么这样设计？** 因为 React 的渲染模型基于"快照"而非"引用"。每次渲染时，组件函数都会重新执行，闭包捕获的是该次渲染时的状态值。`setCount` 只是请求 React 用新值进行下一次渲染，它不会修改当前闭包中的 `count` 变量。这种设计让状态可预测、可调试，避免了"状态被意外修改"的问题。

#### 3.2 基于上一次状态更新

多次调用时，直接传值会基于同一个旧值，使用更新函数可确保拿到最新值：

```jsx
// 错误：三次都基于 count = 0
setCount(count + 1);
setCount(count + 1);
setCount(count + 1);

// 正确：使用更新函数
setCount(a => a + 1);
setCount(a => a + 1);
setCount(a => a + 1);
```

- **闭包陷阱**：`setCount(count + 1)` 三次调用都基于同一个 count 快照值（0）
- **更新函数**：`setCount(a => a + 1)` 传入更新函数，React 按顺序执行
- **参数含义**：`a` 是上一次 state 值，返回新的 state 值

**为什么这样设计？** React 将同一事件中的多次状态更新放入队列，批量处理。如果直接传值（如 `count + 1`），每次读取的 `count` 都是同一个闭包快照值（0），所以三次调用等价于 `setCount(1)`。而传入更新函数（`a => a + 1`），React 会在队列中依次执行：第一次接收 0 返回 1，第二次接收 1 返回 2，第三次接收 2 返回 3，最终结果为 3。这种设计确保了多次更新的正确性。

#### 3.3 不可变更新原则

状态被视为只读，应该替换而非修改：

```jsx
// 错误：直接修改
form.firstName = 'Taylor';
setForm(form);

// 正确：创建新对象
setForm({ ...form, firstName: 'Taylor' });
```

- **直接修改**：`form.firstName = 'Taylor'` 直接修改原对象，违反不可变原则
- **对象展开**：`{ ...form, firstName: 'Taylor' }` 创建新对象，保留原属性并覆盖 firstName
- **不可变更新**：必须创建新对象，让 React 通过 `Object.is` 检测到变化

**为什么这样设计？** React 使用 `Object.is` 比较新旧状态来判断是否需要重渲染。如果直接修改原对象，新旧引用相同，`Object.is` 返回 `true`，React 会跳过重渲染。此外，不可变更新让 React 能够进行高效的"浅比较"来检测变化，这是 React 性能优化的基础。

#### 3.4 惰性初始化

传入函数作为初始值，避免重复创建大型数据结构：

```jsx
const [todos, setTodos] = useState(() => createInitialTodos());
```

- **惰性初始化**：`useState(() => ...)` 传入函数作为初始值
- **首次执行**：初始值函数仅在首次渲染时执行，避免重复计算

**为什么这样设计？** `useState` 的初始值参数仅在首次渲染时生效，后续渲染会被忽略。但如果直接传入函数调用结果（如 `useState(createInitialTodos())`），`createInitialTodos()` 会在每次渲染时都执行，即使结果被忽略。对于创建大型数组或执行复杂计算的场景，这会造成不必要的性能浪费。传入函数本身（而非调用结果），React 仅在初始化时调用一次，后续渲染跳过，从而避免重复计算。

## 二、useEffect

### 1. 概念与作用

`useEffect` 用于将组件与**外部系统**连接和同步，包括网络请求、订阅、手动修改 DOM 等。它是脱离 React 渲染范式的"逃生舱口"。

**中文官方文档链接：**
- [useEffect 参考文档](https://zh-hans.react.dev/reference/react/useEffect)
- [与外部系统同步（Effects）](https://zh-hans.react.dev/learn/synchronizing-with-effects)
- [你可能不需要 Effect](https://zh-hans.react.dev/learn/you-might-not-need-an-effect)

### 2. 基本用法

```jsx
import { useState, useEffect } from 'react';

function ChatRoom({ roomId }) {
  useEffect(() => {
    const connection = createConnection(roomId);
    connection.connect();
    return () => connection.disconnect(); // 清理函数
  }, [roomId]); // 依赖项

  return <ChatIndicator roomId={roomId} />;
}
```

- **props 解构**：`({ roomId })` 从 props 对象中提取 roomId 属性
- **useEffect Hook**：`useEffect(() => {...}, [roomId])` 依赖 roomId 变化时执行
- **清理函数**：`return () => connection.disconnect()` 组件卸载或依赖变化时清理
- **依赖项数组**：`[roomId]` 表示仅当 roomId 变化时重新执行

### 3. 依赖项数组的行为

| 依赖项写法 | 执行时机 | 使用场景 |
|-----------|---------|---------|
| `useEffect(() => {...})` | 每次渲染后 | 不推荐，性能差 |
| `useEffect(() => {...}, [])` | 仅挂载和卸载时 | 数据获取、订阅连接 |
| `useEffect(() => {...}, [dep])` | 依赖变化时 | 响应 props 或 state 变化 |

### 4. 深入思考

#### 4.1 清理函数防止内存泄漏

```jsx
useEffect(() => {
  const subscription = api.subscribe(data => setData(data));
  return () => subscription.unsubscribe(); // 必须清理
}, []);
```

- **订阅创建**：`api.subscribe(data => setData(data))` 创建订阅，数据变化时更新 state
- **箭头函数回调**：`data => setData(data)` 接收订阅数据并调用 setState
- **清理函数**：`return () => subscription.unsubscribe()` 清理订阅防止内存泄漏
- **空依赖数组**：`[]` 表示仅在挂载和卸载时执行

**为什么需要清理？** Effect 在组件挂载时执行，但如果组件在 Effect 执行完毕前卸载（如用户快速导航离开），或者依赖项变化导致 Effect 重新执行，旧的订阅/定时器/事件监听器仍然存活。这会导致：① 内存泄漏——订阅对象无法被垃圾回收；② 更新已卸载组件的状态——React 会抛出警告；③ 竞态条件——旧的异步请求在新请求之后返回，覆盖正确数据。清理函数确保每次 Effect 执行前或组件卸载前，先清理上一次的资源。

#### 4.2 Effect 不是为编排数据流设计的

官方强调：**不要使用 Effect 来转换数据或计算派生状态**：

```jsx
// 错误：在 Effect 中计算派生状态
useEffect(() => {
  setVisibleTodos(filterTodos(todos, tab));
}, [todos, tab]);

// 正确：在渲染时计算
const visibleTodos = useMemo(() => filterTodos(todos, tab), [todos, tab]);
```

- **错误写法**：`useEffect(() => {...}, [todos, tab])` 在 effect 中计算派生状态
- **setState 调用**：`setVisibleTodos(...)` 在 effect 中更新 state，导致额外重渲染
- **useMemo Hook**：`useMemo(() => filterTodos(todos, tab), [todos, tab])` 在渲染时缓存计算结果

**为什么这样设计？** React 的渲染过程应该是"纯"的——给定相同的 props 和 state，应该产生相同的 UI。派生状态（如根据 todos 和 tab 过滤后的 visibleTodos）应该在渲染过程中直接计算，而不是在 Effect 中异步更新。在 Effect 中计算派生状态会导致：① 额外的重渲染（Effect 执行后 setState 触发又一次渲染）；② 视觉闪烁（先渲染旧数据，Effect 执行后再渲染新数据）；③ 性能浪费（两次渲染而非一次）。`useMemo` 在渲染时缓存计算结果，既保证了纯度又避免了重复计算。

#### 4.3 异步操作中的竞态处理

```jsx
useEffect(() => {
  let ignore = false;
  fetchData().then(data => {
    if (!ignore) setData(data);
  });
  return () => { ignore = true; };
}, []);
```

- **ignore 标志**：`let ignore = false` 用于防止旧请求覆盖新请求
- **异步链式调用**：`fetchData().then(data => {...})` 异步获取数据后更新 state
- **条件更新**：`if (!ignore) setData(data)` 仅在未被忽略时更新 state
- **清理函数**：`return () => { ignore = true; }` 组件卸载时设置 ignore 为 true

**为什么需要竞态处理？** 当用户快速切换页面或依赖项时，旧的异步请求可能尚未完成，而新的请求已经发出。如果旧请求在新请求之后返回，会导致数据不一致（显示旧数据）。通过 `ignore` 标志或 `AbortController`，可以在组件卸载或依赖变化时取消或忽略旧请求的结果，确保始终显示最新数据。

#### 4.4 StrictMode 下的双重调用

开发模式下，React 会将组件和 Effect 调用两次，帮助发现副作用和不纯函数。这是预期行为。

**为什么这样设计？** React 在开发模式下故意双重调用组件和 Effect，是为了帮助开发者发现"不纯"的代码。如果组件或 Effect 中有副作用（如修改全局变量、直接操作 DOM、发起网络请求），双重调用会暴露这些问题。生产模式下不会双重调用，这是开发-only 的行为。

## 三、useContext

### 1. 概念与作用

`useContext` 允许组件**无需逐层传递 props** 就能读取 Context 的值，解决"props 逐层传递"的**属性透传（Prop Drilling）**问题。

**中文官方文档链接：**
- [useContext 参考文档](https://zh-hans.react.dev/reference/react/useContext)
- [向 distant 父组件传递数据（Context）](https://zh-hans.react.dev/learn/passing-props-to-a-component)

### 2. 基本用法

```jsx
const ThemeContext = createContext('light');

function App() {
  return (
    <ThemeContext.Provider value="dark">
      <Toolbar />
    </ThemeContext.Provider>
  );
}

function Button() {
  const theme = useContext(ThemeContext);
  return <button className={theme}>按钮</button>;
}
```

- **createContext**：`createContext('light')` 创建 Context，默认值为 'light'
- **Provider 组件**：`<ThemeContext.Provider value="dark">` 提供 Context 值
- **value prop**：`value="dark"` 传递给所有消费该 Context 的组件
- **useContext Hook**：`const theme = useContext(ThemeContext)` 读取 Context 值
- **className 绑定**：`className={theme}` 将 theme 值作为 CSS 类名

### 3. 深入思考

#### 3.1 Context vs Redux 的选型

| 特性 | useContext | Redux / Zustand |
|------|-----------|-----------------|
| 状态管理 | 仅共享数据 | 完整状态管理 |
| 性能优化 | 需手动优化 | 内置 selector |
| 适用场景 | 低频更新（主题、语言） | 高频更新（购物车、表单） |
| 学习成本 | 低 | 较高 |

**为什么这样选型？** Context 的设计目标是"跨层级共享数据"，而非"全局状态管理"。Context 值变化时，所有消费该 Context 的组件都会重新渲染，没有内置的细粒度优化机制。而 Redux/Zustand 提供了 selector 机制，只有 selector 返回值变化的组件才会重渲染。因此，对于低频更新的数据（主题、语言、用户信息），Context 足够且简单；对于高频更新的数据（购物车数量、表单输入），使用 Redux/Zustand 可以避免不必要的重渲染。

#### 3.2 性能问题与优化

Context 值变化时，所有使用该 Context 的组件都会重新渲染。

```jsx
// 优化1：拆分 Context
const UserContext = createContext();
const ThemeContext = createContext();

// 优化2：使用 useMemo 稳定引用
const themeValue = useMemo(() => ({ theme, toggleTheme }), [theme]);
<ThemeContext.Provider value={themeValue}>
```

- **createContext 无默认值**：`createContext()` 不传默认值，创建空 Context
- **useMemo Hook**：`useMemo(() => ({ theme, toggleTheme }), [theme])` 缓存对象引用
- **依赖项**：`[theme]` 表示仅当 theme 变化时重新计算
- **Provider value**：`value={themeValue}` 传递稳定的对象引用，避免不必要的重渲染

**为什么需要优化？** Context 的 Provider 通过 `value` 的引用判断是否通知消费者。如果 `value` 每次渲染都是新对象（如 `{ theme, toggleTheme }`），即使 `theme` 和 `toggleTheme` 的值没变，引用也变了，所有消费者都会重渲染。使用 `useMemo` 缓存 `value` 对象，确保值不变时引用不变，从而避免不必要的重渲染。拆分 Context 则是缩小影响范围——只有真正需要某个值的组件才消费对应的 Context。

#### 3.3 自定义 Hook 封装

```jsx
function useTheme() {
  const context = useContext(ThemeContext);
  if (!context) throw new Error('useTheme 必须在 ThemeProvider 内使用');
  return context;
}
```

- **自定义 Hook 命名**：`useTheme` 以 use 开头，遵循自定义 Hook 命名规范
- **useContext Hook**：`useContext(ThemeContext)` 读取 Context 值
- **空值检查**：`if (!context)` 检查 context 是否为 null/undefined
- **错误抛出**：`throw new Error(...)` 在 Provider 之外使用时抛出明确错误
- **返回值**：`return context` 返回 Context 值供调用方使用

**为什么推荐封装？** 直接使用 `useContext` 时，如果组件在 Provider 之外调用，会拿到 `undefined`，且没有明确的错误提示。自定义 Hook 可以在使用时立即抛出有意义的错误，而不是等到后续代码访问 `undefined` 属性时才报错。同时，封装后调用方只需 `useTheme()` 而非 `useContext(ThemeContext)`，代码更简洁、意图更清晰。

## 四、useRef

### 1. 概念与作用

`useRef` 返回一个**可变的 ref 对象**，其 `.current` 属性保存引用的值。两个主要用途：

1. **访问 DOM 元素**
2. **在渲染之间保持可变值**（不触发重渲染）

**中文官方文档链接：**
- [useRef 参考文档](https://zh-hans.react.dev/reference/react/useRef)
- [使用 Refs 引用值](https://zh-hans.react.dev/learn/referencing-values-with-refs)

### 2. 基本用法

```jsx
function TextInput() {
  const inputRef = useRef(null);

  const focusInput = () => {
    inputRef.current?.focus();
  };

  return (
    <>
      <input ref={inputRef} type="text" />
      <button onClick={focusInput}>聚焦输入框</button>
    </>
  );
}
```

- **useRef Hook**：`const inputRef = useRef(null)` 创建 ref 对象，初始 `.current` 为 null
- **可选链操作符**：`inputRef.current?.focus()` 安全调用，null 时不报错
- **ref 绑定**：`ref={inputRef}` 将 ref 绑定到 DOM 元素
- **Fragment 语法**：`<>...</>` 是 Fragment 简写，不产生额外 DOM 节点
- **事件绑定**：`onClick={focusInput}` 将函数引用绑定到点击事件

### 3. 深入思考

#### 3.1 ref 与 state 的关键区别

| 特性 | useRef | useState |
|------|--------|----------|
| 更新触发重渲染 | 不会 | 会 |
| 持久化值 | 是 | 是 |
| 读取最新值 | `.current` | 闭包中的值 |
| 典型场景 | DOM 引用、定时器 ID | UI 状态 |

**为什么 ref 不触发重渲染？** `useState` 的设计目标是管理"影响 UI 的数据"，更新后必须触发重渲染以反映变化。而 `useRef` 的设计目标是"持有不影响 UI 的可变值"，如 DOM 引用、定时器 ID、上一次请求的 ID 等。这些值的变化不需要反映到界面上，因此修改 `.current` 不会触发重渲染。如果修改 ref 也触发重渲染，会导致无限循环和性能问题。

#### 3.2 在闭包中保持最新值

```jsx
function Timer() {
  const [count, setCount] = useState(0);
  const countRef = useRef(count);
  countRef.current = count; // 始终获取最新值

  useEffect(() => {
    const interval = setInterval(() => {
      console.log(countRef.current); // 始终是当前最新值
    }, 1000);
    return () => clearInterval(interval);
  }, []);

  return <div>{count}</div>;
}
```

- **useState Hook**：`const [count, setCount] = useState(0)` 创建状态变量
- **useRef Hook**：`const countRef = useRef(count)` 创建 ref 对象保存 count 值
- **同步到 ref**：`countRef.current = count` 在每次渲染时将 state 同步到 ref
- **setInterval**：`setInterval(() => {...}, 1000)` 每 1000ms 执行一次回调
- **清理函数**：`return () => clearInterval(interval)` 组件卸载时清除定时器
- **空依赖数组**：`[]` 表示 effect 仅在挂载时执行一次

**为什么需要 ref 保持最新值？** `useEffect` 的依赖项数组为 `[]` 时，effect 内的闭包捕获的是初始渲染时的值。如果 effect 内部有定时器或事件监听器，它们无法自动获取最新的 state 值。将 state 同步到 ref（`countRef.current = count`），定时器内部读取 `countRef.current` 就能始终拿到最新值。这是因为 ref 对象在组件的整个生命周期中是同一个实例，修改 `.current` 不会触发重渲染，但值会持久化。

#### 3.3 修改 ref.current 不会触发渲染

```jsx
inputRef.current = 'new value'; // 界面不会更新！
// 如果需要 ref 和 state 同步
useEffect(() => {
  inputRef.current = value;
}, [value]);
```

- **直接修改 current**：`inputRef.current = 'new value'` 直接修改 ref 值，不触发重渲染
- **useEffect 同步**：`useEffect(() => {...}, [value])` 在 value 变化时同步 ref

**为什么这样设计？** ref 的设计初衷就是"持有不用于渲染的值"。如果修改 ref 触发重渲染，就失去了它的意义——此时应该使用 state。如果需要 ref 和 state 保持同步，应通过 `useEffect` 手动同步，这样可以在需要时精确控制同步时机。

#### 3.4 直接操作 DOM 的风险

```jsx
divRef.current.style.color = 'red'; // 跳过 React 虚拟 DOM
// 这会导致 React 不知道 DOM 已被修改，下次 diff 可能出问题
```

**为什么有风险？** React 通过虚拟 DOM diff 来管理 UI 更新。如果直接操作真实 DOM（如 `divRef.current.style.color = 'red'`），React 在下一次渲染时会认为真实 DOM 应该与虚拟 DOM 一致，可能会覆盖你的手动修改。此外，React DevTools 无法追踪 ref 中的 DOM 操作，调试困难。如果必须操作 DOM，应在 effect 中执行，并确保清理函数恢复状态。

## 五、Hook 核心区别对比

### 1. 四维对比表

| 维度 | useState | useEffect | useContext | useRef |
|------|----------|-----------|------------|--------|
| **本质** | 状态变量 | 副作用同步 | 上下文消费 | 引用容器 |
| **触发重渲染** | ✅ 是 | ❌ 否（间接通过 setState） | ❌ 否（间接通过 Provider） | ❌ 否 |
| **值是否持久** | ✅ 是 | - | - | ✅ 是 |
| **读取最新值** | 闭包快照 | 依赖项数组 | Context.Provider | .current |
| **典型场景** | 表单输入、计数器 | 数据请求、订阅、DOM操作 | 主题、语言、用户信息 | DOM元素、定时器ID、闭包中持值 |
| **更新方式** | 调用 set 函数 | 依赖变化自动执行 | Provider 传递新值 | 直接修改 .current |
| **数据流向** | 组件内部 | 组件 ↔ 外部系统 | 父 → 子（跨层级） | 组件内部 / DOM |

### 2. 一句话区分

- **useState**：组件"记住"数据，变化时更新 UI
- **useEffect**：组件与外部世界"同步"，如请求数据、操作 DOM
- **useContext**：组件"读取"祖先组件共享的数据，跳过逐层传参
- **useRef**：组件"持有"一个可变值，变化时不更新 UI

### 3. 效果对比示例

以下代码同时使用四个 Hook，直观展示它们的效果差异：

```jsx
import { useState, useEffect, useContext, useRef, createContext } from 'react';

const ThemeContext = createContext('light');

function HookComparison() {
  // useState: 状态变化 → 触发重渲染 → UI 更新
  const [count, setCount] = useState(0);

  // useEffect: 依赖变化 → 执行副作用 → 与外部同步
  useEffect(() => {
    console.log('count 变为:', count); // 每次 count 变化时打印
  }, [count]);

  // useContext: 读取祖先组件的共享值
  const theme = useContext(ThemeContext);

  // useRef: 持有可变值 → 不触发重渲染 → UI 不变
  const renderCountRef = useRef(0);
  renderCountRef.current += 1; // 每次渲染自增，但不会导致重渲染

  return (
    <div className={theme}>
      <p>count: {count}</p>           {/* useState 变化 → UI 更新 */}
      <p>theme: {theme}</p>           {/* useContext 读取 → 由 Provider 控制更新 */}
      <p>渲染次数: {renderCountRef.current}</p> {/* useRef 持有 → 值变化但 UI 不更新 */}
      <button onClick={() => setCount(c => c + 1)}>
        点击（count +1，触发 useEffect 和重渲染）
      </button>
    </div>
  );
}
```

- **useState Hook**：`const [count, setCount] = useState(0)` 创建状态变量，初始值为 0
- **useEffect Hook**：`useEffect(() => {...}, [count])` 依赖变化时执行副作用，依赖数组为 `[count]`
- **useContext Hook**：`const theme = useContext(ThemeContext)` 读取 Context 共享值
- **useRef Hook**：`const renderCountRef = useRef(0)` 创建 ref 对象，`.current` 可变不触发重渲染
- **className 绑定**：`className={theme}` 将 theme 值作为 CSS 类名
- **表达式渲染**：`{count}`、`{theme}`、`{renderCountRef.current}` 在 JSX 中渲染对应值
- **箭头函数事件**：`onClick={() => setCount(c => c + 1)}` 点击时调用 setCount，使用更新函数

**点击按钮后的效果：**
- `count` 从 0 → 1，UI 更新显示新值（useState 生效）
- 控制台打印 `count 变为: 1`（useEffect 因依赖变化执行）
- `renderCountRef.current` 自增但不影响 UI（useRef 不触发重渲染）
- `theme` 不变，除非祖先组件的 Provider 传递了新值（useContext 由 Provider 控制）

### 4. 核心定位对比

| Hook | 核心用途 | 关键特性 | 是否触发重渲染 |
|------|---------|---------|-------------|
| useState | 管理组件内部状态 | 快照式状态、不可变更新 | 是 |
| useEffect | 处理与外部系统的同步 | 依赖项控制、清理函数 | 否（间接通过 setState） |
| useContext | 跨组件共享数据 | 避免 props 透传 | 否（间接通过 Provider） |
| useRef | 持久化可变值 / DOM 引用 | 不触发重渲染 | 否 |

### 5. 组合使用示例

```jsx
function DataFetcher({ url }) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);
  const abortRef = useRef(null);
  const context = useContext(ApiContext);

  useEffect(() => {
    abortRef.current?.abort(); // 取消上一个请求
    const controller = new AbortController();
    abortRef.current = controller;

    setLoading(true);
    fetch(url, { signal: controller.signal, headers: context.headers })
      .then(res => res.json())
      .then(data => {
        setData(data);
        setLoading(false);
      })
      .catch(err => {
        if (err.name !== 'AbortError') setLoading(false);
      });

    return () => controller.abort();
  }, [url, context]);

  if (loading) return <div>加载中...</div>;
  return <div>{JSON.stringify(data)}</div>;
}
```

- **props 解构**：`({ url })` 从 props 对象中提取 url 属性
- **useState Hook**：`useState(null)` 创建 data 状态，初始为 null；`useState(true)` 创建 loading 状态
- **useRef Hook**：`useRef(null)` 创建 abortRef，用于持有 AbortController 实例
- **useContext Hook**：`useContext(ApiContext)` 读取 API 上下文
- **可选链调用**：`abortRef.current?.abort()` 安全调用 abort 方法
- **AbortController**：`new AbortController()` 创建请求控制器，用于取消请求
- **fetch API**：`fetch(url, { signal, headers })` 发起 HTTP 请求，signal 关联控制器
- **链式.then**：`.then(res => res.json())` 解析 JSON，`.then(data => {...})` 更新 state
- **清理函数**：`return () => controller.abort()` 取消未完成的请求
- **依赖项数组**：`[url, context]` 表示 url 或 context 变化时重新执行
- **条件渲染**：`if (loading) return ...` 加载中时显示加载状态
- **JSON 序列化**：`JSON.stringify(data)` 将数据对象转为 JSON 字符串

## 六、总结

React Hooks 的核心设计哲学是**让函数组件具备类组件的所有能力**，同时解决类组件中逻辑复用和代码组织的问题。

- **useState** 是状态管理的基石，理解"快照"和"不可变更新"是关键
- **useEffect** 处理与外部世界的交互，理解依赖项和清理函数是核心
- **useContext** 解决跨组件数据共享，理解性能影响和适用场景很重要
- **useRef** 提供不触发重渲染的持久化引用，适合 DOM 操作和闭包中保持最新值
