# Props 详解：数据传递、验证与单向数据流

---

## Props 的定义

Props（properties 的缩写）是 React 组件之间传递数据的机制。父组件通过 props 向子组件传递数据，子组件接收 props 并渲染 UI。

**核心特点：**
- Props 是只读的，组件不能修改自己的 props
- 数据流动是单向的：父 → 子
- Props 可以是任何 JavaScript 类型（字符串、数字、对象、数组、函数、JSX 等）
- 实现组件复用和定制化的核心机制

## Props 基本用法

### 1. 传递基本类型 Props

```jsx
function Greeting({ name, age }) {
  return (
    <div>
      <p>姓名：{name}</p>
      <p>年龄：{age}</p>
    </div>
  );
}

// 使用
<Greeting name="小明" age={20} />
```

- `({ name, age })` 是参数解构，从 props 对象中提取 name 和 age 属性
- `{name}` 和 `{age}` 是 JSX 中的表达式，渲染对应的 prop 值
- `name="小明"` 是字符串类型的 prop，用引号包裹
- `age={20}` 是表达式类型的 prop，用花括号包裹 JavaScript 值

### 2. 传递对象和数组

```jsx
function UserCard({ user }) {
  return (
    <div>
      <h3>{user.name}</h3>
      <ul>
        {user.hobbies.map(h => <li key={h}>{h}</li>)}
      </ul>
    </div>
  );
}

// 使用
<UserCard user={{ name: '小红', hobbies: ['阅读', '编程'] }} />
```

- `({ user })` 解构出 user prop，user 是一个对象
- `{user.name}` 是对象属性访问表达式，渲染 user.name 的值
- `{user.hobbies.map(...)}` 是数组方法调用，遍历 hobbies 数组渲染列表
- `user={{ name: '小红', hobbies: [...] }}` 传递对象字面量作为 prop，花括号内写 JS 表达式

### 3. 传递函数（回调）

```jsx
function Button({ onClick, label }) {
  return <button onClick={onClick}>{label}</button>;
}

// 使用
<Button label="点击" onClick={() => alert('clicked')} />
```

- `({ onClick, label })` 解构出 onClick 函数和 label 字符串
- `onClick={onClick}` 将 prop 中的函数绑定到按钮的点击事件
- `{label}` 渲染 label prop 的值作为按钮文本
- `onClick={() => alert('clicked')}` 传递箭头函数作为 prop，点击时执行

### 4. 传递 JSX

```jsx
function Card({ title, content, footer }) {
  return (
    <div className="card">
      <h2>{title}</h2>
      <div>{content}</div>
      <div>{footer}</div>
    </div>
  );
}

// 使用
<Card 
  title="标题"
  content={<p>卡片内容</p>}
  footer={<button>操作</button>}
/>
```

- `content={<p>卡片内容</p>}` 传递 JSX 元素作为 prop
- `footer={<button>操作</button>}` 传递嵌套组件作为 prop
- `{content}` 和 `{footer}` 在组件内部渲染传入的 JSX
- 这种模式称为"内容注入"，父组件可以定制子组件的局部内容

### 5. children Prop

React 自动将所有嵌套内容传递给 `children` prop：

```jsx
function Card({ children }) {
  return <div className="card">{children}</div>;
}

// 使用
<Card>
  <p>这是卡片内容</p>
  <button>操作</button>
</Card>
```

- `{children}` 是特殊 prop，无需显式声明，React 自动提供
- `<Card>...</Card>` 标签内的所有内容自动成为 children
- `{children}` 在组件内部渲染的位置决定子元素显示的位置
- children 可以是任何可渲染内容：JSX、字符串、数字、函数返回值等

## Props 默认值与类型检查

### 1. 默认参数（推荐）

```jsx
function Greeting({ name = '访客' }) {
  return <h1>你好，{name}!</h1>;
}
```

- `{ name = '访客' }` 是默认参数语法，当 name 未传入时使用 '访客'
- 默认参数在解构时生效，简洁且无需额外配置
- 推荐优先使用默认参数而非 defaultProps

### 2. defaultProps

```jsx
function Greeting({ name }) {
  return <h1>你好，{name}!</h1>;
}

Greeting.defaultProps = { name: '访客' };
```

- `Greeting.defaultProps` 是组件的静态属性，定义默认 prop 值
- 当 name 未传入时，使用 defaultProps 中的值
- 默认参数语法更简洁，是 TypeScript 项目中的首选方式

### 3. PropTypes 类型检查

```jsx
import PropTypes from 'prop-types';

function UserCard({ name, age, isAdmin, onClick }) {
  return <div>{name}</div>;
}

UserCard.propTypes = {
  name: PropTypes.string.isRequired,
  age: PropTypes.number,
  isAdmin: PropTypes.bool,
  onClick: PropTypes.func,
  children: PropTypes.node,
};
```

- `PropTypes.string.isRequired` 表示 name 是必填的字符串类型
- `PropTypes.number` 表示 age 是可选的数字类型
- `PropTypes.func` 表示 onClick 是可选的函数类型
- `PropTypes.node` 表示 children 可以是任何可渲染内容
- PropTypes 仅在开发模式下生效，生产环境会被移除

**常用类型：**

| 类型 | 说明 |
|------|------|
| PropTypes.string | 字符串 |
| PropTypes.number | 数字 |
| PropTypes.bool | 布尔值 |
| PropTypes.func | 函数 |
| PropTypes.object | 对象 |
| PropTypes.array | 数组 |
| PropTypes.node | 任何可渲染的内容（字符串、数字、JSX、数组等） |
| PropTypes.element | React 元素 |
| PropTypes.isRequired | 必填 |

**注意：** PropTypes 仅在开发模式下生效，生产环境会被移除。TypeScript 项目中推荐使用 TypeScript 替代 PropTypes。

## Props 深入思考

### 1. 单向数据流

Props 是单向的，子组件不能直接修改 props：

```jsx
// 错误：子组件不能修改 props
function Counter({ count }) {
  count += 1;  // 无效，且不应该这样做
  return <p>{count}</p>;
}

// 正确：通过回调函数让父组件更新状态
function Counter({ count, onIncrement }) {
  return <button onClick={onIncrement}>{count}</button>;
}
```

- `count += 1` 尝试修改 prop，但 prop 是只读的，修改无效
- `onIncrement` 是回调函数 prop，子组件调用它通知父组件更新
- `onClick={onIncrement}` 将回调函数绑定到点击事件
- 子组件通过调用回调函数，让父组件更新 state，再传递新的 props

**为什么单向数据流？** 单向数据流让数据变化可预测、可追踪。如果子组件可以直接修改 props，数据流向会变得混乱，难以调试。React 的哲学是"状态提升"——将共享状态放在最近的公共父组件中，通过回调函数向下传递更新能力。

### 2. Props 是只读的快照

每次父组件渲染时，都会创建新的 props 对象传递给子组件：

```jsx
function Parent() {
  const [count, setCount] = useState(0);
  
  return <Child count={count} />;
}

function Child({ count }) {
  // count 是当前渲染的快照值
  // 即使父组件后续更新，这里的 count 也不会变
}
```

- `count={count}` 将父组件的 state 值作为 prop 传递给子组件
- `({ count })` 在子组件中解构接收 prop
- count 是当前渲染时的快照值，子组件不会自动感知后续变化
- 只有父组件重新渲染时，子组件才会收到新的 props

**为什么是快照？** 这与 React 的渲染模型一致。每次渲染都有独立的状态和 props 快照，确保组件在渲染过程中的数据一致性。

### 3. Props 对比与性能

| 场景 | 是否触发重渲染 | 说明 |
|------|-------------|------|
| props 值变化 | 是 | 子组件会重新渲染 |
| props 引用变化（对象/数组） | 是 | 即使内容相同，引用不同也会重渲染 |
| props 未变化 | 否（配合 React.memo） | 使用 React.memo 可跳过渲染 |

**优化技巧：**

```jsx
// 问题：每次渲染创建新对象，导致子组件重渲染
<Child config={{ theme: 'dark', lang: 'zh' }} />

// 优化：使用 useMemo 稳定引用
const config = useMemo(() => ({ theme: 'dark', lang: 'zh' }), []);
<Child config={config} />
```

- `{{ theme: 'dark', lang: 'zh' }}` 每次渲染创建新对象，引用不同
- `useMemo(() => ({ ... }), [])` 缓存对象引用，避免重复创建
- 外层 `{}` 是 JSX 表达式，内层 `{}` 是对象字面量

### 4. 组合 vs 透传

```jsx
// 不推荐：透传所有 props，隐藏组件接口
function Wrapper({ ...props }) {
  return <div {...props} />;
}

// 推荐：明确声明需要的 props
function Wrapper({ className, children }) {
  return <div className={`wrapper ${className}`}>{children}</div>;
}
```

- `{ ...props }` 是展开运算符，解构所有 prop
- `<div {...props} />` 将 prop 展开为 HTML 属性
- 明确声明 `className` 和 `children` 使组件接口清晰
- 推荐组件只接收明确声明的 props，避免隐式透传

**为什么推荐明确声明？** 明确声明 props 让组件接口清晰，便于理解和维护。透传所有 props 会隐藏组件的真实依赖，增加调试难度。

## 常见陷阱与最佳实践

### 1. 避免过度拆分 props

```jsx
// 不推荐：props 过多
function Form({ name, age, email, phone, address, city, country, zip }) {}

// 推荐：分组 props
function Form({ user: { name, age, email }, contact: { phone, address } }) {}
```

- 过多的 prop 使组件接口难以维护
- `user: { name, age, email }` 是嵌套解构，从 user 对象中提取属性
- 将相关 prop 分组为对象，减少 prop 数量

### 2. 回调函数的稳定引用

```jsx
// 问题：每次渲染创建新函数
<Child onChange={(value) => setValue(value)} />

// 优化：使用 useCallback 稳定引用
const handleChange = useCallback((value) => setValue(value), []);
<Child onChange={handleChange} />
```

- `{(value) => setValue(value)}` 每次渲染创建新箭头函数，引用不同
- `useCallback((value) => setValue(value), [])` 缓存函数引用
- 稳定引用避免子组件不必要的重渲染

### 3. 条件渲染在子组件中处理

```jsx
// 不推荐：父组件处理多个子组件的显示逻辑
{showTitle && <Title />}
{showContent && <Content />}

// 推荐：子组件内部处理
<Title show={showTitle} />
<Content show={showContent} />
```

- `show={showTitle}` 将布尔值作为 prop 传递给子组件
- 子组件内部根据 show prop 决定是否渲染
- 将显示逻辑下沉到子组件，父组件更简洁

### 4. 最佳实践

1. **Props 只读**，永远不要修改 props
2. **使用默认参数**替代 defaultProps（更简洁）
3. **TypeScript 替代 PropTypes**，获得编译时类型检查
4. **props 变化触发重渲染**，合理使用 React.memo 优化
5. **通过回调函数实现子→父通信**，保持单向数据流
6. **明确声明 props**，避免过度使用展开运算符
7. **children 是特殊 prop**，无需显式声明即可使用

---

## 总结

Props 是 React 数据传递的核心机制：

- **传递**：可以是任何类型，包括基本值、对象、函数、JSX
- **单向**：父→子单向流动，子组件不能修改 props
- **只读**：props 是只读的快照，确保数据可预测
- **优化**：通过 `React.memo`、`useCallback`、`useMemo` 优化性能
