# 条件渲染与列表渲染详解

---

## 条件渲染的定义

条件渲染是根据条件决定显示不同 UI 的机制。列表渲染是根据数据数组动态生成列表项的机制。两者是 React 中最常用的渲染模式。

**核心特点：**
- 条件渲染基于 JavaScript 条件表达式
- 列表渲染使用 `Array.map()` 方法
- 条件为 `false`、`null`、`undefined` 的元素不会渲染
- 列表渲染需要稳定的 `key` 属性

## 条件渲染

### 1. 条件表达式（if/else）

```jsx
function Greeting({ isLoggedIn }) {
  if (isLoggedIn) {
    return <h1>欢迎回来！</h1>;
  }
  return <h1>请先登录</h1>;
}
```

- `if (isLoggedIn)` 根据 isLoggedIn prop 的值决定渲染逻辑
- `return <h1>欢迎回来！</h1>` 条件为 true 时渲染欢迎消息
- `return <h1>请先登录</h1>` 条件为 false 时渲染登录提示
- if/else 适合复杂条件或多分支场景

### 2. 逻辑与（&&）运算符

```jsx
function Notification({ count }) {
  return (
    <div>
      {count > 0 && <p>你有 {count} 条新消息</p>}
    </div>
  );
}
```

- `{count > 0 && <p>...</p>}` 是逻辑与条件渲染
- 当 `count > 0` 为 true 时，渲染 p 元素
- 当 `count > 0` 为 false 时，不渲染任何内容
- `{count}` 是嵌入表达式，显示 count prop 的值
- 简洁但注意左侧必须是布尔值

**注意：** 避免在 `&&` 左侧使用数字，`0 && 大量JSX` 会渲染出 `0`：

```jsx
// 问题：count 为 0 时会渲染 0
{count && <p>你有 {count} 条消息</p>}

// 正确：确保左侧是布尔值
{count > 0 && <p>你有 {count} 条消息</p>}
```

- `{count && ...}` 当 count 为 0 时，0 是 falsy 值，不会渲染 JSX，但会渲染出 0
- `{count > 0 && ...}` 确保左侧是布尔值，避免渲染数字 0

### 3. 三元运算符

```jsx
function Status({ isLoading }) {
  return (
    <div>
      {isLoading ? <Spinner /> : <Content />}
    </div>
  );
}
```

- `{isLoading ? <Spinner /> : <Content />}` 是三元运算符
- 当 isLoading 为 true 时渲染 Spinner 组件
- 当 isLoading 为 false 时渲染 Content 组件
- 适合两个分支切换的场景

### 4. 条件渲染对比

| 写法 | 适用场景 | 优点 | 缺点 |
|------|---------|------|------|
| if/else | 复杂条件、多个分支 | 逻辑清晰 | 不能在 return 中直接使用 |
| && 短路 | 简单条件显示/隐藏 | 简洁 | 左侧为 0 时会渲染 0 |
| 三元运算符 | 两个分支切换 | 简洁 | 条件过多时难以维护 |

## 列表渲染

### 1. 基本列表渲染

```jsx
function TodoList({ todos }) {
  return (
    <ul>
      {todos.map(todo => (
        <li key={todo.id}>{todo.text}</li>
      ))}
    </ul>
  );
}
```

- `{todos.map(todo => (...))}` 是数组 map 方法，遍历 todos 数组
- `todo => (...)` 是箭头函数，接收 todo 对象作为参数
- `<li key={todo.id}>` 是列表项，`key={todo.id}` 是 React 必需的 key prop
- `{todo.text}` 显示 todo 对象的 text 属性值
- map 返回 JSX 元素数组，渲染为列表项

### 2. 列表渲染中的 key

```jsx
function UserList({ users }) {
  return (
    <ul>
      {users.map(user => (
        <UserCard key={user.id} user={user} />
      ))}
    </ul>
  );
}
```

- `<UserCard key={user.id} user={user} />` 是自定义子组件
- `key={user.id}` 使用用户 ID 作为唯一标识
- `user={user}` 将用户对象作为 prop 传递给 UserCard 组件
- key 应该在列表兄弟元素之间唯一且稳定

**为什么需要 key？** key 帮助 React 识别哪些列表项发生了变化、新增或删除。没有稳定的 key，React 会重新创建所有列表项，导致：
- 性能问题：不必要的 DOM 操作
- 状态丢失：列表项中的输入状态、展开状态等丢失
- 视觉闪烁：动画效果异常

**key 的选择原则：**

| 选择 | 说明 | 推荐度 |
|------|------|--------|
| 数据唯一 ID | `key={user.id}` | 推荐 |
| 唯一组合 | `key={`${type}-${id}`}` | 推荐 |
| 索引 | `key={index}` | 仅静态列表 |
| Math.random() | `key={Math.random()}` | 不推荐 |

### 3. 嵌套列表

```jsx
function CategoryList({ categories }) {
  return (
    <div>
      {categories.map(category => (
        <div key={category.id}>
          <h3>{category.name}</h3>
          <ul>
            {category.items.map(item => (
              <li key={item.id}>{item.name}</li>
            ))}
          </ul>
        </div>
      ))}
    </div>
  );
}
```

- 外层 `categories.map(category => ...)` 遍历分类数组
- `key={category.id}` 是外层列表的 key
- 内层 `category.items.map(item => ...)` 遍历每个分类下的物品
- `key={item.id}` 是内层列表的 key
- 嵌套列表需要分别为每层提供 key

### 4. 列表渲染中的条件过滤

```jsx
function TodoList({ todos, filter }) {
  const filteredTodos = todos.filter(todo => {
    if (filter === 'active') return !todo.done;
    if (filter === 'done') return todo.done;
    return true;
  });

  return (
    <ul>
      {filteredTodos.map(todo => (
        <li key={todo.id}>
          {todo.text}
          {todo.done && <span> ✓</span>}
        </li>
      ))}
    </ul>
  );
}
```

- `todos.filter(todo => ...)` 过滤出符合条件的 todo
- `filter === 'active'` 时返回未完成的任务（!todo.done）
- `filter === 'done'` 时返回已完成的任务（todo.done）
- `{todo.done && <span> ✓</span>}` 条件渲染：done 为 true 时显示勾选标记
- 过滤逻辑在渲染前完成，不在 JSX 中直接写复杂过滤

## 条件渲染与列表渲染深入思考

### 1. 空列表处理

```jsx
function TodoList({ todos }) {
  if (todos.length === 0) {
    return <p>暂无任务</p>;
  }

  return (
    <ul>
      {todos.map(todo => <li key={todo.id}>{todo.text}</li>)}
    </ul>
  );
}
```

- `if (todos.length === 0)` 在渲染前检查列表是否为空
- `return <p>暂无任务</p>` 空列表时显示友好提示
- 空状态处理应该在列表渲染之前完成
- 提供空状态提示提升用户体验

### 2. 列表渲染的性能优化

#### 2.1 大型列表虚拟化

渲染大量列表项时，使用虚拟化技术只渲染可见区域：

```jsx
import { useVirtualizer } from '@tanstack/react-virtual';

function VirtualList({ items }) {
  const parentRef = useRef(null);
  
  const virtualizer = useVirtualizer({
    count: items.length,
    getScrollElement: () => parentRef.current,
    estimateSize: () => 50,
    overscan: 5,
  });

  return (
    <div ref={parentRef} style={{ height: '400px', overflow: 'auto' }}>
      <div style={{ height: `${virtualizer.getTotalSize()}px`, position: 'relative' }}>
        {virtualizer.getVirtualItems().map(virtualItem => (
          <div
            key={virtualItem.key}
            style={{
              position: 'absolute',
              top: 0,
              left: 0,
              width: '100%',
              height: `${virtualItem.size}px`,
              transform: `translateY(${virtualItem.start}px)`,
            }}
          >
            {items[virtualItem.index].text}
          </div>
        ))}
      </div>
    </div>
  );
}
```

- `useVirtualizer({...})` 创建虚拟化实例
- `count: items.length` 指定列表总长度
- `estimateSize: () => 50` 估算每个 item 的高度
- `getScrollElement: () => parentRef.current` 获取滚动容器
- `virtualizer.getVirtualItems()` 只返回可见区域的 item
- 通过 `transform: translateY(...)` 定位可见项到正确位置

#### 2.2 React.memo 优化列表项

```jsx
const TodoItem = React.memo(({ todo, onToggle }) => {
  return (
    <li>
      <input
        type="checkbox"
        checked={todo.done}
        onChange={() => onToggle(todo.id)}
      />
      {todo.text}
    </li>
  );
});

function TodoList({ todos, onToggle }) {
  return (
    <ul>
      {todos.map(todo => (
        <TodoItem key={todo.id} todo={todo} onToggle={onToggle} />
      ))}
    </ul>
  );
}
```

- `React.memo(...)` 包裹组件，props 未变化时跳过渲染
- `({ todo, onToggle })` 解构 todo 对象和 onToggle 回调
- `checked={todo.done}` 绑定完成状态（受控复选框）
- `onChange={() => onToggle(todo.id)}` 点击时调用回调，传入 todo.id
- `key={todo.id}` 是列表渲染必需的 key
- `todo={todo}` 和 `onToggle={onToggle}` 是传递给子组件的 prop

### 3. 列表渲染与状态管理

```jsx
function TodoList() {
  const [todos, setTodos] = useState([
    { id: 1, text: '任务1', done: false },
    { id: 2, text: '任务2', done: false },
  ]);

  const toggleTodo = (id) => {
    setTodos(prev => prev.map(todo =>
      todo.id === id ? { ...todo, done: !todo.done } : todo
    ));
  };

  return (
    <ul>
      {todos.map(todo => (
        <li key={todo.id}>
          <input
            type="checkbox"
            checked={todo.done}
            onChange={() => toggleTodo(todo.id)}
          />
          {todo.text}
        </li>
      ))}
    </ul>
  );
}
```

- `useState([...])` 创建包含 todo 对象的数组 state
- 每个 todo 对象包含 id（唯一标识）、text（文本）、done（完成状态）
- `toggleTodo(id)` 是切换完成状态的事件处理函数
- `prev.map(todo => ...)` 遍历 todos，找到匹配的 todo 并切换 done
- `{ ...todo, done: !todo.done }` 创建新 todo 对象，切换 done 状态
- `onChange={() => toggleTodo(todo.id)}` 复选框变化时调用 toggleTodo

### 4. 条件渲染与列表渲染的组合

```jsx
function SearchResults({ items, query, isLoading }) {
  if (isLoading) return <Spinner />;

  const filtered = items.filter(item =>
    item.name.toLowerCase().includes(query.toLowerCase())
  );

  if (filtered.length === 0) return <p>未找到结果</p>;

  return (
    <ul>
      {filtered.map(item => (
        <li key={item.id}>{item.name}</li>
      ))}
    </ul>
  );
}
```

- `if (isLoading) return <Spinner />` 加载中时显示加载状态
- `items.filter(item => ...)` 根据 query 过滤 items
- `item.name.toLowerCase().includes(query.toLowerCase())` 大小写不敏感搜索
- `if (filtered.length === 0) return <p>未找到结果</p>` 无结果时显示提示
- 条件渲染和列表渲染组合使用，处理完整的用户体验流程

## 常见陷阱与最佳实践

### 1. 条件渲染中的陷阱

```jsx
// 错误：false && JSX 不会渲染，但 true && 0 会渲染 0
{false && <div>内容</div>}  {/* 不渲染，正确 */}
{0 && <div>内容</div>}      {/* 渲染 0，错误 */}

// 正确：确保左侧是布尔值
{count > 0 && <div>内容</div>}
```

- `{false && ...}` 不渲染任何内容
- `{0 && ...}` 会渲染出数字 0，因为 0 不是 falsy 值在 && 中的行为
- 始终确保 && 左侧是布尔值，如 `count > 0`

### 2. 列表 key 的陷阱

```jsx
// 错误：使用索引作为 key（列表动态变化时）
{items.map((item, index) => <Item key={index} />)}

// 错误：使用 Math.random()（每次渲染 key 变化，导致全部重渲染）
{items.map(item => <Item key={Math.random()} />)}

// 正确：使用唯一稳定的 ID
{items.map(item => <Item key={item.id} />)}
```

- `key={index}` 在列表增删时会导致状态错乱
- `key={Math.random()}` 每次渲染 key 都变化，导致全部重渲染
- `key={item.id}` 使用唯一稳定的 ID，是最佳实践

### 3. 列表渲染中的函数创建

```jsx
// 问题：每次渲染创建新函数
{items.map(item => (
  <Item key={item.id} onDelete={() => handleDelete(item.id)} />
))}

// 优化：提取处理函数
const handleDelete = useCallback((id) => {
  setItems(prev => prev.filter(item => item.id !== id));
}, []);

{items.map(item => (
  <Item key={item.id} onDelete={() => handleDelete(item.id)} />
))}
```

- `onDelete={() => handleDelete(item.id)}` 每次渲染创建新箭头函数
- `useCallback((id) => {...}, [])` 缓存函数引用
- 空依赖数组 `[]` 表示函数不依赖任何值，引用稳定
- 稳定引用避免子组件不必要的重渲染

### 4. 最佳实践

1. **列表必须提供稳定的 key**，优先使用数据唯一 ID
2. **条件渲染优先使用逻辑与或三元运算符**，保持 JSX 简洁
3. **空列表单独处理**，提供友好的空状态提示
4. **大型列表使用虚拟化**，只渲染可见区域
5. **列表项使用 React.memo 优化**，避免不必要的重渲染
6. **过滤逻辑在渲染前完成**，不在 JSX 中直接写复杂过滤
7. **避免在列表渲染中创建新函数**，使用 useCallback 稳定引用

## 条件渲染 vs 列表渲染对比

| 特性 | 条件渲染 | 列表渲染 |
|------|---------|---------|
| 核心方法 | if/else、&&、三元运算符 | Array.map() |
| 数据源 | 布尔条件 | 数组 |
| 关键属性 | 无 | key |
| 性能关注 | 分支复杂度 | key 稳定性、虚拟化 |
| 空状态 | 显示默认内容 | 显示空状态提示 |

---

## 总结

条件渲染和列表渲染是 React 的核心渲染模式：

- **条件渲染**：基于 JavaScript 条件表达式，灵活控制 UI 显示
- **列表渲染**：使用 `map()` 遍历数组，key 是性能关键
- **性能优化**：大型列表虚拟化、React.memo、稳定函数引用
- **空状态处理**：列表为空时提供友好的提示信息
