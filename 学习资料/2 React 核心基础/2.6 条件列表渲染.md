# 条件渲染与列表渲染详解

---

## 条件渲染

条件渲染是根据条件决定显示不同 UI 的机制。

### 1. 条件表达式（if/else）

```jsx
function Greeting({ isLoggedIn }) {
  if (isLoggedIn) {
    return <h1>欢迎回来！</h1>;
  }
  return <h1>请先登录</h1>;
}
```

- **条件判断**：`if (isLoggedIn)` 根据 prop 的值决定渲染逻辑
- **适用场景**：适合复杂条件或多分支场景
- **提前返回**：`return <h1>...</h1>` 条件满足时提前返回，避免嵌套

### 2. 逻辑与（&&）运算符

```jsx
function Notification({ count }) {
  return (
    <div>
      {count > 0 && <p>你有 {count} 条新消息</p>}
    </div>
  );
}
```

- **逻辑与条件渲染**：`{count > 0 && <p>...</p>}` 条件为 true 时渲染 JSX
- **注意**：左侧必须是布尔值，`{0 && ...}` 会渲染出 0
- **短路求值**：`A && B` 当 A 为 false 时不执行 B，当 A 为 true 时返回 B

### 3. 三元运算符

```jsx
function Status({ isLoading }) {
  return (
    <div>
      {isLoading ? <Spinner /> : <Content />}
    </div>
  );
}
```

- **三元运算符**：`{isLoading ? <Spinner /> : <Content />}` 根据条件切换两个组件
- **适用场景**：适合两个分支切换的场景
- **三元语法**：`条件 ? 真值表达式 : 假值表达式`

### 4. 条件渲染对比

| 写法 | 适用场景 | 优点 | 缺点 |
|------|---------|------|------|
| if/else | 复杂条件、多个分支 | 逻辑清晰 | 不能在 return 中直接使用 |
| && 短路 | 简单条件显示/隐藏 | 简洁 | 左侧为 0 时会渲染 0 |
| 三元运算符 | 两个分支切换 | 简洁 | 条件过多时难以维护 |

## 列表渲染

列表渲染是根据数据数组动态生成列表项的机制。

### 1. 基本列表渲染

```jsx
function TodoList({ todos }) {
  return (
    <ul>
      {todos.map(todo => (
        <li key={todo.id}>{todo.text}</li>
      ))}
    </ul>
  );
}
```

- **map 方法**：`todos.map(todo => ...)` 遍历数组，返回 JSX 元素数组
- **key 属性**：`key={todo.id}` 是每个列表项必需的 key，帮助 React 识别变化
- **箭头函数**：`todo => (...)` 箭头函数遍历每个 todo 元素
- **括号包裹**：`(...)` 多行 JSX 用括号包裹，避免自动插入分号

### 2. 列表渲染中的 key

```jsx
function UserList({ users }) {
  return (
    <ul>
      {users.map(user => (
        <UserCard key={user.id} user={user} />
      ))}
    </ul>
  );
}
```

- **key 作为 prop**：`key={user.id}` 使用唯一 ID 作为标识
- **对象作为 prop**：`user={user}` 将用户对象作为 prop 传递给子组件
- **key 的作用**：帮助 React 识别哪些列表项发生了变化、新增或删除

**为什么需要 key？** key 帮助 React 识别哪些列表项发生了变化、新增或删除。没有稳定的 key 会导致性能问题和状态丢失。

**key 的选择原则：**

| 选择 | 说明 | 推荐度 |
|------|------|--------|
| 数据唯一 ID | `key={user.id}` | 推荐 |
| 索引 | `key={index}` | 仅静态列表 |

### 3. 列表渲染中的条件过滤

```jsx
function TodoList({ todos, filter }) {
  const filteredTodos = todos.filter(todo => {
    if (filter === 'active') return !todo.done;
    if (filter === 'done') return todo.done;
    return true;
  });

  return (
    <ul>
      {filteredTodos.map(todo => (
        <li key={todo.id}>
          {todo.text}
          {todo.done && <span> ✓</span>}
        </li>
      ))}
    </ul>
  );
}
```

- **数组过滤**：`todos.filter(todo => ...)` 过滤出符合条件的 todo
- **条件渲染**：`{todo.done && <span> ✓</span>}` 条件为 true 时显示勾选标记
- **过滤在前**：`const filteredTodos =` 在渲染前完成过滤，不在 JSX 中写复杂逻辑

## 常见陷阱与最佳实践

### 1. 条件渲染中的陷阱

```jsx
// 错误：0 会渲染出数字 0
{count && <div>内容</div>}

// 正确：确保左侧是布尔值
{count > 0 && <div>内容</div>}
```

- **0 陷阱**：`{0 && ...}` 会渲染出数字 0
- **布尔值保证**：`{count > 0 && ...}` 始终确保左侧是布尔值

### 2. 列表 key 的陷阱

```jsx
// 错误：使用索引作为 key（列表动态变化时）
{items.map((item, index) => <Item key={index} />)}

// 错误：使用 Math.random()（每次渲染 key 变化，导致全部重渲染）
{items.map(item => <Item key={Math.random()} />)}

// 正确：使用唯一稳定的 ID
{items.map(item => <Item key={item.id} />)}
```

- **索引陷阱**：`key={index}` 在列表增删时会导致状态错乱
- **random 陷阱**：`key={Math.random()}` 每次渲染 key 都变化，导致全部重渲染
- **唯一 ID**：`key={item.id}` 使用唯一稳定的 ID，是最佳实践

### 3. 最佳实践

1. **列表必须提供稳定的 key**，优先使用数据唯一 ID
2. **条件渲染优先使用逻辑与或三元运算符**，保持 JSX 简洁
3. **空列表单独处理**，提供友好的空状态提示
4. **过滤逻辑在渲染前完成**，不在 JSX 中直接写复杂过滤

---

## 总结

条件渲染和列表渲染是 React 的核心渲染模式：

- **条件渲染**：基于 JavaScript 条件表达式，灵活控制 UI 显示
- **列表渲染**：使用 `map()` 遍历数组，key 是性能关键
