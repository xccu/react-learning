# TypeScript 基础详解：类型系统、接口与泛型

---

## TypeScript 的定义

TypeScript 是 JavaScript 的超集，添加了静态类型系统。它在编译时进行类型检查，帮助开发者在运行前发现错误，提升代码质量和开发体验。

**核心特点：**
- 是 JavaScript 的超集，所有 JS 代码都是合法的 TS 代码
- 提供静态类型检查，在编译时发现错误
- 支持类型推断，减少类型注解的编写
- 与 React 生态完美集成

## 基础类型

### 1. 基本类型

```typescript
// 字符串
let name: string = 'React';

// 数字
let count: number = 42;

// 布尔值
let isActive: boolean = true;

// 空值
let notDefined: null = null;
let notYet: undefined = undefined;

// 数组
let numbers: number[] = [1, 2, 3];
let strings: Array<string> = ['a', 'b', 'c'];

// 元组
let tuple: [string, number] = ['hello', 42];

// 枚举
enum Direction {
  Up = 'UP',
  Down = 'DOWN',
  Left = 'LEFT',
  Right = 'RIGHT'
}
let dir: Direction = Direction.Up;

// any：跳过类型检查（不推荐）
let flexible: any = 'hello';
flexible = 42;

// unknown：安全的 any
let safe: unknown = 'hello';
if (typeof safe === 'string') {
  console.log(safe.toUpperCase()); // 安全的类型收窄
}

// never：永不返回值的函数
function throwError(message: string): never {
  throw new Error(message);
};
```

- **类型注解**：`let name: string` 使用 `: 类型` 语法为变量标注类型
- **数组类型**：`number[]` 或 `Array<string>` 两种数组类型声明方式，前者更常用
- **元组类型**：`[string, number]` 固定长度和类型的数组，每个位置类型可不同
- **枚举类型**：`enum Direction` 定义具名常量集合，增强代码可读性
- **any 类型**：`let flexible: any` 跳过类型检查，不推荐使用
- **unknown 类型**：`let safe: unknown` 安全的 any，使用前需类型收窄
- **never 类型**：`(): never` 表示函数永不返回（如永远抛错或死循环）

### 2. 类型推断

```typescript
// 变量声明时自动推断类型
let name = 'React'; // 推断为 string
let count = 42;     // 推断为 number

// 函数返回值自动推断
function add(a: number, b: number) {
  return a + b; // 推断返回类型为 number
}

// 需要显式标注的情况
let numbers: number[] = []; // 空数组需要类型标注
numbers.push(1); // 正确
numbers.push('hello'); // 错误
```

- **类型推断**：`let name = 'React'` 根据赋值自动推断类型为 string，无需显式标注
- **返回值推断**：`function add(a: number, b: number)` 根据 return 语句推断返回类型为 number
- **空数组标注**：`let numbers: number[] = []` 空数组需要显式类型标注，否则推断为 unknown[]

## 接口与类型别名

### 1. 接口（Interface）

```typescript
interface User {
  name: string;
  age: number;
  email: string;
}

const user: User = {
  name: '小明',
  age: 20,
  email: 'xiaoming@example.com'
};

// 可选属性
interface Config {
  theme: string;
  lang?: string;  // 可选
  debug?: boolean;
}

// 只读属性
interface Point {
  readonly x: number;
  readonly y: number;
}

// 索引签名
interface StringMap {
  [key: string]: number;
}
const scores: StringMap = {
  math: 90,
  english: 85
};
```

- **接口定义**：`interface User` 定义对象形状，描述对象的属性结构
- **属性类型**：`name: string` 属性名后跟类型注解，指定属性类型
- **可选属性**：`lang?: string` 使用 `?` 标记可选属性，该属性可不存在
- **只读属性**：`readonly x: number` 属性声明后不可修改
- **索引签名**：`[key: string]: number` 允许用字符串索引访问，值为 number 类型

```typescript

```typescript
type StringOrNumber = string | number;
type ID = string | number;

type User = {
  name: string;
  age: number;
};

type ApiResponse<T> = {
  data: T;
  status: number;
  message: string;
};

// 联合类型
type Status = 'loading' | 'success' | 'error';

// 交叉类型
type Admin = User & { role: string; permissions: string[] };
```

- **类型别名**：`type StringOrNumber = string | number` 使用 type 定义类型，可用 `|` 创建联合类型
- **字面量类型**：`type Status = 'loading' | 'success'` 限定类型为特定字符串值之一
- **泛型类型**：`type ApiResponse<T>` 使用 `<T>` 定义泛型，使用时无需重复指定内部结构
- **交叉类型**：`type Admin = User & { role: string }` 使用 `&` 合并多个类型，包含所有属性

### 3. Interface vs Type

| 特性 | Interface | Type |
|------|-----------|------|
| 合并声明 | ✅ 支持 | ❌ 不支持 |
| 联合类型 | ❌ 不支持 | ✅ 支持 |
| 映射类型 | ❌ 不支持 | ✅ 支持 |
| 类实现 | ✅ 支持 | ✅ 支持 |
| 推荐场景 | 对象形状 | 联合、交叉、元组 |

## 函数类型

### 1. 函数类型定义

```typescript
// 参数和返回值类型
function add(a: number, b: number): number {
  return a + b;
}

// 可选参数
function greet(name: string, greeting?: string): string {
  return `${greeting || 'Hello'}, ${name}!`;
}

// 默认参数
function createUser(name: string, role: string = 'user') {
  return { name, role };
}

// 剩余参数
function sum(...numbers: number[]): number {
  return numbers.reduce((a, b) => a + b, 0);
};

// 函数类型
type MathOperation = (a: number, b: number) => number;
const multiply: MathOperation = (a, b) => a * b;
```

- **参数类型**：`function add(a: number, b: number)` 为每个参数标注类型
- **返回值类型**：`: number` 标注函数返回值类型
- **可选参数**：`greeting?: string` 函数参数加 `?` 标记为可选
- **默认参数**：`role: string = 'user'` 提供默认值，调用时可省略
- **剩余参数**：`...numbers: number[]` 收集多个参数为数组并标注类型
- **函数类型**：`(a: number, b: number) => number` 定义函数签名，参数和返回值类型都要标注

### 2. React 组件类型

```typescript
// 函数组件 Props 类型
interface ButtonProps {
  label: string;
  onClick: () => void;
  disabled?: boolean;
}

const Button: React.FC<ButtonProps> = ({ label, onClick, disabled = false }) => (
  <button onClick={onClick} disabled={disabled}>{label}</button>
);

// 不带 Props 的组件
const Divider: React.FC = () => <hr />;

// 使用泛型的组件
interface ListProps<T> {
  items: T[];
  renderItem: (item: T) => React.ReactNode;
}

function List<T>({ items, renderItem }: ListProps<T>) {
  return (
    <ul>
      {items.map((item, index) => (
        <li key={index}>{renderItem(item)}</li>
      ))}
    </ul>
  );
};
```

- **React.FC**：`React.FC<ButtonProps>` 函数组件类型，自动包含 React 组件的特性
- **Props 接口**：`interface ButtonProps` 定义组件接收的 props 类型
- **回调类型**：`onClick: () => void` 函数类型注解，无参数无返回值
- **可选 Props**：`disabled?: boolean` props 中的可选属性
- **泛型组件**：`interface ListProps<T>` 使用泛型 T 创建类型安全的通用组件
- **React.ReactNode**：`renderItem: (item: T) => React.ReactNode` 返回值可以是任意 React 节点

## 泛型

### 1. 基本用法

```typescript
// 泛型函数
function identity<T>(arg: T): T {
  return arg;
}
const result = identity<string>('hello');

// 泛型接口
interface Response<T> {
  data: T;
  status: number;
}

const response: Response<User> = {
  data: { name: '小明', age: 20 },
  status: 200
};

// 泛型约束
interface HasId {
  id: number;
}

function getId<T extends HasId>(item: T): number {
  return item.id;
};
```

- **泛型函数**：`function identity<T>(arg: T)` 使用 `<T>` 定义泛型参数，调用时可指定具体类型
- **泛型接口**：`interface Response<T>` 接口中使用泛型，实现时指定具体类型
- **泛型约束**：`T extends HasId` 限制 T 必须包含 HasId 的属性和类型
- **类型参数传递**：`Response<User>` 使用 `<User>` 将泛型 T 替换为具体类型

### 2. 泛型在 React 中的应用

```typescript
// 通用表单组件
interface FormFieldProps<T> {
  value: T;
  onChange: (value: T) => void;
  placeholder?: string;
}

function FormField<T>({ value, onChange, placeholder }: FormFieldProps<T>) {
  return (
    <input
      value={value as string}
      onChange={e => onChange(e.target.value as unknown as T)}
      placeholder={placeholder}
    />
  );
}

// 使用
<FormField<string> value={name} onChange={setName} placeholder="姓名" />
<FormField<number> value={age} onChange={setAge} placeholder="年龄" />
```

- **泛型组件使用**：`<FormField<string> value={name}>` 使用 `<string>` 指定泛型 T 为 string 类型
- **类型安全 onChange**：`(value: T) => void` onChange 的参数类型与泛型 T 一致
- **类型断言**：`as string` 和 `as unknown as T` 在事件处理中进行类型转换

## 类型工具

### 1. 内置工具类型

```typescript
interface User {
  name: string;
  age: number;
  email: string;
}

// Partial：所有属性可选
type PartialUser = Partial<User>;
// { name?: string; age?: number; email?: string; }

// Required：所有属性必填
type RequiredUser = Required<PartialUser>;

// Pick：选择部分属性
type UserName = Pick<User, 'name' | 'email'>;

// Omit：排除部分属性
type UserWithoutEmail = Omit<User, 'email'>;

// Record：创建键值对类型
type RoleMap = Record<string, string>;

// Readonly：所有属性只读
type ReadonlyUser = Readonly<User>;
```

- **Partial**：`Partial<User>` 将 User 所有属性变为可选
- **Required**：`Required<PartialUser>` 将 PartialUser 所有属性变为必填
- **Pick**：`Pick<User, 'name' | 'email'>` 从 User 中选择指定属性
- **Omit**：`Omit<User, 'email'>` 从 User 中排除指定属性
- **Record**：`Record<string, string>` 创建键为 string、值为 string 的对象类型
- **Readonly**：`Readonly<User>` 将 User 所有属性变为只读

### 2. 类型守卫

```typescript
// 类型断言
const name = (user.name) as string;
const name2 = user.name as string;

// typeof 类型守卫
function format(value: string | number) {
  if (typeof value === 'string') {
    return value.toUpperCase();
  }
  return value.toString();
}

// in 类型守卫
interface Dog { bark(): void; }
interface Cat { meow(): void; }

function move(pet: Dog | Cat) {
  if ('bark' in pet) {
    pet.bark();
  } else {
    pet.meow();
  }
}

// 自定义类型守卫
function isUser(value: unknown): value is User {
  return typeof value === 'object' && value !== null && 'name' in value;
};
```

- **类型断言**：`as string` 告诉编译器值是指定类型，跳过类型检查
- **typeof 守卫**：`typeof value === 'string'` 在条件块内 TypeScript 自动收窄类型
- **in 守卫**：`'bark' in pet` 检查对象是否包含指定属性，用于区分联合类型
- **自定义守卫**：`value is User` 谓词类型，自定义类型判断函数，返回 boolean 同时收窄类型

## 深入思考

### 1. 类型推断的局限性

```typescript
// 推断为 any
const arr = [];
arr.push(1);
arr.push('hello'); // 不会报错

// 解决：显式标注
const numbers: number[] = [];

// 推断为 {}
const obj = {};
obj.name = 'hello'; // 不会报错

// 解决：显式标注
const obj: Record<string, any> = {};
```

- **空数组推断**：`const arr = []` 推断为 `any[]`，失去类型保护
- **空对象推断**：`const obj = {}` 推断为 `{}`，可任意添加属性
- **显式标注**：`const numbers: number[] = []` 手动指定类型，获得完整类型检查

### 2. 类型与运行时检查

```typescript
// 类型只在编译时检查，运行时不存在
type User = { name: string; age: number };
const user: User = { name: '小明', age: '20' }; // 编译时报错

// Zod 库用于运行时验证
import { z } from 'zod';

const UserSchema = z.object({
  name: z.string(),
  age: z.number()
});

type User = z.infer<typeof UserSchema>;

const result = UserSchema.safeParse({ name: '小明', age: 20 });
if (result.success) {
  const user = result.data; // 类型安全
}
```

- **编译时类型**：`type User` 定义的类型在编译后被移除，运行时不存在
- **Zod Schema**：`z.object({ name: z.string() })` 定义运行时验证规则
- **z.infer**：`z.infer<typeof UserSchema>` 从 Schema 推断 TypeScript 类型
- **safeParse**：`UserSchema.safeParse(...)` 安全解析，返回 success/error 对象

### 3. 类型性能考量

```typescript
// 复杂类型可能增加编译时间
type DeepNested = {
  level1: {
    level2: {
      level3: {
        level4: {
          value: string;
        }
      }
    }
  }
};

// 优化：使用接口拆分
interface Level4 { value: string; }
interface Level3 { level4: Level4; }
interface Level2 { level3: Level3; }
interface Level1 { level2: Level2; }
```

- **嵌套类型**：`type DeepNested = { level1: { level2: ... } }` 深层嵌套类型增加编译负担
- **接口拆分**：`interface Level4` 将嵌套类型拆分为多个扁平接口，提升编译性能
- **类型引用**：`level4: Level4` 通过接口引用替代内联嵌套，保持类型可读性

## 常见陷阱与最佳实践

### 1. 避免使用 any

```typescript
// 不推荐
const data: any = fetchData();

// 推荐：使用 unknown 或具体类型
const data: unknown = fetchData();
if (typeof data === 'object' && data !== null) {
  // 类型收窄
}

// 或使用类型断言（明确知道类型时）
const data = fetchData() as ApiResponse<User>;
```

- **any 问题**：`const data: any` 完全跳过类型检查，失去 TypeScript 保护
- **unknown 替代**：`const data: unknown` 安全的顶部类型，使用前需类型收窄
- **类型断言**：`as ApiResponse<User>` 明确知道类型时使用断言，比 any 更安全

### 2. 接口 vs 类型选择

```typescript
// 对象形状使用 Interface
interface User {
  name: string;
  age: number;
}

// 联合、交叉、映射使用 Type
type Status = 'loading' | 'success' | 'error';
type Admin = User & { role: string };
```

- **Interface 适用场景**：`interface User` 定义对象形状，支持声明合并
- **Type 适用场景**：`type Status = 'loading' | 'success'` 联合类型、交叉类型使用 type

### 3. React 类型最佳实践

```typescript
// 推荐：使用 React.FC（可选）
const Button: React.FC<ButtonProps> = ({ label }) => <button>{label}</button>;

// 推荐：Props 使用 interface
interface Props {
  name: string;
}

// 推荐：使用泛型处理通用组件
function List<T>({ items }: { items: T[] }) {
  return <ul>{items.map((item, i) => <li key={i}>{item}</li>)}</ul>;
}

// 不推荐：使用 any
const Component: React.FC<{ data: any }> = ({ data }) => <div>{data}</div>;
```

### 4. 最佳实践

1. **开启严格模式**（`"strict": true`），获得最严格的类型检查
2. **避免 any**，使用 unknown 或具体类型替代
3. **接口用于对象形状**，类型用于联合和复杂类型
4. **善用类型工具**（Partial、Pick、Omit 等）
5. **React 组件定义 Props 类型**，提升可维护性
6. **使用 Zod 等库进行运行时验证**，弥补编译时类型的不足

## 总结

TypeScript 为 JavaScript 带来强大的类型系统：

- **基础类型**：string、number、boolean、数组、元组等
- **接口与类型别名**：定义对象形状和复杂类型
- **泛型**：创建可复用的类型安全的组件和函数
- **类型工具**：Partial、Pick、Omit 等内置工具类型
- **最佳实践**：避免 any，开启严格模式，合理选择 Interface/Type
