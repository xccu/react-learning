# TypeScript 基础详解：类型系统、接口与泛型

---

## TypeScript 的定义

TypeScript 是 JavaScript 的超集，添加了静态类型系统。它在编译时进行类型检查，帮助开发者在运行前发现错误，提升代码质量和开发体验。

**核心特点：**
- 是 JavaScript 的超集，所有 JS 代码都是合法的 TS 代码
- 提供静态类型检查，在编译时发现错误
- 支持类型推断，减少类型注解的编写
- 与 React 生态完美集成

## 基础类型

### 1. 基本类型

```typescript
// 字符串
let name: string = 'React';

// 数字
let count: number = 42;

// 布尔值
let isActive: boolean = true;

// 空值
let notDefined: null = null;
let notYet: undefined = undefined;

// 数组
let numbers: number[] = [1, 2, 3];
let strings: Array<string> = ['a', 'b', 'c'];

// 元组
let tuple: [string, number] = ['hello', 42];

// 枚举
enum Direction {
  Up = 'UP',
  Down = 'DOWN',
  Left = 'LEFT',
  Right = 'RIGHT'
}
let dir: Direction = Direction.Up;

// any：跳过类型检查（不推荐）
let flexible: any = 'hello';
flexible = 42;

// unknown：安全的 any
let safe: unknown = 'hello';
if (typeof safe === 'string') {
  console.log(safe.toUpperCase()); // 安全的类型收窄
}

// never：永不返回值的函数
function throwError(message: string): never {
  throw new Error(message);
}
```

### 2. 类型推断

```typescript
// 变量声明时自动推断类型
let name = 'React'; // 推断为 string
let count = 42;     // 推断为 number

// 函数返回值自动推断
function add(a: number, b: number) {
  return a + b; // 推断返回类型为 number
}

// 需要显式标注的情况
let numbers: number[] = []; // 空数组需要类型标注
numbers.push(1); // 正确
numbers.push('hello'); // 错误
```

## 接口与类型别名

### 1. 接口（Interface）

```typescript
interface User {
  name: string;
  age: number;
  email: string;
}

const user: User = {
  name: '小明',
  age: 20,
  email: 'xiaoming@example.com'
};

// 可选属性
interface Config {
  theme: string;
  lang?: string;  // 可选
  debug?: boolean;
}

// 只读属性
interface Point {
  readonly x: number;
  readonly y: number;
}

// 索引签名
interface StringMap {
  [key: string]: number;
}
const scores: StringMap = {
  math: 90,
  english: 85
};
```

### 2. 类型别名（Type Alias）

```typescript
type StringOrNumber = string | number;
type ID = string | number;

type User = {
  name: string;
  age: number;
};

type ApiResponse<T> = {
  data: T;
  status: number;
  message: string;
};

// 联合类型
type Status = 'loading' | 'success' | 'error';

// 交叉类型
type Admin = User & { role: string; permissions: string[] };
```

### 3. Interface vs Type

| 特性 | Interface | Type |
|------|-----------|------|
| 合并声明 | ✅ 支持 | ❌ 不支持 |
| 联合类型 | ❌ 不支持 | ✅ 支持 |
| 映射类型 | ❌ 不支持 | ✅ 支持 |
| 类实现 | ✅ 支持 | ✅ 支持 |
| 推荐场景 | 对象形状 | 联合、交叉、元组 |

## 函数类型

### 1. 函数类型定义

```typescript
// 参数和返回值类型
function add(a: number, b: number): number {
  return a + b;
}

// 可选参数
function greet(name: string, greeting?: string): string {
  return `${greeting || 'Hello'}, ${name}!`;
}

// 默认参数
function createUser(name: string, role: string = 'user') {
  return { name, role };
}

// 剩余参数
function sum(...numbers: number[]): number {
  return numbers.reduce((a, b) => a + b, 0);
}

// 函数类型
type MathOperation = (a: number, b: number) => number;
const multiply: MathOperation = (a, b) => a * b;
```

### 2. React 组件类型

```typescript
// 函数组件 Props 类型
interface ButtonProps {
  label: string;
  onClick: () => void;
  disabled?: boolean;
}

const Button: React.FC<ButtonProps> = ({ label, onClick, disabled = false }) => (
  <button onClick={onClick} disabled={disabled}>{label}</button>
);

// 不带 Props 的组件
const Divider: React.FC = () => <hr />;

// 使用泛型的组件
interface ListProps<T> {
  items: T[];
  renderItem: (item: T) => React.ReactNode;
}

function List<T>({ items, renderItem }: ListProps<T>) {
  return (
    <ul>
      {items.map((item, index) => (
        <li key={index}>{renderItem(item)}</li>
      ))}
    </ul>
  );
}
```

## 泛型

### 1. 基本用法

```typescript
// 泛型函数
function identity<T>(arg: T): T {
  return arg;
}
const result = identity<string>('hello');

// 泛型接口
interface Response<T> {
  data: T;
  status: number;
}

const response: Response<User> = {
  data: { name: '小明', age: 20 },
  status: 200
};

// 泛型约束
interface HasId {
  id: number;
}

function getId<T extends HasId>(item: T): number {
  return item.id;
}
```

### 2. 泛型在 React 中的应用

```typescript
// 通用表单组件
interface FormFieldProps<T> {
  value: T;
  onChange: (value: T) => void;
  placeholder?: string;
}

function FormField<T>({ value, onChange, placeholder }: FormFieldProps<T>) {
  return (
    <input
      value={value as string}
      onChange={e => onChange(e.target.value as unknown as T)}
      placeholder={placeholder}
    />
  );
}

// 使用
<FormField<string> value={name} onChange={setName} placeholder="姓名" />
<FormField<number> value={age} onChange={setAge} placeholder="年龄" />
```

## 类型工具

### 1. 内置工具类型

```typescript
interface User {
  name: string;
  age: number;
  email: string;
}

// Partial：所有属性可选
type PartialUser = Partial<User>;
// { name?: string; age?: number; email?: string; }

// Required：所有属性必填
type RequiredUser = Required<PartialUser>;

// Pick：选择部分属性
type UserName = Pick<User, 'name' | 'email'>;

// Omit：排除部分属性
type UserWithoutEmail = Omit<User, 'email'>;

// Record：创建键值对类型
type RoleMap = Record<string, string>;

// Readonly：所有属性只读
type ReadonlyUser = Readonly<User>;
```

### 2. 类型守卫

```typescript
// 类型断言
const name = (user.name) as string;
const name2 = user.name as string;

// typeof 类型守卫
function format(value: string | number) {
  if (typeof value === 'string') {
    return value.toUpperCase();
  }
  return value.toString();
}

// in 类型守卫
interface Dog { bark(): void; }
interface Cat { meow(): void; }

function move(pet: Dog | Cat) {
  if ('bark' in pet) {
    pet.bark();
  } else {
    pet.meow();
  }
}

// 自定义类型守卫
function isUser(value: unknown): value is User {
  return typeof value === 'object' && value !== null && 'name' in value;
}
```

## 深入思考

### 1. 类型推断的局限性

```typescript
// 推断为 any
const arr = [];
arr.push(1);
arr.push('hello'); // 不会报错

// 解决：显式标注
const numbers: number[] = [];

// 推断为 {}
const obj = {};
obj.name = 'hello'; // 不会报错

// 解决：显式标注
const obj: Record<string, any> = {};
```

### 2. 类型与运行时检查

```typescript
// 类型只在编译时检查，运行时不存在
type User = { name: string; age: number };
const user: User = { name: '小明', age: '20' }; // 编译时报错

// Zod 库用于运行时验证
import { z } from 'zod';

const UserSchema = z.object({
  name: z.string(),
  age: z.number()
});

type User = z.infer<typeof UserSchema>;

const result = UserSchema.safeParse({ name: '小明', age: 20 });
if (result.success) {
  const user = result.data; // 类型安全
}
```

### 3. 类型性能考量

```typescript
// 复杂类型可能增加编译时间
type DeepNested = {
  level1: {
    level2: {
      level3: {
        level4: {
          value: string;
        }
      }
    }
  }
};

// 优化：使用接口拆分
interface Level4 { value: string; }
interface Level3 { level4: Level4; }
interface Level2 { level3: Level3; }
interface Level1 { level2: Level2; }
```

## 常见陷阱与最佳实践

### 1. 避免使用 any

```typescript
// 不推荐
const data: any = fetchData();

// 推荐：使用 unknown 或具体类型
const data: unknown = fetchData();
if (typeof data === 'object' && data !== null) {
  // 类型收窄
}

// 或使用类型断言（明确知道类型时）
const data = fetchData() as ApiResponse<User>;
```

### 2. 接口 vs 类型选择

```typescript
// 对象形状使用 Interface
interface User {
  name: string;
  age: number;
}

// 联合、交叉、映射使用 Type
type Status = 'loading' | 'success' | 'error';
type Admin = User & { role: string };
```

### 3. React 类型最佳实践

```typescript
// 推荐：使用 React.FC（可选）
const Button: React.FC<ButtonProps> = ({ label }) => <button>{label}</button>;

// 推荐：Props 使用 interface
interface Props {
  name: string;
}

// 推荐：使用泛型处理通用组件
function List<T>({ items }: { items: T[] }) {
  return <ul>{items.map((item, i) => <li key={i}>{item}</li>)}</ul>;
}

// 不推荐：使用 any
const Component: React.FC<{ data: any }> = ({ data }) => <div>{data}</div>;
```

### 4. 最佳实践

1. **开启严格模式**（`"strict": true`），获得最严格的类型检查
2. **避免 any**，使用 unknown 或具体类型替代
3. **接口用于对象形状**，类型用于联合和复杂类型
4. **善用类型工具**（Partial、Pick、Omit 等）
5. **React 组件定义 Props 类型**，提升可维护性
6. **使用 Zod 等库进行运行时验证**，弥补编译时类型的不足

## 总结

TypeScript 为 JavaScript 带来强大的类型系统：

- **基础类型**：string、number、boolean、数组、元组等
- **接口与类型别名**：定义对象形状和复杂类型
- **泛型**：创建可复用的类型安全的组件和函数
- **类型工具**：Partial、Pick、Omit 等内置工具类型
- **最佳实践**：避免 any，开启严格模式，合理选择 Interface/Type
