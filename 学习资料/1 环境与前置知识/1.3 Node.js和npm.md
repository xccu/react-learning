# Node.js 和 npm 详解：环境配置、包管理与脚本命令

---

## Node.js 的定义

Node.js 是一个基于 Chrome V8 引擎的 JavaScript 运行时环境，允许在服务器端运行 JavaScript。它是 React 开发环境的基础。

**核心特点：**
- 非阻塞 I/O 模型，适合高并发场景
- 拥有全球最大的包生态系统（npm）
- React 项目的构建和开发依赖 Node.js

**官方文档链接：**
- [Node.js 官方文档](https://nodejs.org/en/docs/)
- [npm 官方文档](https://docs.npmjs.com/)

## Node.js 基础

### 1. 安装与版本管理

```bash
# 查看 Node.js 版本
node -v

# 查看 npm 版本
npm -v

# 推荐使用 nvm 管理 Node 版本
# Windows: nvm-windows
# Mac/Linux: nvm

# 安装指定版本
nvm install 18
nvm use 18

# 设置默认版本
nvm alias default 18
```

- **node -v**：`node -v` 查看当前 Node.js 版本，确认环境配置
- **npm -v**：`npm -v` 查看 npm 包管理器版本
- **nvm 版本管理**：`nvm install 18` 安装 Node 版本，`nvm use 18` 切换版本
- **nvm alias**：`nvm alias default 18` 设置默认 Node 版本，新终端自动生效

### 2. 运行 JavaScript 文件

```javascript
// hello.js
console.log('Hello, Node.js!');

// 运行
node hello.js
```

- **console.log**：`console.log(...)` 在终端输出信息，用于调试和日志
- **node 命令**：`node hello.js` 使用 Node.js 运行 JavaScript 文件

### 3. Node.js 核心模块

```javascript
// 文件系统
const fs = require('fs');
const data = fs.readFileSync('file.txt', 'utf-8');
fs.writeFileSync('output.txt', 'Hello');

// 路径处理
const path = require('path');
const fullPath = path.join(__dirname, 'file.txt');
const fileName = path.basename(fullPath);

// 模块系统
const myModule = require('./myModule');
module.exports = myModule;
```

- **require 语法**：`require('fs')` 引入 Node.js 内置模块或第三方模块
- **同步读写**：`fs.readFileSync` 同步读取文件，阻塞执行直到读取完成
- **path.join**：`path.join(__dirname, 'file.txt')` 拼接路径，自动处理平台差异
- **__dirname**：`__dirname` 当前文件所在目录的全路径，Node.js 全局变量
- **module.exports**：`module.exports = myModule` CommonJS 模块导出方式

## npm 基础

### 1. 初始化项目

```bash
# 初始化 package.json
npm init

# 交互式初始化
npm init -y

# package.json 结构
{
  "name": "my-react-app",
  "version": "1.0.0",
  "description": "My React application",
  "main": "index.js",
  "scripts": {
    "start": "react-scripts start",
    "build": "react-scripts build",
    "test": "react-scripts test"
  },
  "dependencies": {
    "react": "^18.2.0",
    "react-dom": "^18.2.0"
  },
  "devDependencies": {
    "typescript": "^5.0.0"
  }
}
```

- **package.json**：项目配置文件，记录项目名称、版本、依赖和脚本命令
- **name/version**：`"name"` 和 `"version"` 是包的唯一标识和版本号
- **main 入口**：`"main": "index.js"` 指定模块入口文件
- **scripts 脚本**：`"scripts"` 定义可执行的命令别名，通过 `npm run` 调用
- **dependencies**：`"dependencies"` 记录生产环境依赖，部署时需要
- **devDependencies**：`"devDependencies"` 记录开发环境依赖，如 TypeScript、ESLint

### 2. 安装依赖

```bash
# 安装生产依赖
npm install react react-dom
npm i react react-dom

# 安装开发依赖
npm install --save-dev typescript eslint
npm i -D typescript eslint

# 安装指定版本
npm install react@17.0.2

# 全局安装
npm install -g create-react-app
npm install -g typescript
```

- **npm install**：`npm install react` 安装依赖包到 node_modules 目录
- **npm i 缩写**：`npm i react` 是 npm install 的简写形式
- **--save-dev 缩写**：`npm install -D typescript` 安装开发依赖，简写为 -D
- **指定版本**：`npm install react@17.0.2` 安装指定版本的包
- **-g 全局安装**：`npm install -g` 安装包到全局，可在终端任何位置使用

### 3. 依赖类型

| 类型 | 说明 | 安装命令 | 保存位置 |
|------|------|---------|---------|
| 生产依赖 | 运行时必需 | `npm install xxx` | dependencies |
| 开发依赖 | 开发工具 | `npm install -D xxx` | devDependencies |
| 全局依赖 | 系统级工具 | `npm install -g xxx` | 全局目录 |

## npm 脚本命令

### 1. 定义脚本

```json
{
  "scripts": {
    "start": "react-scripts start",
    "build": "react-scripts build",
    "test": "react-scripts test",
    "eject": "react-scripts eject",
    "lint": "eslint src/",
"format": "prettier --write src/"
  }
}
```

- **scripts 定义**：`"scripts"` 中定义命令别名，简化复杂命令的使用
- **npm run**：`npm run start` 执行 scripts 中定义的命令
- **cross-env**：`cross-env PORT=3001` 跨平台设置环境变量，解决 Windows 和 Unix 差异

### 3. npm 生命周期钩子

```json
{
  "scripts": {
    "preinstall": "echo '安装前执行'",
    "postinstall": "echo '安装后执行'",
    "prebuild": "echo '构建前执行'",
    "postbuild": "echo '构建后执行'"
  }
}
```

- **生命周期钩子**：`preinstall` 在 `install` 之前执行，`postinstall` 在之后执行
- **pre/post 模式**：`prebuild`/`postbuild` 在构建前后执行自定义脚本
- **脚本命名规则**：npm 自动识别 `pre<脚本名>` 和 `post<脚本名>` 并在前后执行

## 包管理进阶

### 1. package-lock.json

```bash
# package-lock.json 的作用
# 锁定依赖版本，确保团队成员安装一致的依赖

# 更新锁文件
npm install
npm update

# 清理并重新安装
rm -rf node_modules package-lock.json
npm install
```

- **package-lock.json**：锁定依赖版本，确保团队成员安装一致的依赖
- **npm install**：`npm install` 根据 lock 文件安装精确版本的依赖
- **npm update**：`npm update` 更新所有依赖到兼容版本
- **rm -rf**：`rm -rf node_modules` 删除依赖目录，配合重新安装解决依赖冲突

### 2. 常用 npm 命令

```bash
# 查看已安装的包
npm list
npm list --depth=0

# 查看过时的包
npm outdated

# 更新包
npm update
npm update <package-name>

# 卸载包
npm uninstall react
npm uninstall -D eslint

# 搜索包
npm search react

# 查看包信息
npm info react

# 查看包的使用量
npm view react downloads
```

- **npm list**：`npm list` 查看已安装的包及其依赖树
- **npm outdated**：`npm outdated` 检查过时的依赖包
- **npm update**：`npm update` 更新依赖到兼容版本
- **npm uninstall**：`npm uninstall react` 卸载指定包
- **npm search**：`npm search react` 在 npm 仓库中搜索包
- **npm info**：`npm info react` 查看包的详细信息
- **npm view**：`npm view react downloads` 查看包的下载量统计

### 3. 镜像源配置

```bash
# 查看当前镜像源
npm config get registry

# 切换为淘宝镜像
npm config set registry https://registry.npmmirror.com

# 切换为官方源
npm config set registry https://registry.npmjs.org

# 使用 nrm 管理镜像源
npm install -g nrm
nrm ls
nrm use taobao
```

- **npm config get registry**：`npm config get registry` 查看当前镜像源地址
- **npm config set registry**：`npm config set registry URL` 切换 npm 镜像源
- **nrm 工具**：`nrm ls/use` 使用 nrm 工具快速切换和管理多个镜像源

## React 项目中的 npm 使用

### 1. create-react-app

```bash
# 创建 React 项目
npx create-react-app my-app
cd my-app
npm start

# 创建 TypeScript 项目
npx create-react-app my-app --template typescript
```

- **npx**：`npx create-react-app` 执行 npm 包中的可执行文件，无需全局安装
- **cd 命令**：`cd my-app` 进入创建的项目目录
- **npm start**：`npm start` 启动开发服务器，默认打开 localhost:3000
- **--template**：`--template typescript` 指定使用 TypeScript 模板创建项目

### 2. Vite 创建 React 项目

```bash
# 使用 Vite 创建 React 项目
npm create vite@latest my-app -- --template react
npm create vite@latest my-app-ts -- --template react-ts
cd my-app
npm install
npm run dev
```

- **npm create vite@latest**：`npm create vite@latest` 使用 Vite 脚手架创建项目
- **-- --template**：`-- --template react` 双破折号后是传递给 vite 的参数
- **npm install**：`npm install` 安装项目依赖到 node_modules
- **npm run dev**：`npm run dev` 启动 Vite 开发服务器，支持热更新

### 3. 常用依赖分类

```json
{
  "dependencies": {
    "react": "^18.2.0",
    "react-dom": "^18.2.0",
    "react-router-dom": "^6.0.0"
  },
  "devDependencies": {
    "typescript": "^5.0.0",
    "@types/react": "^18.2.0",
    "@types/react-dom": "^18.2.0",
    "eslint": "^8.0.0",
    "prettier": "^3.0.0",
    "vite": "^5.0.0",
    "@vitejs/plugin-react": "^4.0.0"
  }
}
```

- **dependencies**：`"dependencies"` 包含运行时必需的包，如 react、react-dom、react-router-dom
- **devDependencies**：`"devDependencies"` 包含开发工具，如 TypeScript、ESLint、Prettier、Vite
- **@types/react**：`"@types/react"` TypeScript 类型定义包，为 React 提供类型提示
- **^版本号**：`"^18.2.0"` 允许更新到次版本，如 18.3.0，但不更新到主版本 19.0.0

## 深入思考

### 1. 依赖树与 hoisting

```bash
# npm 会将依赖提升到顶层（npm v3+）
# 但嵌套依赖仍可能产生版本冲突

# 查看依赖树
npm ls
npm ls react

# 查找重复依赖
npm ls --all | grep -E "duplicate|UNMET"
```

- **npm ls**：`npm ls` 查看依赖树，展示包之间的依赖关系
- **npm ls react**：`npm ls react` 查看特定包的依赖情况
- **grep 过滤**：`grep -E "duplicate|UNMET"` 查找重复依赖或未满足的依赖

### 2. 语义化版本

```
主版本.次版本.修订版本
  ^       ^     ^
  |       |     └─ 补丁：向后兼容的 bug 修复
  |       └────── 新功能：向后兼容
  └────────────── 不兼容的 API 变更

# 版本范围
"react": "^18.2.0"    # >=18.2.0 <19.0.0
"react": "~18.2.0"    # >=18.2.0 <18.3.0
"react": "18.2.0"     # 精确版本
"react": ">=18.0.0"   # 大于等于
```

- **语义化版本**：`主版本.次版本.修订版本`，如 18.2.0 分别表示主版本、次版本、补丁
- **^ caret**：`"^18.2.0"` 允许次版本更新，`>=18.2.0 <19.0.0`
- **~ tilde**：`"~18.2.0"` 允许补丁更新，`>=18.2.0 <18.3.0`
- **精确版本**：`"18.2.0"` 锁定精确版本，不自动更新

### 3. 依赖安装优化

```bash
# 使用 pnpm 替代 npm（节省磁盘空间，安装更快）
npm install -g pnpm
pnpm create vite my-app --template react
pnpm install
pnpm add react
pnpm add -D typescript

# 使用 yarn
npm install -g yarn
yarn create vite my-app --template react
yarn install
yarn add react
```

- **pnpm**：`npm install -g pnpm` 全局安装 pnpm，使用符号链接节省磁盘空间
- **pnpm add**：`pnpm add react` 安装依赖，比 npm 安装更快
- **yarn**：`npm install -g yarn` 全局安装 yarn，另一种流行的包管理器
- **yarn add**：`yarn add react` 使用 yarn 安装依赖

## 常见陷阱与最佳实践

### 1. 不要提交 node_modules

```bash
# .gitignore 中应包含
node_modules/
dist/
.env
```

- **.gitignore**：`.gitignore` 文件指定 git 忽略的文件和目录
- **node_modules/**：`node_modules/` 不提交，通过 package.json 重新安装
- **dist/**：`dist/` 构建产物不提交，由 CI/CD 生成
- **.env**：`.env` 环境变量文件不提交，避免泄露敏感信息

### 2. 锁定依赖版本

```bash
# 始终提交 package-lock.json
# 确保团队成员安装一致的依赖版本

# 生产环境使用精确版本
npm install react@18.2.0 --save --save-exact
```

- **package-lock.json**：`package-lock.json` 锁定依赖树，确保团队环境一致
- **--save-exact**：`--save-exact` 安装时记录精确版本，不使用 ^ 或 ~

### 3. 定期更新依赖

```bash
# 检查过时依赖
npm outdated

# 安全更新
npm audit
npm audit fix

# 手动更新
npm update
```

### 4. 最佳实践

1. **区分生产依赖和开发依赖**，减小生产包体积
2. **提交 package-lock.json**，确保环境一致性
3. **不要提交 node_modules**，在 CI/CD 中重新安装
4. **定期更新依赖**，修复安全漏洞
5. **使用 nvm 管理 Node 版本**，避免版本冲突
6. **考虑使用 pnpm/yarn**，提升安装速度和磁盘效率
7. **敏感信息放入 .env**，不要提交到版本控制

- **Node.js**：JavaScript 运行时，提供执行环境和核心模块

- **版本管理**：语义化版本、package-lock.json、nvm
