# 第3阶段：React 生态与工程化 — 学习计划（6周）

> 基于已有的「工时填报」单页应用，引入路由、数据请求、状态管理、UI 组件库等生态工具，将其改造为一个功能完整的后台管理系统。
>
> **前置条件**：已完成第1、2阶段学习，具备一个使用 Context + useState 管理的工时填报单页应用。
>
> **阶段产出的 8 个功能（按实现顺序）**：
> ① 登录 → ② 列表页 → ③ 详情页 → ④ 增删改查 → ⑤ 导入导出 → ⑥ 提交-审批-驳回-重填流程管理 → ⑦ 用户管理 → ⑧ 权限管理

---

## 一、总体学习路径

### 每周概览（严格按产出顺序）

| 周次 | 对应产出功能 | 主题 | 引入的技术栈 |
|------|------------|------|-------------|
| 第1周 | ①登录、②列表页、③详情页 | 路由与页面结构 | React Router |
| 第2周 | ④增删改查（新增、编辑、删除、列表查询） | 数据请求与表单 | Axios、React Hook Form |
| 第3周 | ⑤导入导出 | Excel 导入导出 + 性能优化基础 | xlsx（SheetJS）、组件缓存 |
| 第4周 | ⑥审批流程（提交-审批-驳回-重填） | 状态管理与 UI 组件库 | Redux Toolkit、Ant Design |
| 第5周 | ⑦用户管理 | 用户 CRUD 与角色数据 | Redux（新状态模块）、Ant Design |
| 第6周 | ⑧权限管理 + 全功能打磨 | 权限控制与工程化 | 权限守卫、缓存 Hook、ESLint、Prettier、Vite |

### 难度进阶评估（由易到难）

各周技术栈的难度定位：

| 周次 | 主题 | 技术栈 | 难度 | 定位说明 |
|------|------|--------|------|---------|
| 第1周 | 路由 | React Router | 易 | 声明式配置、概念直观，是项目结构化的第一步 |
| 第2周 | 数据请求与表单 | Axios、React Hook Form | 较易 | 围绕"数据怎么来、怎么进出"，仍在熟悉的组件思维内 |
| 第3周 | 导入导出 | xlsx、组件缓存 | 较易 | 以第三方库的读/写用法为主；组件缓存是性能优化的入门 |
| 第4周 | 审批流程 | Redux Toolkit、Ant Design | 难（概念高峰） | 引入全新的全局状态范式，同时接入组件库，是全程难度峰值 |
| 第5周 | 用户管理 | Redux、Ant Design | 中等 | 完全复用第4周的模式，用于巩固状态管理 |
| 第6周 | 权限与工程化 | 权限守卫、缓存 Hook、工程化工具 | 中等 | 功能已完备，转向安全控制与工程规范，无新范式 |

**为什么这个顺序符合"由易到难、循序渐进"：**

1. **先解决"界面组织"，再解决"数据来源"**：第1周先学路由，把单页拆成多页结构，为后续所有功能提供页面骨架；第2周再学数据请求，在已有页面上填充真实数据，理解数据流的完整链路。
2. **先手工后工具、先原理后便利**：第2、3周用手工表单、手写列表理解数据流与渲染原理；第4周再引入组件库与状态管理，此时学习者能真正体会到工具的价值，而不是"为了用而用"。
3. **概念高峰放在中段而非起点**：Redux 的全局状态范式是生态中最难、最抽象的一环，安排在第4周——此时已具备"跨页面、跨组件共享数据（审批流转）"的真实业务动机；第5周用同样的模式做第二个模块来巩固，难度自然回落，形成"高峰—回落—巩固"的合理曲线。
4. **性能优化由浅入深**：第3周先学最直观的组件缓存，第6周再学进阶的缓存 Hook（缓存计算结果与函数引用），符合认知梯度，避免一开始就被抽象概念淹没。
5. **同一主题内部分层**：路由守卫从第1周的"登录态守卫"（易）到第6周的"角色权限守卫"（进阶）逐步加深，权限管理建立在完整登录体系与用户状态之上。
6. **工程化收尾而非开局**：代码规范、格式化、构建优化、环境变量与部署属于"打磨"性质，放在最后一周作为全项目收尾，避免过早陷入配置细节而耽误核心功能学习。

**结论**：当前计划整体按"由易到难、循序渐进"规划，难点集中且有真实业务动机支撑，后续通过复用既有模式降低学习曲线。其中第4周为全程难度与任务量峰值，若进度紧张可适当放宽，不必强求一周内全部完成。

### 阶段推进原则

- 每周的产出建立在上一周基础之上，**不要跳周**。
- 每引入一个新的技术栈，都先解决一个**真实的业务痛点**，再谈它的全部能力。
- 功能优先于优雅：先跑通，再优化，最后打磨。

## 第1周：路由与页面结构

### 对应产出

| 产出序号 | 产出内容 | 本周完成度 |
|---------|---------|-----------|
| ① | 登录 | ✅ 完成登录页与登录状态守卫 |
| ② | 列表页 | ✅ 完成页面结构与路由，数据加载在第2周 |
| ③ | 详情页 | ✅ 完成动态路由与页面框架，数据加载在第2周 |

### 学习目标

- 理解 SPA（单页应用）路由的基本概念（URL 与页面组件的映射）
- 掌握路由的配置、导航与参数传递
- 将单页应用拆分为多页面结构

### 引入的技术栈

- **React Router** — 前端路由解决方案，以声明方式将 URL 映射到页面组件，无需后端配合

### 本周任务

1. **拆解页面结构**（约1天）：将现有单页拆分为登录页、主布局页、列表页、详情页、404 页。主布局承载统一框架（如侧边导航 + 主内容区），子页面在内容区渲染。
2. **配置基础路由**（约1天）：建立 URL 与页面的映射关系；支持主布局内嵌套子页面；为未匹配地址提供 404 兜底。
3. **实现登录页**（约1天）：登录表单与基本校验；登录成功后保存登录状态并跳转至主页面。
4. **实现登录守卫**（约0.5天）：未登录访问受保护页面时自动跳转到登录页；登录成功后返回用户原本想访问的页面。
5. **实现详情页路由**（约0.5天）：通过 URL 中的可变标识定位单条记录；列表项与详情页之间的页面导航；详情页内读取该标识。
6. **完成 404 页面**（约0.5天）：提示页面不存在，并提供返回入口。

### 知识清单

| 概念 | 说明 |
|------|------|
| 路由 | 将不同 URL 映射到不同页面组件 |
| 浏览器路由 | 基于浏览器 History 的路径管理，URL 形态与普通路径一致 |
| 声明式导航 | 通过链接组件进行页面跳转，不刷新页面 |
| 编程式导航 | 在业务逻辑代码中触发跳转 |
| 嵌套路由 | 父页面内嵌子页面，子页面在占位区域渲染 |
| 动态路由参数 | URL 中包含可变标识，用于定位单条数据 |
| 路由守卫 | 在进入页面前做条件判断（如登录态）并拦截跳转 |
| 登录状态持久化 | 登录状态在刷新后仍保留，并在页面间传递 |

### 第1周产出确认

- [ ] ① **登录页**：登录表单、校验，成功后保存登录状态并跳转列表页
- [ ] ② **列表页路由**：主页面路由配置完成，页面框架搭建（暂用静态数据占位）
- [ ] ③ **详情页路由**：动态路由配置完成，能读取标识（数据加载待第2周）
- [ ] 带统一框架的主布局（导航高亮 + 退出登录）
- [ ] 登录守卫（未登录自动跳转登录页，登录后返回原页面）

### 学习目标

- 理解前后端数据交互的完整链路

5. **实现删除**（约0.5天）：删除前确认；删除成功后即时更新列表，界面体验先行。
6. **详情页数据加载**（约0.5天）：根据路由中的标识获取并展示单条记录详情。

### 知识清单

| 概念 | 说明 |
|------|------|

| 拦截器 | 请求发出前统一附加凭证、收到响应后统一错误处理 |
| 数据请求流程 | 页面挂载 → 发起请求 → 渲染数据 → 处理失败 |
| 加载状态管理 | 加载中、加载失败、空数据三种状态的展示 |
| 表单库 | 通过注册字段的方式管理表单，减少手动监听 |
| 表单验证 | 必填、自定义规则、提交前统一校验 |
| 提交状态 | 提交中禁用按钮，防止重复提交 |
| 交互反馈 | 操作成功的提示与列表的即时刷新 |

- 掌握缓存 Hook（缓存计算结果与函数引用），与第3周组件缓存形成完整优化体系
- 完成工程化收尾（代码规范、格式化、构建优化、环境变量、生产构建）

### 引入的技术栈

- 权限守卫、权限控制组件
- 缓存 Hook（值缓存、函数缓存）
- ESLint、Prettier、Vite

### 本周任务

1. **路由级权限**（约1天）：在第1周登录守卫基础上，增加角色判断——按角色限制页面访问，无权访问时跳转到提示页。
2. **按钮级权限**（约0.5天）：按角色控制操作入口（如"新增用户"）的显隐，权限逻辑封装为可复用的控制组件。
3. **动态菜单**（约0.5天）：为导航项标注可见角色，按当前用户角色过滤侧边栏菜单。
4. **性能优化进阶**（约1天）：在列表过滤、数据处理等场景缓存计算结果；为传给缓存组件的回调缓存函数引用；并与第3周组件缓存对照，明确三者各自的使用场景。
5. **工程化收尾**（约1.5天）：接入代码规范检查并按提示修复；统一代码格式化；优化构建配置（代码分割、路径别名）；按环境区分配置（开发 / 生产）；执行生产构建并验证产物。

## 学习建议

1. **严格按周推进**：每周的产出建立在上一周基础之上，不要跳周。
2. **第4周预留弹性**：这是全程难度与任务量峰值，若进度紧张可适当放宽，先保证审批流程跑通。
3. **先跑通再优化**：第一遍实现功能时不必追求完美，先让功能跑起来，再谈组件缓存、代码规范等优化。
4. **每周结束时对照「产出确认」清单**打勾，确保本周目标全部完成。
5. **善用浏览器开发者工具**：网络面板查看请求，React DevTools 查看组件与状态。
6. **不要急于引入新工具**：本周计划已包含所有必要技术，不要额外添加；先体会当前工具解决的痛点，再考虑扩展。

> 完成本阶段后，你将具备开发中后台管理系统的能力，为第4阶段 Taro 小程序开发打下坚实基础。
