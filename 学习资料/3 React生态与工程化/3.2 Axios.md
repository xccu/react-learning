# Axios 详解：数据请求与拦截器

---

## Axios 的定义

Axios 是一个基于 Promise 的 HTTP 客户端，用于浏览器和 Node.js，是 React 项目中前后端数据交互的主流方案。它以简洁的 API 完成对后端接口的请求（增删改查）与响应处理，配合拦截器可在请求发出前和响应返回后统一处理公共逻辑。

**核心特点：**
- 基于 Promise，支持 `async/await` 语法，代码可读性强
- 支持请求与响应拦截器，可统一附加凭证、统一错误处理
- 浏览器端支持取消请求、自动转换 JSON 数据，并提供超时控制

## Axios 基本用法

### 1. 基本请求方法

Axios 针对增删改查提供了对应的方法，所有方法都返回 Promise，配合 `async/await` 简化异步代码：

```ts
import axios from 'axios';

// 1. 查询：GET 请求，获取工时记录列表
const fetchWorkLogs = async () => {
  const response = await axios.get('/api/work-logs');
  return response.data;
};

// 2. 新增：POST 请求，新增一条工时记录
const createWorkLog = async (record) => {
  const response = await axios.post('/api/work-logs', record);
  return response.data;
};

// 3. 修改：PUT 请求，更新整条工时记录
const updateWorkLog = async (id, record) => {
  const response = await axios.put(`/api/work-logs/${id}`, record);
  return response.data;
};

// 4. 删除：DELETE 请求，删除指定的工时记录
const deleteWorkLog = async (id) => {
  const response = await axios.delete(`/api/work-logs/${id}`);
  return response.data;
};

// 5. 组件中使用：配合 async/await 与加载状态
const WorkLogPage = () => {
  const [records, setRecords] = useState([]);
  const [loading, setLoading] = useState(false);

  const loadRecords = async () => {
    setLoading(true);
    try {
      const data = await fetchWorkLogs();
      setRecords(data);
    } finally {
      setLoading(false);
    }
  };

  return (
    <div>
      <button onClick={loadRecords} disabled={loading}>
        {loading ? '加载中...' : '加载工时记录'}
      </button>
      <ul>
        {records.map((item) => (
          <li key={item.id}>{item.projectName}</li>
        ))}
      </ul>
    </div>
  );
};
```

- **请求方法对应**：`GET` 查询、`POST` 新增、`PUT` 修改、`DELETE` 删除，语义清晰
- **返回 Promise**：所有方法返回 Promise，`await` 拿到 `response`，再通过 `response.data` 取数据
- **路径参数**：`/api/work-logs/${id}` 使用模板字符串拼接路径参数，标识具体记录
- **async/await**：`await` 使异步请求像同步代码一样顺序书写，配合 `try/finally` 管理加载状态
- **加载状态**：`setLoading(true/false)` 控制按钮禁用与提示文案，防止重复请求

### 2. 创建请求实例

项目接口通常有统一前缀（如 `/api`），通过 `create` 创建实例统一配置，避免每个请求重复书写：

```ts
import axios from 'axios';

// 创建请求实例：统一地址前缀、超时时间
const request = axios.create({
  baseURL: '/api',
  timeout: 10000
});

// 使用实例发起请求，无需再写 /api 前缀
export const fetchWorkLogs = async () => {
  const response = await request.get('/work-logs');
  return response.data;
};
```

- **baseURL**：`'/api'` 统一拼接地址前缀，后续请求只需写相对路径
- **timeout**：`10000` 设置请求超时时间为 10 秒，超时自动中断并抛出错误
- **模块导出**：`export const` 将基于实例的请求函数导出，业务组件直接调用
- **统一管理**：所有接口集中在实例配置下，便于修改前缀、超时等全局参数

### 3. 拦截器

拦截器可以在请求发出前和响应返回后执行公共逻辑，例如统一附加 token 凭证、统一错误处理、登录失效跳转：

```ts
import axios from 'axios';

const request = axios.create({
  baseURL: '/api',
  timeout: 10000
});

// 请求拦截器：统一附加登录凭证
request.interceptors.request.use(
  (config) => {
    const token = localStorage.getItem('token');
    if (token) {
      config.headers.Authorization = `Bearer ${token}`;
    }
    return config;
  },
  (error) => Promise.reject(error)
);

// 响应拦截器：直接取数据、统一错误处理、登录失效跳转
request.interceptors.response.use(
  (response) => {
    const res = response.data;
    if (res.code === 0) {
      return res.data;
    }
    return Promise.reject(new Error(res.message));
  },
  (error) => {
    if (error.response?.status === 401) {
      localStorage.removeItem('token');
      window.location.href = '/login';
    }
    return Promise.reject(error);
  }
);

// 业务代码：await 直接得到业务数据，无需再取 .data
const data = await request.get('/work-logs');
```

- **请求拦截器**：`interceptors.request.use` 在请求发出前执行，从 `localStorage` 读取 token 并写入请求头
- **响应拦截器**：`interceptors.response.use` 在响应返回后执行，`code === 0` 时直接返回业务数据 `res.data`
- **业务错误处理**：后端返回业务错误码时统一 `Promise.reject`，抛出带错误信息的异常
- **登录失效**：`status === 401` 时清除 token 并跳转登录页，实现统一认证拦截
- **简化业务代码**：拦截器处理后，业务层 `await request.get(...)` 直接得到数据，无需重复取 `.data` 和判断状态码

### 4. 可选链安全访问

网络异常时 `error.response` 可能为 `undefined`，直接访问其属性会报错，使用可选链 `?.` 安全访问：

```ts
try {
  const data = await request.get('/work-logs');
  console.log(data);
} catch (error) {
  // 错误：网络异常时 error.response 为 undefined，直接访问会报 TypeError
  // const status = error.response.status;

  // 正确：使用可选链，undefined 时安全返回 undefined，不会抛错
  const status = error.response?.status;
  const message = error.message || '请求失败，请检查网络';

  if (status === 401) {
    window.location.href = '/login';
  } else {
    alert(message);
  }
}
```

- **可选链**：`error.response?.status` 当 `error.response` 为 `undefined` 时返回 `undefined`，避免 TypeError
- **兜底文案**：`error.message || '请求失败...'` 网络异常时展示友好提示
- **场景区分**：网络断开、超时等异常没有 `response`，需与后端返回的错误区分处理

## 常见陷阱与最佳实践

### 1. 忘记 await 导致拿到 Promise

```ts
// 错误：缺少 await，data 是一个 Promise 对象而非数据
const fetchList = async () => {
  const data = request.get('/work-logs');  // 未加 await
  console.log(data);  // Promise { <pending> }
};

// 正确：加 await 后 data 才是真正的数据
const fetchList = async () => {
  const data = await request.get('/work-logs');
  console.log(data);
};
```

### 2. 响应拦截器返回类型不一致

```ts
// 错误：拦截器返回 res.data 后，业务层再次取 .data 得到 undefined
request.interceptors.response.use((response) => response.data);

const data = await request.get('/work-logs').data;  // undefined

// 正确：拦截器取过一次后，业务层直接使用返回值
request.interceptors.response.use((response) => response.data);

const data = await request.get('/work-logs');
```

### 3. 并发请求

```ts
// 错误：逐个 await，串行执行，耗时累加
const list1 = await request.get('/work-logs');
const list2 = await request.get('/users');

// 正确：使用 Promise.all 并发执行，同时返回结果
const [list1, list2] = await Promise.all([
  request.get('/work-logs'),
  request.get('/users')
]);
```

### 4. 错误处理遗漏

```ts
// 错误：遗漏 catch，请求失败时状态不更新，页面卡在加载中
const loadRecords = async () => {
  setLoading(true);
  const data = await request.get('/work-logs');  // 失败时抛出异常
  setRecords(data);
  setLoading(false);  // 永远不会执行
};

// 正确：try/catch/finally 覆盖正常与异常路径
const loadRecords = async () => {
  setLoading(true);
  try {
    const data = await request.get('/work-logs');
    setRecords(data);
  } catch (error) {
    alert('加载失败，请稍后重试');
  } finally {
    setLoading(false);
  }
};
```

### 最佳实践

1. **统一使用实例发起请求**，通过 `create` 配置 baseURL、timeout，避免散落配置
2. **拦截器负责公共逻辑**，token 附加、业务码判断、401 跳转统一在拦截器处理
3. **善用可选链与兜底文案**，网络异常时不崩溃，给用户友好提示
4. **并发请求用 Promise.all**，无关接口同时发起，减少等待时间
5. **请求失败必须重置 loading**，使用 `try/catch/finally` 保证状态一致
6. **token 保存在 localStorage** 并设置过期时间，登录失效时及时清除并跳转

## 总结

Axios 是 React 项目前后端数据交互的核心工具：

- **请求方法**：GET/POST/PUT/DELETE 对应查增改删，返回 Promise，配合 async/await
- **请求实例**：统一配置 baseURL 与 timeout，集中管理接口请求
- **拦截器**：请求拦截统一附加 token，响应拦截统一取数据与错误处理
- **健壮性**：可选链与兜底文案保证网络异常时不崩溃
- **最佳实践**：并发用 Promise.all，错误处理用 try/catch/finally
