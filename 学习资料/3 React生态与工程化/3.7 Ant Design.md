# Ant Design 详解：企业级 UI 组件库

---

## Ant Design 的定义

Ant Design（antd）是蚂蚁集团推出的企业级 React UI 组件库。它提供开箱即用的表格、表单、弹窗、提示等组件，并内置统一的视觉规范与交互模式，让开发者无需从零搭建 UI，即可快速构建风格一致、体验成熟的中后台系统。

**核心特点：**
- 组件丰富：覆盖表格、表单、弹窗、消息提示、导航布局等中后台常见场景
- 开箱即用：样式随组件打包，无需额外引入 CSS 文件即可直接使用
- 统一规范：遵循蚂蚁设计语言，保证视觉与交互体验的一致性

**官方文档链接：**
- [Ant Design 官方中文文档](https://ant.design/)

## Ant Design 基本用法

### 1. 引入与基础配置

先安装 antd 依赖（`npm install antd`），然后引入组件与全局样式。React 18 及以上推荐使用 `createRoot` 挂载：

```tsx
import { createRoot } from 'react-dom/client';
import { Button, ConfigProvider } from 'antd';
import zhCN from 'antd/locale/zh_CN';
import 'antd/dist/reset.css';

const root = createRoot(document.getElementById('root')!);

root.render(
  <ConfigProvider locale={zhCN}>
    <Button type="primary" onClick={() => alert('开始填报')}>
      新建填报
    </Button>
  </ConfigProvider>
);
```

- **组件引入**：`import { Button } from 'antd'` 按需引入组件，避免整包加载
- **样式引入**：`import 'antd/dist/reset.css'` 引入 antd 基础样式
- **ConfigProvider**：`<ConfigProvider locale={zhCN}>` 全局配置组件，设置中文语言包
- **Button 按钮**：`<Button type="primary">` 主按钮样式，`onClick` 绑定点击事件

### 2. 表格

Table 是工时填报后台的核心组件，通过 `columns` 描述列、`dataSource` 提供数据，配合 `pagination` 与 `loading` 实现完整列表页：

```tsx
import { Table, Tag } from 'antd';
import type { ColumnsType } from 'antd/es/table';

interface WorkLog {
  id: number;
  date: string;
  hours: number;
  project: string;
  status: 'pending' | 'approved' | 'rejected';
}

const columns: ColumnsType<WorkLog> = [
  { title: '日期', dataIndex: 'date', key: 'date' },
  { title: '项目', dataIndex: 'project', key: 'project' },
  { title: '工时', dataIndex: 'hours', key: 'hours', render: (v: number) => `${v} 小时` },
  {
    title: '状态',
    dataIndex: 'status',
    key: 'status',
    render: (s: WorkLog['status']) =>
      s === 'approved' ? <Tag color="green">已通过</Tag> : <Tag color="orange">待审批</Tag>,
  },
];

const data: WorkLog[] = [
  { id: 1, date: '2026-08-01', hours: 8, project: '中台重构', status: 'pending' },
  { id: 2, date: '2026-08-02', hours: 7, project: '数据看板', status: 'approved' },
];

function WorkLogTable() {
  return (
    <Table<WorkLog>
      rowKey="id"
      columns={columns}
      dataSource={data}
      loading={false}
      pagination={{ pageSize: 10, showTotal: (t) => `共 ${t} 条` }}
    />
  );
}
```

- **数据源**：`dataSource={data}` 传入数组数据，每条记录对应一行
- **列配置**：`columns` 中 `title` 是表头，`dataIndex` 是数据字段，`key` 是列唯一标识
- **列渲染**：`render` 自定义单元格内容，例如把工时渲染为 `8 小时`、把状态渲染为 Tag
- **rowKey**：`rowKey="id"` 指定每行的唯一标识，避免 React 警告并保证更新性能
- **分页**：`pagination={{ pageSize: 10 }}` 每页条数，`showTotal` 显示总数
- **加载状态**：`loading={loading}` 请求数据期间显示表格骨架屏

### 3. 表单与弹窗

Form 通过 `Form.Item` 配置字段与校验规则，Modal 内嵌表单用于新增/编辑用户。

#### 3.1 表单提交：onFinish 模式

`Form` 的 `onFinish` 属性在表单校验通过后自动触发，是声明式表单提交的首选方式。与手动 `validateFields()` 不同，`onFinish` 由表单驱动，校验通过后才执行回调。

```tsx
import { Button, Form, Input, message } from 'antd';

interface LoginForm {
  username: string;
  password: string;
}

function LoginFormDemo() {
  const [form] = Form.useForm<LoginForm>();

  const handleSubmit = async (values: LoginForm) => {
    // values 已通过校验，类型安全
    message.success(`登录成功：${values.username}`);
    form.resetFields();
  };

  const handleReset = () => {
    form.resetFields();
  };

  return (
    <Form form={form} layout="vertical" onFinish={handleSubmit} onFinishFailed={() => message.error('请检查表单填写')}>
      <Form.Item
        name="username"
        label="用户名"
        rules={[{ required: true, message: '请输入用户名' }]}
      >
        <Input placeholder="请输入用户名" />
      </Form.Item>
      <Form.Item
        name="password"
        label="密码"
        rules={[{ required: true, message: '请输入密码' }]}
      >
        <Input.Password placeholder="请输入密码" />
      </Form.Item>
      <Form.Item>
        <Button type="primary" htmlType="submit" block>
          登录
        </Button>
        <Button onClick={handleReset} block style={{ marginTop: 8 }}>
          重置
        </Button>
      </Form.Item>
    </Form>
  );
}
```

- **`onFinish`**：校验通过后自动触发，回调参数 `values` 已通过校验，类型由 `Form.useForm<T>()` 泛型推导
- **`onFinishFailed`**：校验失败时触发，可在此显示全局错误提示
- **`htmlType="submit"`**：按钮必须设置 `htmlType="submit"` 才能触发表单提交，否则 `onFinish` 不会执行
- **`Form.useForm<T>()`**：泛型 `T` 定义表单字段类型，`values` 参数自动获得类型提示
- **`form.resetFields()`**：清空所有字段值并恢复初始状态

### 3.2 表单提交：validateFields 模式

手动调用 `form.validateFields()` 校验表单，适用于 Modal 内嵌表单、动态表单等需要手动控制校验时机的场景。

```tsx
import { Button, Form, Input, Modal, Select, message } from 'antd';
import { useState } from 'react';

interface UserForm {
  name: string;
  role: string;
}

function UserModal() {
  const [form] = Form.useForm<UserForm>();
  const [open, setOpen] = useState(false);

  const handleSubmit = async () => {
    const values = await form.validateFields();
    message.success(`已保存用户：${values.name}`);
    setOpen(false);
  };

  return (
    <>
      <Button type="primary" onClick={() => setOpen(true)}>
        新增用户
      </Button>
      <Modal
        title="新增用户"
        open={open}
        onOk={handleSubmit}
        onCancel={() => setOpen(false)}
        destroyOnClose
      >
        <Form form={form} layout="vertical">
          <Form.Item
            name="name"
            label="姓名"
            rules={[{ required: true, message: '请输入姓名' }]}
          >
            <Input placeholder="请输入姓名" />
          </Form.Item>
          <Form.Item
            name="role"
            label="角色"
            rules={[{ required: true, message: '请选择角色' }]}
          >
            <Select
              options={[
                { value: 'admin', label: '管理员' },
                { value: 'member', label: '普通成员' },
              ]}
            />
          </Form.Item>
        </Form>
      </Modal>
    </>
  );
}
```

- **表单实例**：`Form.useForm()` 创建表单实例，用于校验、取值、重置
- **字段绑定**：`Form.Item` 的 `name` 对应字段名，子组件自动接入受控 value 与 onChange
- **校验规则**：`rules={[{ required: true, message: '请输入姓名' }]}` 必填校验，不通过时提示
- **校验执行**：`form.validateFields()` 校验全部字段，返回通过后的值对象
- **Modal 受控**：`open` 控制弹窗显示，`onOk`/`onCancel` 处理确定与取消
- **弹窗表单**：编辑场景先 `form.setFieldsValue(record)` 回填，再打开弹窗

**`onFinish` vs `validateFields()` 对比：**

| 维度 | `onFinish` | `validateFields()` |
|------|-----------|-------------------|
| 触发方式 | 表单自动触发（点击 submit 按钮） | 手动调用 |
| 校验失败 | 执行 `onFinishFailed` | 返回 rejected Promise |
| 取值方式 | 回调参数直接传入 values | 需要 await 返回值 |
| 适用场景 | 查询表单、登录表单等完整表单 | Modal 内嵌表单、动态表单 |
| 灵活性 | 较低，绑定在 Form 上 | 较高，可在任意时机调用 |

**两种模式可以共存：**

```tsx
// Modal 中使用 validateFields 模式
<Modal
  open={open}
  onOk={async () => {
    try {
      const values = await form.validateFields();
      await saveApi(values);
      setOpen(false);
    } catch {
      message.error('请检查表单填写');
    }
  }}
  onCancel={() => setOpen(false)}
>
  <Form form={form}>
    {/* ... */}
  </Form>
</Modal>

// 独立查询表单使用 onFinish 模式
<Form form={form} onFinish={handleQuery}>
  <Form.Item name="keyword" label="关键词">
    <Input />
  </Form.Item>
  <Button htmlType="submit" type="primary">查询</Button>
</Form>
```

### 4. 状态标签与确认操作

Tag 用于展示审批状态等枚举信息，Popconfirm 在删除/驳回等危险操作前提供二次确认：

```tsx
import { Button, Popconfirm, Tag, message } from 'antd';
import type { ColumnsType } from 'antd/es/table';

interface WorkLog {
  id: number;
  date: string;
  status: 'pending' | 'approved' | 'rejected';
}

const statusColor = { pending: 'orange', approved: 'green', rejected: 'red' } as const;
const statusText = { pending: '待审批', approved: '已通过', rejected: '已驳回' } as const;

const handleDelete = async (id: number) => {
  message.loading('正在删除...', 0.5);
  message.success(`已删除记录 ${id}`);
};

const columns: ColumnsType<WorkLog> = [
  { title: '日期', dataIndex: 'date', key: 'date' },
  {
    title: '状态',
    dataIndex: 'status',
    key: 'status',
    render: (s: WorkLog['status']) => <Tag color={statusColor[s]}>{statusText[s]}</Tag>,
  },
  {
    title: '操作',
    key: 'action',
    render: (_: unknown, record: WorkLog) => (
      <Popconfirm
        title="确定删除该条工时记录？"
        okText="删除"
        cancelText="取消"
        onConfirm={() => handleDelete(record.id)}
      >
        <Button danger size="small">
          删除
        </Button>
      </Popconfirm>
    ),
  },
];

function ActionList() {
  const data: WorkLog[] = [
    { id: 1, date: '2026-08-01', status: 'pending' },
    { id: 2, date: '2026-08-02', status: 'approved' },
  ];
  return <table>{/* 实际项目中使用 antd Table 渲染 columns */}</table>;
}
```

- **状态标签**：`<Tag color={statusColor[s]}>` 通过映射对象把状态值转为对应颜色与文案
- **危险按钮**：`<Button danger>` 红色危险样式，用于删除等破坏性操作
- **气泡确认**：`<Popconfirm onConfirm={...}>` 包裹触发元素，点击弹出确认气泡
- **确认回调**：`onConfirm` 在用户点击"删除"后执行，未确认则不会触发

### 5. 操作反馈

message 提供全局的消息提示，用于反馈新增、删除、提交等操作的执行结果：

```tsx
import { Button, message } from 'antd';

const handleSave = async () => {
  message.loading({ content: '正在保存...', key: 'save' });

  try {
    // 模拟请求接口
    await new Promise((resolve) => setTimeout(resolve, 1000));
    message.success({ content: '保存成功', key: 'save' });
  } catch (error) {
    message.error({ content: '保存失败，请重试', key: 'save' });
  }
};

function FeedbackDemo() {
  return (
    <Button type="primary" onClick={handleSave}>
      保存填报
    </Button>
  );
}
```

- **成功提示**：`message.success('保存成功')` 顶部弹出成功提示，自动消失
- **加载提示**：`message.loading('正在保存...')` 显示加载状态，操作完成后可替换
- **错误提示**：`message.error('保存失败')` 提示失败信息，配合 try/catch 使用
- **唯一 key**：`key: 'save'` 让同一 key 的消息互相替换，避免重复弹层

## 常见陷阱与最佳实践

### 1. Table 缺少 rowKey 导致警告

未指定 `rowKey` 时，React 会使用行索引作为 key，控制台报 key 警告，且数据变更时可能出现渲染错乱：

```tsx
// 错误：未指定 rowKey，产生控制台警告，行复用错误
<Table columns={columns} dataSource={data} />

// 正确：指定数据中唯一的 id 字段
<Table rowKey="id" columns={columns} dataSource={data} />

// 正确：数据字段名不是 id 时，用函数返回唯一值
<Table rowKey={(record) => record.workLogId} columns={columns} dataSource={data} />
```

### 2. Form 校验规则与受控 value

Form.Item 子组件依赖表单的受控 value，混用手动受控写法会破坏校验与取值：

```tsx
// 错误：手动绑定 value，表单实例无法获取与校验该字段
<Form.Item name="name" rules={[{ required: true }]}>
  <Input value={manualValue} onChange={handleChange} />
</Form.Item>

// 正确：只写 name，让 Form 管理受控状态
<Form.Item name="name" rules={[{ required: true }]}>
  <Input />
</Form.Item>
```

### 3. Modal 关闭后表单残留

复用同一个 Modal 打开下一条数据时，上次的填写内容会残留在表单中：

```tsx
// 错误：关闭后重新打开，表单仍是上一次的值
<Modal open={open} onOk={handleOk} onCancel={handleCancel}>
  <Form form={form}>...</Form>
</Modal>

// 正确：destroyOnClose 在关闭时销毁内部 DOM，重新打开时表单被重置
<Modal open={open} onOk={handleOk} onCancel={handleCancel} destroyOnClose>
  <Form form={form}>...</Form>
</Modal>

// 正确：编辑前手动回填，新增时清空
const openModal = (record?: UserForm) => {
  record ? form.setFieldsValue(record) : form.resetFields();
  setOpen(true);
};
```

### 4. 操作列 key 缺失

只渲染列内容而忘记给列设置 `key`，antd 会报警告；操作列常依赖 `dataIndex`，此时必须显式指定 `key`：

```tsx
// 错误：操作列没有 dataIndex 也没有 key，产生警告
{ title: '操作', render: () => <Button>编辑</Button> },

// 正确：为无 dataIndex 的列显式提供 key
{ title: '操作', key: 'action', render: () => <Button>编辑</Button> },
```

### 最佳实践

1. **统一使用 `rowKey` 指定唯一字段**，避免表格 key 警告与行复用错误
2. **Form.Item 内子组件只写 `name`**，不手动绑定 value，让表单实例管理受控状态
3. **弹窗表单开启 `destroyOnClose`** 或编辑前显式 `setFieldsValue`/`resetFields`
4. **表单提交先 `form.validateFields()`** 再发请求，由 rules 统一做前端校验
5. **异步操作配合 loading 状态**，用 `message.loading` 与 `finally` 中结束 loading
6. **枚举状态用映射对象驱动 Tag 颜色与文案**，避免 render 中散落魔法字符串

## 总结

Ant Design 是构建企业级中后台系统的首选 UI 组件库：

- **组件**：表格、表单、弹窗、标签、消息提示等开箱即用，覆盖典型业务场景
- **表单**：Form.Item 通过 rules 实现声明式校验，validateFields 统一取值
- **表格**：columns 声明式配置 + rowKey + pagination + loading，快速搭建列表页
- **交互**：Tag 状态可视化、Popconfirm 危险操作确认、message 全局反馈
- **规范**：ConfigProvider 配置语言与主题，保证全局视觉交互一致性
