# React Router 详解：路由配置与页面导航

---

## React Router 的定义

React Router 是 React 生态中最主流的路由库，用于实现单页应用（SPA）的页面切换。它根据 URL 的变化渲染对应的组件，无需刷新浏览器即可完成页面导航，同时支持嵌套路由、动态参数、路由守卫等高级能力。

**核心特点：**
- 声明式路由配置，将路径与页面组件一一映射
- 基于 URL 驱动，与浏览器历史记录深度集成（前进、后退、收藏）
- 支持嵌套路由、动态参数、编程式导航等丰富的路由场景

**官方文档链接：**
- [React Router 官网](https://reactrouter.com)
- [React Router 中文教程](https://reactrouter.com/tutorials)

## React Router 版本差异（v5 → v6 → v7）

React Router 目前主流的三大版本差异较大，理解版本差异有助于阅读旧代码与迁移。本教程代码基于 v6/v7 语法（`Routes`、`Route`、`Outlet`、`useNavigate`）。

### v5 → v6（破坏性变更，迁移成本大）

| 方面 | v5 | v6 |
|------|----|----|
| 路由容器 | `<Switch>` | `<Routes>` |
| 组件写法 | `<Route path="/" component={Home} />` 或 `render` | `<Route path="/" element={<Home />} />` |
| 精确匹配 | 需要手动加 `exact` | 默认精确匹配，`exact` 已删除 |
| 编程式导航 | `useHistory()` → `history.push('/x')` | `useNavigate()` → `navigate('/x')` |
| 重定向 | `<Redirect to="/x" />` | `<Navigate to="/x" replace />` |
| 嵌套路由 | `<Route>` 内直接嵌套子组件，用 `props.children` 渲染 | 子 `<Route>` 嵌套 + 父组件渲染 `<Outlet />` |
| 动态参数 | `useParams()`（未变） | `useParams()`（未变） |

- **`Switch` → `Routes`**：`Routes` 按「路由排名」自动选择最优匹配，不再依赖声明顺序
- **`exact` 删除**：v6 默认精确匹配，`/` 不再匹配 `/timesheet` 这类子路径
- **`useHistory` → `useNavigate`**：API 更简洁，`navigate('/x')` 一行即可
- **`Redirect` → `Navigate`**：v6 的 `Navigate` 是组件式声明，常配合路由守卫使用
- **嵌套方式变化**：v5 靠组件 children 传递子路由，v6 改为 `Outlet` 占位符，布局复用更清晰

### v6 → v7（基本兼容，迁移成本小）

| 方面 | v6 | v7 |
|------|----|----|
| 包名 | `react-router-dom` / `react-router-native` 等分拆 | 合并为统一 `react-router` 包 |
| 声明式模式 | `BrowserRouter` + `Routes` + `Route` | 仍然可用（v6 写法直接迁移） |
| 数据路由 | 无（需自行 fetch） | 新增 `createBrowserRouter` + `RouterProvider` + `loader` / `action` |
| 新 Hook | 基础 hooks | 新增 `useLoaderData`、`useActionData`、`useRouteError` 等 |

- **包合并**：v7 将 `react-router-dom` 等功能并入 `react-router`，官方推荐直接使用 `react-router`；项目里继续用 `react-router-dom` 也完全兼容（作为别名）
- **数据模式（v7 最大新增）**：`createBrowserRouter` 允许在路由配置中声明数据加载（`loader`）与提交（`action`），类似 Remix 的写法，减少手写 useEffect 拉数据
- **声明式模式仍保留**：本教程使用的 `BrowserRouter` + `Routes` 写法在 v7 依旧可用，v6 代码几乎无需改动即可升级

### 迁移建议

- **v5 项目**：升级到 v6/v7 需全面改写路由配置、导航与嵌套写法，建议按官方迁移指南逐项替换
- **v6 项目**：升级到 v7 成本很低，只需确认包引入方式与可选的 data 模式，现有代码基本可原样运行
- **新项目**：直接使用 v7（如当前工时填报项目使用 `react-router-dom@^7.18.1`），声明式写法足够覆盖第 1 周需求

## 前置准备：安装 React Router

在开始编写路由代码前，先安装依赖。项目基于 Vite + React + TypeScript 脚手架创建：

```bash
npm install react-router-dom
```

- **安装命令**：`npm install` 将最新版（v7）写入 `package.json` 的 `dependencies` 并下载到 `node_modules`
- **包名选择**：v7 已将功能合并进 `react-router`，官方推荐 `npm install react-router`；项目沿用 `react-router-dom` 也完全兼容（作为别名，导出的 API 一致）
- **版本锁定**：安装后 `package.json` 显示如 `"react-router-dom": "^7.18.1"`，`^` 表示可升级到同大版本内最新小版本
- **验证安装**：`package.json` 的 `dependencies` 中出现 `react-router-dom`，即可在代码中 `import { BrowserRouter } from 'react-router-dom'`

安装完成后，下面的示例代码即可直接运行。

## React Router 基本用法

下面以一个"工时填报后台管理系统"为例，演示路由配置、页面导航、布局复用、动态参数与路由守卫的完整用法。

### 1. 基础路由配置

首先在应用入口配置路由，将不同的 URL 路径映射到对应的页面组件：

```tsx
import { BrowserRouter, Routes, Route } from 'react-router-dom';
import Login from './pages/Login';
import WorkTimeList from './pages/WorkTimeList';
import WorkTimeDetail from './pages/WorkTimeDetail';
import NotFound from './pages/NotFound';

function App() {
  return (
    <BrowserRouter>
      <Routes>
        <Route path="/login" element={<Login />} />
        <Route path="/work-time" element={<WorkTimeList />} />
        <Route path="/work-time/:id" element={<WorkTimeDetail />} />
        <Route path="*" element={<NotFound />} />
      </Routes>
    </BrowserRouter>
  );
}
```

- **浏览器路由容器**：`<BrowserRouter>` 基于 HTML5 History API 管理 URL，是路由的最外层容器，必须包裹所有路由配置
- **路由容器**：`<Routes>` 是路由配置的容器，负责匹配当前路径并渲染对应的页面
- **路径与页面的映射**：`<Route path="/login" element={<Login />} />` 将路径与页面组件一一对应
- **通配符 404**：`<Route path="*" element={<NotFound />} />` 匹配所有未定义的路径，渲染 404 页面

### 2. 声明式导航与编程式导航

页面之间的跳转有两种方式：`Link` 组件声明式跳转，以及 `useNavigate` 编程式跳转：

```tsx
import { Link, useNavigate, useLocation } from 'react-router-dom';

function Header() {
  const navigate = useNavigate();
  const location = useLocation();

  return (
    <div>
      <Link to="/work-time">工时列表</Link>
      <Link to="/login">登录</Link>
      <button onClick={() => navigate('/work-time/1001')}>查看详情</button>
      <p>当前路径：{location.pathname}</p>
    </div>
  );
}
```

- **声明式导航**：`<Link to="/work-time">` 渲染为 `<a>` 标签，点击后跳转且不刷新页面
- **编程式导航**：`navigate('/work-time/1001')` 在事件处理等逻辑中主动触发跳转
- **导航函数**：`useNavigate()` 返回的 navigate 函数，支持字符串、路径对象或相对路径
- **获取当前路径**：`useLocation()` 返回的 `location.pathname` 读取当前 URL 路径

### 3. 嵌套路由与布局页

嵌套路由让「布局组件只渲染一次、子页面复用它」成为可能。它需要**布局组件**和**路由表**两部分配合完成，下面分三步逐步搭建。

**① 布局组件：作为父路由的页面，只负责公共框架**

```tsx
import { Outlet } from 'react-router-dom';

function Layout() {
  return (
    <div>
      <header>工时填报后台管理系统</header>
      <nav>导航菜单</nav>
      <main>
        <Outlet />
      </main>
      <footer>版本 1.0.0</footer>
    </div>
  );
}
```

- `<Outlet />` 是子路由的「插槽」，命中哪个子路由，哪个页面就渲染在这个位置

**② 子页面组件：只写页面自己的内容，不重复公共框架**

```tsx
function WorkTimeList() {
  return <h2>我的工时列表</h2>;
}

function WorkTimeDetail() {
  return <h2>工时详情</h2>;
}
```

**③ 路由表：把 ①② 的组件和路径对应起来**

```tsx
import { BrowserRouter, Routes, Route } from 'react-router-dom';

function App() {
  return (
    <BrowserRouter>
      <Routes>
        <Route path="/" element={<Layout />}>
          <Route index element={<WorkTimeList />} />
          <Route path="work-time/:id" element={<WorkTimeDetail />} />
        </Route>
      </Routes>
    </BrowserRouter>
  );
}
```

三个代码块的关系：

- **① ↔ ③**：路由表里父路由的 `element={<Layout />}` 指向 ① 的 `Layout` —— 只要 URL 以 `/` 开头，就先渲染 `Layout`，公共框架出现；框架里 `<Outlet />` 的位置由 ③ 的子路由决定
- **② ↔ ③**：路由表里子 `<Route>` 的 `element` 指向 ② 的组件 —— 该路径命中时，对应组件被渲染进 ① 的 `<Outlet />`
- **子路由匹配**：访问 `/` 时 `index` 命中，`<Outlet />` 显示 `WorkTimeList`；访问 `/work-time/1` 时 `work-time/:id` 命中，`<Outlet />` 换成 `WorkTimeDetail`，`Layout` 框架保持不动
- **嵌套结构**：子 `<Route>` 写在父 `<Route>` 的 JSX 内部，形成树状结构，层级关系即 URL 层级关系
- **路径拼接**：子路由的 `path` 不加 `/` 前缀，`work-time/:id` 基于父路径 `/` 自动变成 `/work-time/:id`
- **缺一不可**：父路由必须有子路由，且父组件必须渲染 `<Outlet />`，否则子页面不会显示

### 4. 动态路由参数

动态路由参数让同一个组件根据 URL 中的变量渲染不同内容，例如按工单编号查看工时详情：

```tsx
import { useParams } from 'react-router-dom';

function WorkTimeDetail() {
  const { id } = useParams();

  return (
    <div>
      <h2>工时详情</h2>
      <p>当前工单编号：{id}</p>
    </div>
  );
}
```

路由配置中对应的映射——动态参数路由同样支持嵌套声明，`:id` 可作为父路由的子路由：

```tsx
<Route path="/work-time" element={<Layout />}>
  <Route index element={<WorkTimeList />} />
  <Route path=":id" element={<WorkTimeDetail />} />
</Route>
```

- **嵌套声明**：`:id` 是父路由 `/work-time` 的子路由，`path` 不加 `/` 前缀，最终匹配 `/work-time/:id`
- **URL 变量标识**：`path=":id"` 中的 `:id` 是动态段，匹配该位置的任意值
- **读取动态参数**：`useParams()` 返回 `{ id }` 对象，组件从中读取 URL 中的变量值

### 5. 路由守卫

路由守卫用于权限控制：未登录的用户访问受保护页面时，跳转到登录页，登录成功后返回原页面：

```tsx
import { Navigate, useLocation } from 'react-router-dom';
import { isLoggedIn } from './utils/auth';

function RequireAuth({ children }: { children: React.ReactNode }) {
  const location = useLocation();

  if (!isLoggedIn()) {
    return <Navigate to="/login" state={{ from: location.pathname }} replace />;
  }

  return <>{children}</>;
}
```

登录页中读取来源路径，登录成功后返回原页面：

```tsx
import { useNavigate, useLocation } from 'react-router-dom';
import { login } from './utils/auth';

function Login() {
  const navigate = useNavigate();
  const location = useLocation();

  const handleLogin = async () => {
    await login();
    const from = location.state?.from || '/';
    navigate(from, { replace: true });
  };

  return <button onClick={handleLogin}>登录</button>;
}
```

在路由配置中使用守卫包装受保护页面：

```tsx
<Route
  path="/"
  element={
    <RequireAuth>
      <Layout />
    </RequireAuth>
  }
/>
```

- **未登录跳转登录页**：`<Navigate to="/login" replace />` 未登录时重定向到登录页
- **携带来源路径**：`state={{ from: location.pathname }}` 记录原始页面路径传给登录页
- **登录后返回原页面**：`navigate(from, { replace: true })` 登录成功后跳回来源页面
- **路由守卫**：`RequireAuth` 包装组件统一校验登录态，未登录就拦截并重定向

## 常见陷阱与最佳实践

### 1. 导航函数传参写法

```tsx
// 正确：直接传字符串
navigate('/work-time/1001');

// 正确：模板字符串拼接动态参数
navigate(`/work-time/${id}`);

// 错误：navigate 不接受 Link 组件的对象写法
navigate({ to: '/work-time/1001' });

// 正确：对象形式传入路径名
navigate({ pathname: '/work-time/1001' });
```

- **字符串参数**：`navigate('/work-time/1001')` 传入完整路径字符串
- **模板字符串**：`navigate(`/work-time/${id}`)` 拼接动态参数
- **对象参数**：`navigate({ pathname: '/work-time/1001' })` 传入路径对象

### 2. 通配符路径必须放在结尾

```tsx
// 错误：通配符放在前面会拦截所有正常路由
<Routes>
  <Route path="*" element={<NotFound />} />
  <Route path="/login" element={<Login />} />
</Routes>

// 正确：通配符放在所有路由之后
<Routes>
  <Route path="/login" element={<Login />} />
  <Route path="*" element={<NotFound />} />
</Routes>
```

- **通配符拦截**：`path="*"` 匹配任意路径，放前面会使后续路由永远无法命中
- **结尾规则**：404 路由必须声明在所有正常路由之后

### 3. state 携带数据与 URL 传参

```tsx
// 正确：使用 navigate 的第二个参数携带数据
navigate('/work-time/detail', { state: { id: '1001', name: '张三' } });

// 读取时使用 useLocation
const location = useLocation();
console.log(location.state?.name);

// 错误：把对象直接拼进 URL 字符串
navigate(`/work-time/detail?data=${JSON.stringify({ id: '1001' })}`);
```

- **state 携带数据**：`navigate(path, { state: {...} })` 在页面间传递对象，不会出现在 URL 中
- **读取 state**：`location.state` 读取跳转时携带的数据
- **错误写法**：对象拼进 URL 需要序列化且易出错，复杂数据应使用 state

### 4. replace 与普通跳转的区别

```tsx
// 普通跳转：新增一条历史记录，可点击浏览器返回回到上一页
navigate('/work-time');

// replace 跳转：替换当前历史记录，不能返回上一页
navigate('/login', { replace: true });
```

- **普通跳转**：`navigate('/work-time')` 保留历史记录，返回键可回到上一页
- **replace 跳转**：`{ replace: true }` 替换当前记录，常用于登录成功后避免返回登录页

### 5. 最佳实践

1. **通配符 404 路由放在所有路由之后**，避免拦截正常路由
2. **动态参数使用 `:param` 命名**，并与 `useParams()` 读取的键保持一致
3. **路由守卫用 `state` 记录来源路径**，登录成功后返回原页面
4. **编程式导航统一使用 `navigate`**，避免 `<a href>` 导致整页刷新
5. **复杂应用使用 `createBrowserRouter` 对象式配置**，便于按模块拆分路由
6. **路由与组件解耦**，页面组件通过 hooks 读取路由信息，不直接拼接 URL

---

## 总结

React Router 是 React 单页应用路由与导航的核心方案：

- **路由配置**：`BrowserRouter` + `Routes` + `Route` 将路径映射到页面组件，通配符处理 404
- **导航方式**：`Link` 声明式导航与 `navigate` 编程式导航，配合 `useLocation` 获取路径
- **布局复用**：嵌套路由配合 `Outlet` 占位符实现公共布局
- **参数传递**：`useParams` 读取动态路由参数，`state` 在页面间传递数据
- **权限控制**：路由守卫组件统一拦截未登录访问，登录后返回原页面
