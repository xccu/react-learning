# Vite 详解：开发服务器与打包构建

---

## Vite 的定义

Vite 是新一代前端构建工具，其开发服务器基于浏览器原生 ES 模块（ESM），启动时无需打包，服务器即时返回源码，因此冷启动极快；生产构建则基于 Rollup 进行优化打包。开发环境下 Vite 使用 esbuild 预构建依赖，配合原生 ESM 实现毫秒级的热更新（HMR），让"工时填报后台管理系统"这类业务在开发与构建之间切换时体验一致、效率更高。

**核心特点：**
- 开发环境基于原生 ES 模块，按需编译，启动速度远超传统打包器
- 热更新（HMR）即时生效，修改代码后无需刷新页面即可看到变化
- 开箱即用的配置与插件生态，原生支持 TypeScript、JSX、CSS 预处理器

**官方文档链接：**
- [Vite 官方文档（中文）](https://cn.vitejs.dev/)
- [Vite 官方文档（英文）](https://vite.dev/)

## Vite 基本用法

### 1. 创建项目与目录结构

使用脚手架命令创建 Vite + React + TypeScript 项目：

```bash
npm create vite@latest work-time-system -- --template react-ts
```

创建完成后，项目的核心目录结构如下：

```
work-time-system/
├── index.html              # 入口 HTML，位于项目根目录
├── package.json            # 项目依赖与脚本配置
├── vite.config.ts          # Vite 配置文件
├── tsconfig.json           # TypeScript 配置文件
└── src/                    # 业务源码目录
    ├── main.tsx            # React 应用入口文件
    ├── App.tsx             # 根组件
    ├── api/                # 接口请求封装
    ├── pages/              # 页面组件
    ├── components/         # 公共组件
    └── vite-env.d.ts       # Vite 类型声明文件
```

- **脚手架命令**：`npm create vite@latest` 通过交互式命令创建项目，`--template react-ts` 指定 React + TypeScript 模板
- **入口 HTML**：`index.html` 位于项目根目录而非 `public` 下，这是 Vite 与传统脚手架的区别
- **入口文件**：`src/main.tsx` 负责挂载 React 应用，`index.html` 通过 `<script type="module" src="/src/main.tsx">` 引用它
- **业务目录**：`src/` 下按 `api`、`pages`、`components` 组织"工时填报后台管理系统"的模块代码

### 2. 开发服务器与热更新

```bash
npm install        # 安装依赖
npm run dev        # 启动开发服务器
```

启动后终端会显示本地访问地址，默认是 `http://localhost:5173`：

- **安装依赖**：`npm install` 根据 `package.json` 安装项目全部依赖
- **启动命令**：`npm run dev` 启动开发服务器，默认端口 5173
- **热更新**：修改 `src` 下的任意文件，浏览器无需刷新即可实时更新
- **按需编译**：Vite 只对当前访问页面涉及的模块进行编译，因此项目再大启动也很快

### 3. 常用配置：路径别名与开发代理

在 `vite.config.ts` 中配置路径别名和接口代理：

```ts
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import { fileURLToPath, URL } from 'node:url';

export default defineConfig({
  plugins: [react()],
  resolve: {
    alias: {
      '@': fileURLToPath(new URL('./src', import.meta.url))
    }
  },
  server: {
    port: 5173,
    proxy: {
      '/api': {
        target: 'http://localhost:8080',
        changeOrigin: true
      }
    }
  }
});
```

- **路径别名**：`'@': fileURLToPath(...)` 将 `@` 映射到 `src` 目录，`import api from '@/api/workTime'` 替代冗长的相对路径
- **开发端口**：`server.port` 指定开发服务器端口，方便固定访问地址
- **接口代理**：`server.proxy` 将 `/api` 开头的请求转发到 `http://localhost:8080`，前端统一使用 `/api/workTime/submit` 形式请求
- **changeOrigin**：`changeOrigin: true` 修改请求头中的 Host，避免后端接口鉴权拦截

别名配置好后，引入模块可以这样写：

```ts
import { submitWorkTime } from '@/api/workTime';
import WorkTimeForm from '@/components/WorkTimeForm';
```

### 4. 环境变量

在项目根目录创建环境变量文件：

```bash
# .env.development    开发环境
VITE_API_BASE_URL=/api

# .env.production     生产环境
VITE_API_BASE_URL=https://work-time.example.com/api
```

在代码中通过 `import.meta.env` 读取：

```ts
const apiBase = import.meta.env.VITE_API_BASE_URL;

export function getWorkTimeList() {
  return fetch(`${apiBase}/workTime/list`);
}
```

- **环境文件**：`.env.development` 在开发环境生效，`.env.production` 在构建时生效
- **变量前缀**：只有以 `VITE_` 开头的变量才会暴露给客户端代码
- **读取方式**：`import.meta.env.VITE_API_BASE_URL` 在源码中读取配置值
- **按环境生效**：同一份代码在 `npm run dev` 时请求 `/api`，构建后请求线上完整地址，无需手动修改

### 5. 生产构建

```bash
npm run build            # 构建生产包
npm run preview          # 本地预览构建产物
```

构建完成后，`dist` 目录下会生成经过压缩和优化的静态文件：

- **构建命令**：`npm run build` 调用 Rollup 对项目进行生产打包
- **预览命令**：`npm run preview` 在本地起一个服务，验证构建产物是否符合预期
- **代码分割**：Vite 默认把 React 等第三方依赖拆分成单独文件，配合浏览器缓存，业务代码更新时第三方库无需重新下载

手动配置代码分割，把 `react` 相关库独立打包：

```ts
import { defineConfig } from 'vite';

export default defineConfig({
  build: {
    rollupOptions: {
      output: {
        manualChunks: {
          react: ['react', 'react-dom'],
          antd: ['antd']
        }
      }
    }
  }
});
```

- **manualChunks**：将 `react`、`react-dom` 拆成 `react` 包，将 `antd` 拆成 `antd` 包
- **独立分包**：第三方库体积大且不常变更，单独分包后利用浏览器缓存，页面加载更快

## 常见陷阱与最佳实践

### 1. 路径别名缺少 TypeScript 配置

`vite.config.ts` 中配置了 `@` 别名，但 `tsconfig.json` 未同步配置，编辑器与类型检查会报错：

```json
// tsconfig.json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["src/*"]
    }
  }
}
```

```ts
// 正确：配置后即可正常使用
import { submitWorkTime } from '@/api/workTime';

// 错误：只配 vite.config.ts 不配 tsconfig.json，编辑器报"找不到模块"
```

- **双重配置**：路径别名需要同时配置 `vite.config.ts` 与 `tsconfig.json`，前者负责打包解析，后者负责类型检查
- **配置一致**：`@/*` 与 `src/*` 的映射必须与 vite 配置保持一致，否则会出现"运行正常、编辑器报错"的割裂现象

### 2. 静态资源路径问题

使用绝对路径 `/` 引用资源，构建后部署到子目录会找不到文件：

```ts
// 错误：部署到子域名或二级目录时资源 404
// index.html 中 <link href="/assets/style.css">

// 正确：基于环境配置基础路径
// vite.config.ts
export default defineConfig({
  base: '/work-time/'   // 部署在 https://example.com/work-time/ 下
});

// 正确：用相对路径引用，或统一使用 import 引入资源
import logo from './assets/logo.png';
```

- **base 配置**：`base` 指定构建产物的基础路径，部署在子目录时必须配置
- **import 引入**：通过 `import` 引入资源交给 Vite 处理，路径由打包器自动生成，避免写死

### 3. 环境变量命名必须以 VITE_ 开头

普通命名的变量在源码中读取不到，且没有报错提示：

```bash
# .env 文件中：
# 错误：没有 VITE_ 前缀，代码中读不到
API_BASE_URL=/api

# 正确：加上 VITE_ 前缀才能暴露给客户端
VITE_API_BASE_URL=/api
```

```ts
console.log(import.meta.env.API_BASE_URL);      // undefined
console.log(import.meta.env.VITE_API_BASE_URL); // /api
```

- **前缀规则**：`import.meta.env` 只暴露以 `VITE_` 开头的变量，其他变量仅存在于构建环境
- **避免敏感信息**：`VITE_` 变量会打包进客户端代码，密钥等敏感配置绝不能以 `VITE_` 开头存放

### 4. 构建后接口地址不一致

开发环境通过代理访问 `/api`，构建后没有代理，请求会 404：

```ts
// 错误：开发代理生效，但构建后 /api 请求打到静态服务器上，报 404
fetch('/api/workTime/submit');

// 正确：结合环境变量，构建后走完整线上地址
const apiBase = import.meta.env.VITE_API_BASE_URL;
fetch(`${apiBase}/workTime/submit`);
```

- **代理仅限开发**：`server.proxy` 只在 `npm run dev` 时生效，生产环境由 Nginx 等反向代理或环境变量指定地址
- **环境区分**：通过 `.env.development` 与 `.env.production` 分别配置接口地址，构建时自动切换

### 5. 最佳实践

1. **使用官方脚手架创建项目**，`npm create vite@latest` 自动生成最佳实践的默认配置
2. **路径别名统一使用 `@` 指向 `src`**，并在 `tsconfig.json` 中同步配置，避免长相对路径
3. **接口地址一律通过环境变量管理**，开发用代理、生产用完整域名，代码中不写死 URL
4. **第三方库单独分包**，利用浏览器缓存减少重复下载
5. **生产构建前用 `npm run preview` 预览**，确认静态资源路径与接口地址正确
6. **不要把密钥写入 `VITE_` 开头的环境变量**，暴露到客户端就是泄露

## 总结

Vite 是 React 生态中最主流的构建工具之一，为"工时填报后台管理系统"这类项目的开发与上线提供了完整的工具链：

- **开发体验**：基于原生 ESM，秒级启动与即时热更新，显著提升开发效率
- **构建能力**：基于 Rollup 的生产打包，自动代码分割、资源优化与静态资源处理
- **工程配置**：路径别名、开发代理、环境变量等配置开箱即用，贴合日常业务场景
- **常见问题**：TS 配置不同步、静态资源路径、环境变量前缀、构建后接口地址是高频踩坑点
