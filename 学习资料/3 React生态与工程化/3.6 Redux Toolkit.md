# Redux Toolkit 详解：全局状态管理

---

## Redux Toolkit 的定义

Redux Toolkit 是 Redux 官方推荐的状态管理方案，用于解决跨页面、跨组件之间共享状态的问题。它把状态集中存放到唯一的全局 Store 中，任何组件都能读取和更新同一份数据，避免繁琐的逐级 props 传递。

Redux Toolkit 遵循单一状态来源和单向数据流的设计原则：组件通过派发 action 发起更新，Reducer 根据 action 生成新状态，Store 变化后再反向驱动组件重渲染。

**核心特点：**
- 单一状态来源：整个应用的状态集中存放于唯一的 Store，数据一致性有保证
- 单向数据流：dispatch action → Reducer 生成新状态 → UI 自动同步更新
- 约定优于配置：内置 Immer 与 thunk，用更少的样板代码完成不可变更新和异步请求

**官方文档链接：**
- [Redux Toolkit 官方文档](https://redux-toolkit.js.org)
- [Redux Toolkit 中文文档](https://cn.redux.js.org/)

## Redux Toolkit 基本用法

### 1. 创建全局状态容器并注册状态模块

```ts
// store/index.ts
import { configureStore } from '@reduxjs/toolkit';
import timesheetReducer from './timesheetSlice';
import userReducer from './userSlice';

const store = configureStore({
  reducer: {
    timesheet: timesheetReducer,
    user: userReducer,
  },
});

export type RootState = ReturnType<typeof store.getState>;
export type AppDispatch = typeof store.dispatch;

export default store;
```

- **configureStore**：`configureStore({...})` 创建全局状态容器，自动集成 Redux DevTools 与常用中间件
- **reducer 注册**：`reducer: { timesheet: ..., user: ... }` 将各状态模块注册进 Store，键名即状态命名空间
- **类型推导**：`RootState` 与 `AppDispatch` 从 store 自动推导，供后续类型化 hook 使用

### 2. 编写状态模块

```ts
// store/timesheetSlice.ts
import { createSlice } from '@reduxjs/toolkit';

interface Timesheet {
  id: number;
  date: string;
  hours: number;
  status: '待审批' | '已通过' | '已驳回';
}

const initialState: Timesheet[] = [
  { id: 1, date: '2026-08-03', hours: 8, status: '待审批' },
  { id: 2, date: '2026-08-04', hours: 7, status: '待审批' },
];

const timesheetSlice = createSlice({
  name: 'timesheet',
  initialState,
  reducers: {
    addRecord(state, action) {
      state.push({ ...action.payload, status: '待审批' });
    },
    approve(state, action) {
      const record = state.find((item) => item.id === action.payload);
      if (record) record.status = '已通过';
    },
    reject(state, action) {
      const record = state.find((item) => item.id === action.payload);
      if (record) record.status = '已驳回';
    },
  },
});

export const { addRecord, approve, reject } = timesheetSlice.actions;
export default timesheetSlice.reducer;
```

- **createSlice**：`createSlice({...})` 一次性完成初始状态、Reducer 与 action 的定义
- **初始状态**：`initialState` 声明该模块的初始数据，如两条待审批的工时记录
- **同步更新**：`approve(state, action)` 在 Reducer 中直接修改 `state`，Immer 自动生成不可变的新状态
- **action 派发**：`timesheetSlice.actions` 自动生成 `approve`、`reject` 等 action 创建函数

### 3. 在根组件注入全局状态

```tsx
// main.tsx
import React from 'react';
import ReactDOM from 'react-dom/client';
import { Provider } from 'react-redux';
import store from './store';
import App from './App';

ReactDOM.createRoot(document.getElementById('root')!).render(
  <Provider store={store}>
    <App />
  </Provider>
);
```

- **Provider**：`<Provider store={store}>` 将全局 Store 注入组件树，所有子组件都能访问状态
- **根组件包裹**：Provider 需包裹整个应用，通常放在入口文件的最外层

### 4. 组件中读取状态与触发更新

```tsx
// components/TimesheetList.tsx
import { useSelector, useDispatch } from 'react-redux';
import type { RootState, AppDispatch } from '../store';
import { approve, reject } from '../store/timesheetSlice';

export default function TimesheetList() {
  const records = useSelector((state: RootState) => state.timesheet);
  const dispatch = useDispatch<AppDispatch>();

  const handleApprove = (id: number) => {
    dispatch(approve(id));
  };

  return (
    <ul>
      {records.map((record) => (
        <li key={record.id}>
          {record.date}：{record.hours} 小时（{record.status}）
          {record.status === '待审批' && (
            <>
              <button onClick={() => handleApprove(record.id)}>通过</button>
              <button onClick={() => dispatch(reject(record.id))}>驳回</button>
            </>
          )}
        </li>
      ))}
    </ul>
  );
}
```

- **useSelector**：`useSelector((state) => state.timesheet)` 订阅 Store 中的指定片段，状态变化时自动重渲染
- **useDispatch**：`useDispatch<AppDispatch>()` 获取 dispatch 函数，用于派发 action
- **派发更新**：`dispatch(approve(id))` 派发 action，Reducer 处理后状态同步更新，列表自动刷新

### 5. 异步数据流

```ts
// store/timesheetSlice.ts
import { createAsyncThunk } from '@reduxjs/toolkit';

// 异步 action 自动派发三个状态：pending 进行中、fulfilled 成功、rejected 失败
export const fetchRecords = createAsyncThunk(
  'timesheet/fetchRecords',
  async (userId: number) => {
    const response = await fetch(`/api/timesheets?userId=${userId}`);
    if (!response.ok) throw new Error('获取工时记录失败');
    return (await response.json()) as Timesheet[];
  }
);

const timesheetSlice = createSlice({
  name: 'timesheet',
  initialState: {
    list: [] as Timesheet[],
    loading: false,
    error: '',
  },
  reducers: {
    // ...同步更新逻辑
  },
  extraReducers: (builder) => {
    builder
      .addCase(fetchRecords.pending, (state) => {
        state.loading = true;
        state.error = '';
      })
      .addCase(fetchRecords.fulfilled, (state, action) => {
        state.loading = false;
        state.list = action.payload;
      })
      .addCase(fetchRecords.rejected, (state, action) => {
        state.loading = false;
        state.error = action.error.message || '加载失败';
      });
  },
});
```

- **createAsyncThunk**：`createAsyncThunk('timesheet/fetchRecords', asyncFn)` 生成异步 action，自动派发三种状态
- **pending**：`fetchRecords.pending` 请求进行中，此时置位 loading，供界面显示加载提示
- **fulfilled**：`fetchRecords.fulfilled` 请求成功，`action.payload` 携带接口返回的数据
- **rejected**：`fetchRecords.rejected` 请求失败，`action.error.message` 携带错误信息
- **extraReducers**：在模块内追加对异步 action 各状态的处理逻辑

### 6. 多状态模块

```ts
// store/userSlice.ts
import { createSlice } from '@reduxjs/toolkit';

const userSlice = createSlice({
  name: 'user',
  initialState: { name: '张三', role: '员工', approvedCount: 0 },
  reducers: {
    setUser(state, action) {
      state.name = action.payload.name;
      state.role = action.payload.role;
    },
    addApprovedCount(state) {
      state.approvedCount += 1;
    },
  },
});

export const { setUser, addApprovedCount } = userSlice.actions;
export default userSlice.reducer;
```

```tsx
// components/UserPanel.tsx
import { useSelector, useDispatch } from 'react-redux';
import type { RootState, AppDispatch } from '../store';
import { addApprovedCount } from '../store/userSlice';

export default function UserPanel() {
  const user = useSelector((state: RootState) => state.user);
  const dispatch = useDispatch<AppDispatch>();

  // 审批通过后，同步更新用户模块的审批计数
  const handleApproved = () => {
    dispatch(addApprovedCount());
  };

  return (
    <div>
      <p>{user.name}（{user.role}）：已审批 {user.approvedCount} 条工时记录</p>
      <button onClick={handleApproved}>审批通过</button>
    </div>
  );
}
```

- **模块独立**：每个业务模块单独一个 slice 文件，按业务领域拆分互不干扰
- **状态命名空间**：`state.user` 对应 configureStore 中注册的 `user` 键
- **模块联动**：一次操作可派发多个 action，实现跨模块状态同步（如审批通过后同步计数）

## 常见陷阱与最佳实践

### 1. 直接修改 state

```ts
// 错误：在 reducer 中给 state 重新赋值，无法触发任何更新
reducers: {
  approve(state, action) {
    state = state.map((item) =>
      item.id === action.payload ? { ...item, status: '已通过' } : item
    );
  },
}

// 正确：依赖 Immer 直接修改，或返回基于原状态的新对象
reducers: {
  approve(state, action) {
    const record = state.find((item) => item.id === action.payload);
    if (record) record.status = '已通过';
  },
}
```

- **重新赋值无效**：`state = ...` 只是更换局部参数引用，Store 数据不会变化
- **不可变更新**：reducer 必须返回新状态或依赖 Immer 的写操作，否则状态不可预测

### 2. 在组件中写业务更新逻辑

```tsx
// 错误：用组件内 state 保存业务数据，绕过 Store，多组件无法同步
function TimesheetList() {
  const [records, setRecords] = useState(initialRecords);
  const handleApprove = (id: number) => {
    setRecords(records.map((r) => r.id === id ? { ...r, status: '已通过' } : r));
  };
}

// 正确：组件只负责派发 action，更新逻辑统一放在 reducer
function TimesheetList() {
  const records = useSelector((state: RootState) => state.timesheet);
  const dispatch = useDispatch<AppDispatch>();
  const handleApprove = (id: number) => dispatch(approve(id));
}
```

- **状态来源单一**：跨组件共享的业务数据应存于 Store，组件内 state 只保存局部 UI 状态
- **职责分离**：更新逻辑集中在 reducer，多个组件复用同一套更新规则

### 3. 异步请求状态不处理

```tsx
// 错误：只触发请求，不处理加载与失败状态，界面无反馈
dispatch(fetchRecords(userId)).then(() => console.log('ok'));

// 正确：通过 pending / fulfilled / rejected 三态驱动 UI
const { list, loading, error } = useSelector((state: RootState) => state.timesheet);

if (loading) return <div>加载中...</div>;
if (error) return <div>加载失败：{error}</div>;
return <TimesheetList records={list} />;
```

- **三种状态衔接**：pending 显示加载提示、fulfilled 渲染数据、rejected 展示错误信息
- **UI 状态对应**：loading 与 error 字段驱动界面反馈，避免白屏或无响应

### 4. 类型定义缺失

```tsx
// 错误：useSelector 与 useDispatch 无类型，字段改名时无法在编译期发现
const records = useSelector((state) => state.timesheet);
const dispatch = useDispatch();

// 正确：使用 RootState 与 AppDispatch 推导类型
const records = useSelector((state: RootState) => state.timesheet);
const dispatch = useDispatch<AppDispatch>();
```

- **RootState**：`RootState` 由 store 推导，保证选择器的字段类型安全
- **AppDispatch**：`AppDispatch` 约束 dispatch 只能派发已注册的 action

### 最佳实践

1. **状态只存业务数据**，UI 临时状态继续用 useState，避免 Store 过度膨胀
2. **更新一律走 reducer**，组件只负责 dispatch，禁止直接修改状态
3. **异步请求必处理三种状态**，同时提供 loading 与 error 反馈
4. **按业务模块拆分 slice**，每个模块独立文件，单一职责
5. **使用类型化的 useSelector / useDispatch**，编译期即可发现字段错误
6. **选择器尽量精准**，只订阅所需的状态片段，减少不必要的重渲染

---

## 总结

Redux Toolkit 让 React 全局状态管理更简单可控：

- **单一状态来源**：全局 Store 集中管理跨页面、跨组件共享的业务数据
- **单向数据流**：dispatch action → reducer 生成新状态 → UI 自动同步
- **内置工具**：Immer 简化不可变更新，thunk 统一异步数据流
- **模块化**：createSlice 按业务拆分，多模块协同维护
- **类型安全**：RootState 与 AppDispatch 推导，开发期即可发现错误
