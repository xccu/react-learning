# Redux Toolkit 详解：全局状态管理

---

## Redux Toolkit 的定义

Redux Toolkit 是 Redux 官方推荐的状态管理方案，用于解决**跨组件共享状态**的问题。它把状态集中存放到唯一的全局 Store 中，任何组件都能读取和更新同一份数据。

**Redux 解决的核心问题：**

| 问题场景 | 不用 Redux 的痛点 | Redux 的解法 |
|---------|-----------------|------------|
| 跨组件共享状态 | 多层组件逐层传 prop（prop drilling），或 Context 更新时所有消费组件全部重渲染 | 单一 Store，组件精确选取需要的数据，只更新自己 |
| 状态更新逻辑分散 | 相同状态在不同组件中各自维护，容易出现数据不一致 | 所有更新走 reducer，逻辑集中、可预测 |
| 复杂交互难以追踪 | 不知道状态在哪被谁修改、何时修改 | 单向数据流 + Redux DevTools 时间旅行，每一步 action 可追溯 |
| 异步请求缺少统一状态管理 | 每个组件自己维护 loading / error，代码重复 | createAsyncThunk 统一处理 pending / fulfilled / rejected |

**Redux vs Context 对比：**

| 维度 | Context + useState | Redux Toolkit |
|------|-------------------|---------------|
| 状态位置 | 分散在各组件或 Context 中 | 集中在唯一 Store 中 |
| 状态更新 | useState setter / Context 方法 | dispatch action，统一走 reducer |
| 精确更新 | 不行，Context 值变化时所有消费组件重渲染 | 可以，useSelector 只选取需要的数据，引用不变则不重渲染 |
| 调试能力 | React DevTools 查看组件树 | Redux DevTools 时间旅行，每一步 action 可追溯 |
| 代码量 | 少，适合简单场景 | 多，需要写 store/slice/provider |
| 学习曲线 | 平缓，React 内置 | 较陡，需要理解单向数据流、不可变更新等概念 |
| 适用场景 | 局部状态、简单跨组件共享（如主题、语言） | 复杂状态、频繁更新、多组件共享、需要调试追踪 |

**什么时候用 Context，什么时候用 Redux？**

- **用 Context**：主题切换、语言切换、用户信息（不频繁变化）、简单的表单状态共享
- **用 Redux**：表单输入频繁变化且多个组件消费、列表增删改查、需要时间旅行调试、异步请求状态统一管理

**核心思想——单向数据流：**

```
组件 dispatch(action) → Reducer 处理 → Store 更新 → UI 自动刷新
```

**核心特点：**
- 单一状态来源：所有状态存在一个 Store 里
- 单向数据流：只能 dispatch action 触发更新，不能直接改状态
- 内置工具：Immer（简化不可变更新）+ thunk（处理异步）

## 核心概念

### 1. Store — 唯一的状态容器

```ts
import { configureStore } from '@reduxjs/toolkit';
import counterReducer from './counterSlice';

const store = configureStore({
  reducer: {
    counter: counterReducer,
  },
});

export type RootState = ReturnType<typeof store.getState>;
export type AppDispatch = typeof store.dispatch;
export default store;
```

- **Store** 是全局唯一的，整个应用共享同一份状态
- `RootState` 和 `AppDispatch` 由 store 自动推导类型，后续组件直接用

### 2. Slice — 一个业务模块的状态 + 更新逻辑

```ts
import { createSlice } from '@reduxjs/toolkit';

const counterSlice = createSlice({
  name: 'counter',
  initialState: { value: 0 },
  reducers: {
    // 加 1
    increment(state) {
      state.value += 1;  // 直接写，Immer 自动处理不可变更新
    },
    // 减 1
    decrement(state) {
      state.value -= 1;
    },
    // 加指定值
    incrementBy(state, action) {
      state.value += action.payload;
    },
  },
});

// 自动生成 action creators
export const { increment, decrement, incrementBy } = counterSlice.actions;
export default counterSlice.reducer;
```

- **createSlice** 一次性定义三样东西：初始状态、更新逻辑（reducers）、action 创建函数
- reducer 里可以直接 `state.value += 1`，Immer 会在背后生成不可变的新状态
- 导出的 `increment`、`decrement` 就是 action creators

### 3. Provider — 把 Store 注入组件树

```tsx
import { Provider } from 'react-redux';
import store from './store';

ReactDOM.createRoot(document.getElementById('root')!).render(
  <Provider store={store}>
    <App />
  </Provider>
);
```

- `<Provider>` 包裹整个应用，子组件才能访问 Store
- 只需在入口文件写一次

### 4. 组件中读取和更新状态

```tsx
import { useSelector, useDispatch } from 'react-redux';
import type { RootState, AppDispatch } from './store';
import { increment, decrement } from './counterSlice';

function Counter() {
  // 读取状态
  const count = useSelector((state: RootState) => state.counter.value);
  // 获取 dispatch
  const dispatch = useDispatch<AppDispatch>();

  return (
    <div>
      <p>当前值：{count}</p>
      <button onClick={() => dispatch(increment())}>+1</button>
      <button onClick={() => dispatch(decrement())}>-1</button>
    </div>
  );
}
```

- **useSelector**：从 Store 中读取需要的状态片段
- **useDispatch**：获取 dispatch 函数
- **dispatch(action)**：派发 action，触发 reducer 更新状态
- **state.counter.value 路径**：由两步自动推导——`initialState: { value: 0 }` 定义字段 `value`，`configureStore({ reducer: { counter: ... } })` 注册键名 `counter` 成为命名空间，组合后就是 `state.counter.value`

## 异步操作

```ts
import { createSlice, createAsyncThunk } from '@reduxjs/toolkit';

// 异步 action：自动管理 pending / fulfilled / rejected 三种状态
export const fetchData = createAsyncThunk(
  'counter/fetchData',
  async () => {
    // 这里写真实的 API 请求
    const response = await fetch('/api/counter');
    return (await response.json()).value;
  }
);

const counterSlice = createSlice({
  name: 'counter',
  initialState: { value: 0, loading: false, error: null },
  reducers: {
    increment(state) { state.value += 1; },
  },
  extraReducers: (builder) => {
    builder
      .addCase(fetchData.pending, (state) => {
        state.loading = true;
      })
      .addCase(fetchData.fulfilled, (state, action) => {
        state.loading = false;
        state.value = action.payload;
      })
      .addCase(fetchData.rejected, (state, action) => {
        state.loading = false;
        state.error = action.error.message;
      });
  },
});
```

- **createAsyncThunk** 自动处理三种状态：
  - `pending` → 请求进行中（显示 loading）
  - `fulfilled` → 请求成功（更新数据）
  - `rejected` → 请求失败（记录错误）
- 在组件中通过 `loading` 和 `error` 字段控制 UI 反馈

## 完整示例：计数器

### 项目结构

```
store/
  index.ts          — 创建 Store
  counterSlice.ts   — 计数器状态模块
main.tsx            — 入口文件
Counter.tsx         — 计数器组件
```

### 代码

```ts
// store/counterSlice.ts
import { createSlice } from '@reduxjs/toolkit';

const counterSlice = createSlice({
  name: 'counter',
  initialState: { value: 0 },
  reducers: {
    increment(state) { state.value += 1; },
    decrement(state) { state.value -= 1; },
    reset(state) { state.value = 0; },
  },
});

export const { increment, decrement, reset } = counterSlice.actions;
export default counterSlice.reducer;
```

- **createSlice**：定义初始状态 `{ value: 0 }` 和三个同步 reducer
- **counterSlice.actions**：自动生成 `increment`、`decrement`、`reset` 三个 action creators
- **export default counterSlice.reducer**：导出 reducer 供 configureStore 注册

```ts
// store/index.ts
import { configureStore } from '@reduxjs/toolkit';
import counterReducer from './counterSlice';

const store = configureStore({
  reducer: { counter: counterReducer },
});

export type RootState = ReturnType<typeof store.getState>;
export type AppDispatch = typeof store.dispatch;
export default store;
```

- **configureStore**：创建全局 Store，自动集成 DevTools 和常用中间件
- **reducer: { counter: ... }**：注册 counter reducer，键名 `counter` 成为状态命名空间
- **RootState / AppDispatch**：由 store 自动推导类型，供组件使用

```tsx
// main.tsx
import { createRoot } from 'react-dom/client';
import { Provider } from 'react-redux';
import store from './store';
import Counter from './Counter';

createRoot(document.getElementById('root')!).render(
  <Provider store={store}>
    <Counter />
  </Provider>
);
```

- **Provider**：将 Store 注入组件树，所有子组件都能通过 useSelector/useDispatch 访问状态
- **包裹整个应用**：只需在入口文件写一次

```tsx
// Counter.tsx
import { useSelector, useDispatch } from 'react-redux';
import type { RootState, AppDispatch } from './store';
import { increment, decrement, reset } from './store/counterSlice';

function Counter() {
  const count = useSelector((state: RootState) => state.counter.value);
  const dispatch = useDispatch<AppDispatch>();

  return (
    <div>
      <h2>计数器：{count}</h2>
      <button onClick={() => dispatch(increment())}>+1</button>
      <button onClick={() => dispatch(decrement())}>-1</button>
      <button onClick={() => dispatch(reset())}>重置</button>
    </div>
  );
}
```

- **useSelector**：读取 `state.counter.value`，状态变化时自动重渲染
- **useDispatch**：获取 dispatch 函数
- **dispatch(increment())**：点击按钮时派发 action，reducer 更新状态，UI 自动刷新

## 常见陷阱

### 陷阱 1：直接给 state 重新赋值

```ts
// 错误：重新赋值只是换了局部引用，Store 不会更新
reducers: {
  increment(state) {
    state = { value: state.value + 1 };  // 无效！
  },
}

// 正确：直接修改 state，Immer 处理不可变更新
reducers: {
  increment(state) {
    state.value += 1;  // 正确
  },
}
```

### 陷阱 2：在组件中直接修改状态

```tsx
// 错误：绕过 reducer，其他组件拿不到更新
function Counter() {
  const [count, setCount] = useState(0);  // 局部 state，其他组件无法共享
}

// 正确：组件只负责 dispatch，更新逻辑统一在 reducer
function Counter() {
  const count = useSelector((state) => state.counter.value);
  const dispatch = useDispatch();
  // 组件只做一件事：dispatch
  return <button onClick={() => dispatch(increment())}>+1</button>;
}
```

### 陷阱 3：异步请求不处理 loading 和 error

```tsx
// 错误：点击按钮后界面无反馈
<button onClick={() => dispatch(fetchData())}>加载</button>

// 正确：通过 loading 和 error 驱动 UI
const { loading, error } = useSelector((state) => state.counter);
if (loading) return <p>加载中...</p>;
if (error) return <p>出错了：{error}</p>;
```

## 最佳实践

1. **状态只存业务数据**，UI 临时状态（如弹窗开关）继续用 useState
2. **更新一律走 reducer**，组件只负责 dispatch
3. **异步请求必处理三种状态**（pending / fulfilled / rejected）
4. **按业务模块拆分 slice**，每个模块独立文件
5. **使用类型化的 useSelector / useDispatch**，编译期即可发现错误

---

## 总结

- **Store**：全局唯一的状态容器
- **Slice**：一个模块的状态 + 更新逻辑
- **Provider**：注入 Store 到组件树
- **useSelector**：读取状态
- **useDispatch**：派发 action
- **createAsyncThunk**：处理异步请求的三种状态
