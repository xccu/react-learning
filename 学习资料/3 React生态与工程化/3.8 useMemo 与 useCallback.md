# useMemo 与 useCallback 详解：缓存计算结果与函数引用

---

## useMemo 与 useCallback 的定义

useMemo 和 useCallback 都是 React 内置的性能优化 Hook。useMemo 用于缓存**计算结果**（值），当依赖项没有变化时，跳过重复计算，直接复用上一次的结果；useCallback 用于缓存**函数引用**，当依赖项没有变化时，跳过函数重建，让函数引用保持稳定。

两者解决的问题不同：useMemo 解决的是"值重复计算"的问题，useCallback 解决的是"函数引用不稳定"的问题。它们都依赖**依赖数组（dependencies）**来判断是否值得复用缓存。需要注意的是，两者服务于渲染优化而非渲染本身，React 官方建议仅在确认存在性能问题时使用。

**核心特点：**
- useMemo 缓存函数的计算结果，返回的是值（对象、数组、数字等）
- useCallback 缓存函数本身，返回的是函数引用
- 两者都通过依赖数组控制缓存何时失效，依赖变化才重新计算/重建

## useMemo 与 useCallback 基本用法

### 1. useMemo 缓存计算结果

在工时填报管理系统中，根据关键字和状态过滤工时列表是典型的"重计算"场景。每次渲染都重新过滤会浪费性能，用 useMemo 把过滤结果缓存起来，只有当 `keyword`、`status` 或 `records` 变化时才重新计算：

```tsx
import { useMemo, useState } from 'react';

function WorkRecordList({ records }: { records: WorkRecord[] }) {
  const [keyword, setKeyword] = useState('');
  const [status, setStatus] = useState('all');

  const filteredRecords = useMemo(() => {
    return records.filter((record) => {
      const matchKeyword = record.taskName.includes(keyword);
      const matchStatus = status === 'all' || record.status === status;
      return matchKeyword && matchStatus;
    });
  }, [keyword, status, records]);

  return (
    <div>
      <input
        placeholder="输入关键字筛选任务"
        value={keyword}
        onChange={(e) => setKeyword(e.target.value)}
      />
      <ul>
        {filteredRecords.map((record) => (
          <li key={record.id}>
            {record.taskName} - {record.hours} 小时 - {record.status}
          </li>
        ))}
      </ul>
    </div>
  );
}
```

- **useMemo 导入**：`useMemo` 从 React 中导入，接收计算函数和依赖数组两个参数
- **缓存结果**：`useMemo(() => {...}, deps)` 只调用传入的函数，返回值为过滤后的列表
- **依赖数组**：`[keyword, status, records]` 任一依赖变化时，才重新执行过滤计算
- **渲染引用**：`filteredRecords` 作为缓存值直接用于渲染，避免每次渲染重复过滤

### 2. useMemo 缓存耗时计算

除列表过滤外，useMemo 也适合缓存**代价高昂的计算**，例如对工时数据进行统计汇总。这类计算在依赖未变时结果相同，缓存后可以避免每次渲染都重复执行：

```tsx
import { useMemo } from 'react';

function WorkStats({ records }: { records: WorkRecord[] }) {
  const stats = useMemo(() => {
    console.log('计算工时统计...');
    return records.reduce(
      (acc, record) => {
        acc.totalHours += record.hours;
        acc.doneCount += record.status === 'done' ? 1 : 0;
        return acc;
      },
      { totalHours: 0, doneCount: 0 }
    );
  }, [records]);

  return (
    <div>
      <p>总工时：{stats.totalHours} 小时</p>
      <p>已完成：{stats.doneCount} 条</p>
    </div>
  );
}
```

- **耗时计算**：`reduce` 汇总计算仅在 `records` 变化时执行，控制台只在必要时打印日志
- **计算缓存**：`stats` 是计算后的对象，被多次渲染稳定复用
- **副作用注意**：useMemo 的工厂函数在渲染期间执行，不应在里面做副作用（如请求数据）

### 3. useCallback 缓存函数引用

当向使用 `memo` 缓存的子组件传递回调函数时，内联函数每次渲染都会创建新引用，导致 memo 缓存失效。useCallback 让函数引用保持稳定：

```tsx
import { useCallback, useState } from 'react';
import { memo } from 'react';

const WorkRecordItem = memo(function WorkRecordItem({
  record,
  onView,
  onDelete,
}: {
  record: WorkRecord;
  onView: (id: string) => void;
  onDelete: (id: string) => void;
}) {
  return (
    <li>
      <span>{record.taskName}</span>
      <button onClick={() => onView(record.id)}>详情</button>
      <button onClick={() => onDelete(record.id)}>删除</button>
    </li>
  );
});

function WorkRecordList({ records }: { records: WorkRecord[] }) {
  const [list, setList] = useState(records);

  const handleView = useCallback((id: string) => {
    console.log('跳转到详情页，记录 ID：', id);
  }, []);

  const handleDelete = useCallback((id: string) => {
    setList((prev) => prev.filter((record) => record.id !== id));
  }, []);

  return (
    <ul>
      {list.map((record) => (
        <WorkRecordItem
          key={record.id}
          record={record}
          onView={handleView}
          onDelete={handleDelete}
        />
      ))}
    </ul>
  );
}
```

- **useCallback 导入**：`useCallback` 返回一个被缓存的函数引用
- **回调缓存**：`handleView`、`handleDelete` 在依赖未变时始终是同一个函数引用
- **配合 memo**：传给 `memo(WorkRecordItem)` 的回调 props 引用稳定，缓存才能生效
- **函数体更新**：`handleDelete` 使用 `setList((prev) => ...)` 函数式更新，不依赖外部变量

### 4. 依赖数组

依赖数组是 useMemo 和 useCallback 的"失效开关"。依赖变化时缓存失效并重新计算/重建，依赖未变时复用缓存：

```tsx
import { useCallback, useMemo } from 'react';

function Demo({ records, baseRate }: { records: WorkRecord[]; baseRate: number }) {
  // 依赖变化（baseRate 或 records）时重新计算
  const overtimeHours = useMemo(() => {
    return records.reduce((sum, r) => sum + r.hours, 0) * baseRate;
  }, [records, baseRate]);

  // 依赖变化时重建函数
  const handleExport = useCallback(() => {
    console.log('导出当前工时的统计结果：', overtimeHours);
  }, [overtimeHours]);

  return <button onClick={handleExport}>导出统计</button>;
}
```

- **依赖声明**：`[records, baseRate]` 声明 useMemo 依赖，两者任一变化触发重算
- **缓存函数依赖**：`handleExport` 内部读取了 `overtimeHours`，依赖数组必须包含它
- **空依赖数组**：`[]` 表示永不重新计算/重建，但闭包中捕获的变量将是首次渲染时的值

### 5. 三者对比

memo、useMemo、useCallback 是 React 三个不同层级的缓存手段，适用场景各不相同：

| API | 缓存对象 | 返回类型 | 适用场景 |
|------|------|------|------|
| memo | 组件渲染结果 | 组件 | 父组件频繁重渲染、props 稳定的展示型组件（列表项、卡片） |
| useMemo | 计算结果 | 值（对象、数组、数字） | 列表过滤、数据统计等耗时计算，结果在渲染中复用 |
| useCallback | 函数引用 | 函数 | 向 memo 子组件传递回调，作为依赖传给 useMemo/useEffect |

- **分工不同**：memo 缓存"组件"，useMemo 缓存"值"，useCallback 缓存"函数"
- **配合使用**：三者常组合使用，如 useCallback 保证传入 memo 子组件的函数 props 稳定
- **先优化后缓存**：三者都不改变渲染逻辑，只做性能优化，应在确认瓶颈后使用

## 常见陷阱与最佳实践

### 1. 过早优化

useMemo 和 useCallback 本身也有开销：依赖数组比较、缓存查找等。对轻量计算或简单组件滥用缓存，收益可能为负：

```tsx
// 错误：无意义的缓存，简单的字符串拼接不值得用 useMemo
const displayName = useMemo(() => `${user.name}-${user.id}`, [user.name, user.id]);

// 正确：直接计算，性能足够且代码更简洁
const displayName = `${user.name}-${user.id}`;

// 错误：为不依赖 memo 的组件包装 useCallback，缓存毫无意义
const handleClick = useCallback(() => setCount(c => c + 1), []);
<button onClick={handleClick}>点击</button>;

// 正确：只有传给 memo 子组件或作为依赖时，才需要稳定的函数引用
const handleClick = useCallback(() => setCount(c => c + 1), []);
<MemoButton onClick={handleClick}>点击</MemoButton>;
```

### 2. 依赖数组遗漏导致闭包过期

如果回调或计算内部使用了某个变量，但依赖数组没有包含它，缓存会一直复用旧闭包，读取到过期的值：

```tsx
// 错误：漏掉 keyword，handleSearch 永远读到首次渲染时的 keyword
function SearchPanel() {
  const [keyword, setKeyword] = useState('');

  const handleSearch = useCallback(() => {
    console.log('搜索关键字：', keyword);
  }, []);
  // 正确：补上 keyword
  // }, [keyword]);

  return (
    <input
      value={keyword}
      onChange={(e) => setKeyword(e.target.value)}
    />
  );
}
```

### 3. 依赖数组写成空数组

依赖数组为 `[]` 时，缓存永不失效，函数或计算会"卡"在首次渲染的状态。若内部使用了会变化的 props 或 state，将产生 bug：

```tsx
// 错误：空依赖 + 内部读取 baseRate，baseRate 变化后仍用旧值计算
function RatePanel({ baseRate }: { baseRate: number }) {
  const [hours, setHours] = useState(40);

  const total = useMemo(() => hours * baseRate, []); // baseRate 变化不重算

  // 正确：baseRate 加入依赖
  // const total = useMemo(() => hours * baseRate, [hours, baseRate]);

  return <p>预计金额：{total}</p>;
}
```

### 4. 无谓地包裹 useCallback

某些情况下 useCallback 提供了稳定引用，但实际代码根本不需要它，反而增加阅读成本：

```tsx
// 错误：本组件内部使用，且没有作为依赖传给其他 Hook，useCallback 纯属多余
function ListPage() {
  const refresh = useCallback(() => {
    window.location.reload();
  }, []);
  return <button onClick={refresh}>刷新</button>;
}

// 正确：普通函数即可，行为完全一致
function ListPage() {
  const refresh = () => {
    window.location.reload();
  };
  return <button onClick={refresh}>刷新</button>;
}
```

### 5. useMemo 中执行副作用

useMemo 的工厂函数在渲染期间同步执行，不能保证只调用一次，也不应做请求、订阅等副作用：

```tsx
// 错误：在 useMemo 里发起请求，依赖变化时会重复请求，且渲染期间产生副作用
const data = useMemo(() => {
  return fetchRecords(); // 副作用，应在 useEffect 中执行
}, []);

// 正确：数据请求放在 useEffect 中，状态驱动渲染
const [data, setData] = useState([]);
useEffect(() => {
  fetchRecords().then(setData);
}, []);
```

### 最佳实践

1. **先测量再优化**：确认计算或渲染确实存在性能瓶颈后，再使用 useMemo / useCallback
2. **配合 memo 使用**：只有向 memo 子组件传回调或把函数作为依赖时，才需要 useCallback
3. **完整声明依赖**：函数内部使用到的变量都应加入依赖数组，保证闭包不过期
4. **避免空依赖闭包**：空依赖数组只在确需捕获首次渲染值时使用，否则及时补全依赖
5. **避免使用 useMemo 替代渲染逻辑**：useMemo 缓存的是计算结果，不是 JSX，直接返回 JSX 的做法不推荐
6. **保持代码可读**：优先写简洁的普通计算，性能确有问题时再引入缓存 Hook

---

## 总结

useMemo 与 useCallback 是 React 中最常用的两个性能优化 Hook：

- **useMemo**：缓存计算结果，依赖变化时重新计算，适合列表过滤、数据统计等耗时计算
- **useCallback**：缓存函数引用，依赖变化时重新创建，适合传给 memo 子组件的回调
- **依赖数组**：是缓存的失效开关，漏写、空写都会导致闭包过期或缓存永不更新
- **三者分工**：memo 缓存组件、useMemo 缓存值、useCallback 缓存函数，配合使用效果最佳
- **避免滥用**：过早优化反而增加开销，应先确认性能瓶颈，再针对性地使用
