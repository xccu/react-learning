# memo 详解：组件级性能优化

---

## memo 的定义

memo 是 React 内置的组件缓存 API，用于对组件进行性能优化。当组件的 props 未发生变化时，React 会跳过重新渲染，直接复用上一次的渲染结果。

memo 通过**浅比较（Shallow Compare）**props 来决定是否重新渲染。它本质上是给组件加上一层"记忆"，让父组件重新渲染时，如果传给子组件的 props 没有变化，子组件就不会白白跟着重渲染一次。

**核心特点：**
- 通过缓存组件来减少不必要的重复渲染
- 基于 props 的浅比较，只影响渲染阶段，不影响组件自身内部状态
- 适用于 props 稳定、内容相对静态的组件

- [memo 参考文档（中文）](https://zh-hans.react.dev/reference/react/memo)

## memo 基本用法

### 1. 包裹组件

使用 `memo()` 包裹组件，得到一个"缓存版本"的组件。当 props 没有变化时，React 会复用上一次渲染结果，跳过重新渲染：

```tsx
import { memo } from 'react';

function WorkRecordItem({ record }: { record: WorkRecord }) {
  return (
    <li>
      <span>{record.taskName}</span>
      <span>{record.hours} 小时</span>
    </li>
  );
}

export const MemoWorkRecordItem = memo(WorkRecordItem);
```

- **memo 导入**：`import { memo } from 'react'` 从 React 中导入 memo API
- **memo 包裹**：`memo(WorkRecordItem)` 将 WorkRecordItem 包装为缓存组件，返回 MemoWorkRecordItem
- **浅比较**：memo 会逐个比较 props 的值，若全部相同则跳过重新渲染
- **复用导出**：组件内部自身 state 变化时仍会正常重新渲染，memo 不会阻止这一点

### 2. 适用场景

memo 最适合包裹**展示型组件**，尤其是列表项这类重复渲染成本高、但自身 props 变化频率低的组件。当父组件频繁重渲染时，memo 能有效减少子组件的不必要渲染：

```tsx
function WorkRecordList({ records }: { records: WorkRecord[] }) {
  const [filterText, setFilterText] = useState('');

  return (
    <div>
      <input
        placeholder="筛选任务"
        value={filterText}
        onChange={(e) => setFilterText(e.target.value)}
      />
      <ul>
        {records.map((record) => (
          <MemoWorkRecordItem key={record.id} record={record} />
        ))}
      </ul>
    </div>
  );
}
```

- **场景识别**：`WorkRecordItem` 是纯展示型组件，只负责显示工时记录
- **频繁重渲染**：父组件因 `filterText` 变化而频繁重渲染时，memo 让列表项组件跳过不必要的渲染
- **触发更新**：点击、输入等交互状态变化都会导致父组件重渲染，但不会波及 props 未变的子组件
- **key 仍然需要**：渲染列表时仍需给每个 `MemoWorkRecordItem` 传 key，用于列表协调

### 3. 引用比较的原理

memo 的浅比较只比较**引用**而非内容。当 props 是对象或内联回调函数时，即使"看起来一样"，每次渲染都会生成新引用，导致缓存失效。

#### 错误写法：引用不稳定导致缓存失效

```tsx
function WorkRecordList({ records }: { records: WorkRecord[] }) {
  const [filterText, setFilterText] = useState('');

  // ❌ 每次渲染都创建新对象，浅比较永远不相等
  const extraProps = { source: 'manual' };
  // ❌ 内联箭头函数每次渲染都是新引用
  const handleEdit = () => {};

  return (
    <ul>
      {records.map((record) => (
        <MemoWorkRecordItem
          key={record.id}
          record={record}
          extra={extraProps}
          onEdit={handleEdit}
        />
      ))}
    </ul>
  );
}
// 第一次渲染：extraProps 引用 A，handleEdit 引用 B
// 第二次渲染：extraProps 引用 C（新对象），handleEdit 引用 D（新函数）
// 浅比较：A !== C，B !== D → 判定变化 → 重新渲染（memo 失效）
```

#### 正确写法：稳定引用让缓存生效

```tsx
function WorkRecordList({ records }: { records: WorkRecord[] }) {
  const [filterText, setFilterText] = useState('');

  // ✅ useMemo 缓存对象引用，始终返回同一引用
  const extraProps = useMemo(() => ({ source: 'manual' }), []);
  // ✅ useCallback 缓存回调引用，始终返回同一引用
  const handleEdit = useCallback(() => {}, []);

  return (
    <ul>
      {records.map((record) => (
        <MemoWorkRecordItem
          key={record.id}
          record={record}
          extra={extraProps}
          onEdit={handleEdit}
        />
      ))}
    </ul>
  );
}
// 两次渲染：extraProps 引用 A（同一对象），handleEdit 引用 B（同一函数）
// 浅比较：A === A，B === B → 判定不变 → 跳过渲染（memo 生效）
```

- **对象比较**：内联对象 `{}` 每次渲染创建新引用；`useMemo` 缓存后引用稳定
- **回调比较**：内联箭头函数每次创建新引用；`useCallback` 缓存后引用稳定
- **比较原理**：浅比较使用 `Object.is` 逐字段对比，对象和函数比较的是引用地址而非内容
- **生效条件**：props 引用稳定时，浅比较判定不变，memo 跳过渲染

## 浅比较的代码写法对比

以下通过"错误写法 vs 正确写法"的对比，说明哪些情况 memo 有效、哪些无效，以及原因。

### 1. 基本类型 props — memo 有效

基本类型（string、number、boolean）的值变化时引用必然不同，浅比较能正确识别。

```tsx
// ✅ 正确：基本类型 props，memo 有效
function UserCard({ name, age }: { name: string; age: number }) {
  return (
    <div>
      <span>{name}</span>
      <span>{age}</span>
    </div>
  );
}
export const MemoUserCard = memo(UserCard);

function Parent() {
  const [name, setName] = useState('Alice');
  return <MemoUserCard name={name} age={25} />;
}
// name 从 'Alice' 变为 'Bob' → 值变化 → 浅比较判定不同 → 重新渲染（正确行为）
// name 不变 → 浅比较判定相同 → 跳过渲染（优化生效）
```

**原因：** 基本类型值变化时引用必然不同，浅比较 `Object.is('Alice', 'Bob')` 返回 false 触发更新；值不变时返回 false 跳过渲染。

---

### 2. 内联对象 vs 缓存对象

```tsx
// ❌ 错误：内联对象，每次渲染创建新引用
function WorkRecordList({ records }: { records: WorkRecord[] }) {
  return (
    <ul>
      {records.map((record) => (
        <MemoWorkRecordItem
          key={record.id}
          record={record}
          metadata={{ source: 'manual', timestamp: Date.now() }}
        />
      ))}
    </ul>
  );
}
// 第一次渲染：{ source: 'manual', timestamp: 1000 }  → 引用 A
// 第二次渲染：{ source: 'manual', timestamp: 2000 }  → 引用 B（新对象）
// 浅比较：引用 A !== 引用 B → 判定为变化 → 重新渲染（memo 失效）
```

```tsx
// ✅ 正确：用 useMemo 缓存对象引用
function WorkRecordList({ records }: { records: WorkRecord[] }) {
  const metadata = useMemo(() => ({ source: 'manual', timestamp: Date.now() }), []);

  return (
    <ul>
      {records.map((record) => (
        <MemoWorkRecordItem key={record.id} record={record} metadata={metadata} />
      ))}
    </ul>
  );
}
// 第一次渲染：useMemo 创建对象 → 引用 A
// 第二次渲染：useMemo 依赖为空 → 返回同一引用 A
// 浅比较：引用 A === 引用 A → 判定为不变 → 跳过渲染（优化生效）
```

**原因：** 内联对象字面量 `{}` 每次渲染创建新对象，引用地址不同；`useMemo` 缓存后两次渲染返回同一引用，浅比较命中缓存。

---

### 3. 内联箭头函数 vs useCallback 缓存

```tsx
// ❌ 错误：内联箭头函数，每次渲染创建新引用
function WorkRecordList({ records }: { records: WorkRecord[] }) {
  return (
    <ul>
      {records.map((record) => (
        <MemoWorkRecordItem
          key={record.id}
          record={record}
          onEdit={() => openEditor(record.id)}
          onClick={(e) => console.log(e)}
        />
      ))}
    </ul>
  );
}
// 第一次渲染：() => openEditor(1)  → 引用 A
// 第二次渲染：() => openEditor(1)  → 引用 B（新函数）
// 浅比较：引用 A !== 引用 B → 判定为变化 → 重新渲染（memo 失效）
```

```tsx
// ✅ 正确：用 useCallback 缓存回调引用
function WorkRecordList({ records }: { records: WorkRecord[] }) {
  const handleEdit = useCallback(
    (id: number) => openEditor(id),
    []
  );

  const handleClick = useCallback((e: MouseEvent) => console.log(e), []);

  return (
    <ul>
      {records.map((record) => (
        <MemoWorkRecordItem
          key={record.id}
          record={record}
          onEdit={handleEdit}
          onClick={handleClick}
        />
      ))}
    </ul>
  );
}
// 第一次渲染：useCallback 创建函数 → 引用 A
// 第二次渲染：useCallback 依赖为空 → 返回同一引用 A
// 浅比较：引用 A === 引用 A → 判定为不变 → 跳过渲染（优化生效）
```

**原因：** 内联箭头函数 `() => {}` 每次渲染创建新函数实例；`useCallback` 缓存后返回同一引用，浅比较命中缓存。

---

### 4. useCallback vs useMemo

两者都缓存引用，但返回值不同：

```tsx
// useCallback 返回缓存的函数，专用于回调
const handleEdit = useCallback(
  (id: number) => openEditor(id),
  []
);

// useMemo 返回缓存的值，可用于对象、计算结果等
const metadata = useMemo(() => ({ source: 'manual' }), []);
```

| 区别点 | useCallback | useMemo |
|--------|------------|---------|
| 返回值 | 缓存的**函数** | 缓存的**值**（任意类型） |
| 本质 | `useMemo(() => fn, deps)` 的语法糖 | 通用值缓存 |
| 适用场景 | 传给子组件的回调 props | 传给子组件的对象 props、计算结果 |
| 依赖数组 | 行为与 useMemo 一致 | 行为与 useCallback 一致 |

**使用建议：** 传给子组件的回调优先用 `useCallback`，语义更清晰；传对象或计算结果用 `useMemo`。两者依赖数组的行为完全一致。

### 5. 父组件状态变化 vs 子组件 props 不变

```tsx
// ✅ 正确：父组件状态变化不影响子组件 props 引用
function TaskManager({ tasks }: { tasks: Task[] }) {
  const [searchText, setSearchText] = useState('');
  const [collapsed, setCollapsed] = useState(false);

  return (
    <div>
      <input value={searchText} onChange={(e) => setSearchText(e.target.value)} />
      <button onClick={() => setCollapsed(!collapsed)}>
        {collapsed ? '展开' : '收起'}
      </button>
      <ul>
        {tasks.map((task) => (
          <MemoTaskItem key={task.id} task={task} />
        ))}
      </ul>
    </div>
  );
}
// 用户输入 searchText → 父组件重渲染
// task prop 引用未变 → 浅比较判定不变 → MemoTaskItem 跳过渲染
// 用户点击折叠按钮 → 父组件重渲染
// task prop 引用未变 → MemoTaskItem 跳过渲染
```

**原因：** 父组件因 searchText / collapsed 变化重渲染，但传给 MemoTaskItem 的 task prop 引用未变，浅比较命中缓存。

### 6. props 频繁变化 — memo 无效

```tsx
// ❌ 无效：props 高频变化，memo 形同虚设
function LiveDashboard() {
  const [data, setData] = useState([]);

  useEffect(() => {
    const timer = setInterval(() => {
      setData(fetchLatestData());
    }, 100);
    return () => clearInterval(timer);
  }, []);

  return <MemoChart data={data} />;
}
// 每 100ms setData 触发重渲染
// data 每次都是新数组 → 引用变化 → 浅比较判定变化 → 重新渲染
// memo 不仅没跳过渲染，还额外增加了浅比较的开销
```

```tsx
// ✅ 正确：不在高频变化的组件上使用 memo
function LiveDashboard() {
  const [data, setData] = useState([]);

  useEffect(() => {
    const timer = setInterval(() => {
      setData(fetchLatestData());
    }, 100);
    return () => clearInterval(timer);
  }, []);

  return <Chart data={data} />;
}
// 去掉 memo，避免不必要的浅比较开销
// 高频变化的 props 不适合用 memo 优化
```

**原因：** props 高频变化时，浅比较始终判定为变化，memo 的跳过渲染机制无法生效，反而增加了比较开销。

### 7. 深层嵌套对象 — 浅比较的陷阱

```tsx
// ⚠️ 有风险：浅比较只比较第一层引用，不比较深层属性
function SettingsPanel({ config }: { config: { theme: { color: string; size: number } } }) {
  return <div>配置面板</div>;
}
export const MemoSettingsPanel = memo(SettingsPanel);

function App() {
  const [color, setColor] = useState('blue');

  // ❌ 每次渲染都创建新 config 对象
  const config = { theme: { color, size: 14 } };

  return <MemoSettingsPanel config={config} />;
}
// 点击改变 color → config 引用变化 → 浅比较判定变化 → 重新渲染
// 虽然结果正确，但每次渲染都创建新 config，useMemo 更合适
```

```tsx
// ✅ 正确：用 useMemo 缓存嵌套对象
function App() {
  const [color, setColor] = useState('blue');

  const config = useMemo(() => ({ theme: { color, size: 14 } }), [color]);

  return <MemoSettingsPanel config={config} />;
}
// color 不变 → useMemo 返回同一引用 → 浅比较命中缓存 → 跳过渲染
// color 变化 → useMemo 创建新引用 → 浅比较判定变化 → 重新渲染
```

**原因：** 浅比较只比较 props 第一层引用，不比较深层属性。内联创建嵌套对象会导致引用不稳定；用 `useMemo` 缓存后引用稳定，memo 缓存生效。

### 8. 对比总结

| 场景 | 写法 | 引用是否稳定 | memo 是否有效 | 原因 |
|------|------|------------|-------------|------|
| 基本类型 props | `name={name}` | 值变引用必变 | ✅ 有效 | 值变化时引用必然不同 |
| 父组件传入的稳定对象 | `<Child data={stableData} />` | 是 | ✅ 有效 | 引用不变，浅比较命中缓存 |
| useMemo 缓存的对象 | `useMemo(() => ({ x: 1 }), [])` | 是 | ✅ 有效 | 依赖不变时引用稳定 |
| useCallback 缓存的回调 | `useCallback(() => doSomething(), [])` | 是 | ✅ 有效 | 依赖不变时引用稳定 |
| 内联对象字面量 | `meta={{ x: 1 }}` | 否 | ❌ 无效 | 每次渲染创建新对象 |
| 内联箭头函数 | `onClick={() => doSomething()}` | 否 | ❌ 无效 | 每次渲染创建新函数 |
| 高频变化 props | `setData(fetchData())` 每 100ms | 否 | ❌ 无效 | 始终判定为变化，增加比较开销 |
| 深层嵌套对象（引用不变） | `config={{ theme: { color } }}`，color 变化但 config 引用不变 | 是 | ⚠️ 有风险 | 浅比较不深入，可能跳过必要更新 |

memo 并非银弹，应在确认存在性能问题后再优化，避免滥用。它的适用前提是：props 稳定且组件渲染成本较高：

```tsx
// 小组件直接内联，无需 memo
function StatusTag({ status }: { status: string }) {
  return <span>{status === 'done' ? '已完成' : '进行中'}</span>;
}

// 成本高的列表项组件才考虑 memo
const MemoWorkRecordItem = memo(WorkRecordItem);
```

- **先测量后优化**：确认组件渲染是性能瓶颈后，再决定是否使用 memo
- **避免滥用**：简单的原生标签或很小的组件，memo 带来的比较开销可能大于收益
- **副作用组件**：memo 不会跳过内部使用了 `useContext` 或响应式依赖的组件的更新
- **对照验证**：优化前后用 React DevTools Profiler 对比渲染次数，验证优化是否有效

## 常见陷阱

### 1. 内联对象与箭头函数导致缓存失效

```tsx
// 错误：内联对象导致缓存失效，组件每次仍会重新渲染
function WorkRecordList({ records }: { records: WorkRecord[] }) {
  return (
    <ul>
      {records.map((record) => (
        <MemoWorkRecordItem
          key={record.id}
          record={record}
          metadata={{ source: 'manual' }}
        />
      ))}
    </ul>
  );
}

// 正确：使用 useMemo 缓存对象引用
function WorkRecordList({ records }: { records: WorkRecord[] }) {
  const metadata = useMemo(() => ({ source: 'manual' }), []);

  return (
    <ul>
      {records.map((record) => (
        <MemoWorkRecordItem key={record.id} record={record} metadata={metadata} />
      ))}
    </ul>
  );
}
```

**为什么会失败：** 父组件每次渲染时，JS 引擎执行到 `{{ source: 'manual' }}` 都会创建一个全新的对象实例，分配新的内存地址。即使两次渲染的对象内容完全相同（key 和 value 都一样），它们的引用地址也不同。memo 内部调用 `Object.is(prevProps.metadata, nextProps.metadata)` 比较的是引用地址而非内容，`Object.is(新对象, 旧对象)` 返回 false，memo 判定 props 已变化，从而跳过缓存、触发子组件重新渲染。内联箭头函数同理，`() => {}` 每次渲染创建新函数实例，引用地址不同，浅比较永远判定为变化。

---

### 2. 把 memo 用于频繁变化的数据

```tsx
// 错误：时间戳每次渲染都在变，memo 完全失效
function LiveClock() {
  const [now, setNow] = useState(new Date());

  useEffect(() => {
    const timer = setInterval(() => setNow(new Date()), 1000);
    return () => clearInterval(timer);
  }, []);

  return <MemoClockDisplay time={now.toLocaleTimeString()} />;
}

// 正确：仅对相对静态的 props 使用 memo
function LiveClock() {
  const [now, setNow] = useState(new Date());

  useEffect(() => {
    const timer = setInterval(() => setNow(new Date()), 1000);
    return () => clearInterval(timer);
  }, []);

  return (
    <div>
      <MemoStaticHeader title="当前时间" />
      <p>{now.toLocaleTimeString()}</p>
    </div>
  );
}
```

**为什么会失败：** `setNow(new Date())` 每秒触发一次父组件重渲染，`now.toLocaleTimeString()` 的值每秒都在变化。memo 浅比较 `Object.is('10:30:00', '10:30:01')` 返回 false，判定 props 已变化，子组件必然重新渲染。此时 memo 不仅没有跳过任何渲染，反而每次都要执行浅比较的逻辑判断，增加了额外的性能开销。memo 的设计初衷是"props 不变时跳过渲染"，当 props 始终变化时，这个设计前提不成立，memo 就失去了存在的意义。

---

### 3. 只包裹单个元素而非列表项组件

```tsx
// 错误：包裹整个列表，map 内部每个 WorkRecordItem 仍各自重渲染
const MemoWorkRecordList = memo(function WorkRecordList({ records }) {
  return (
    <ul>
      {records.map((record) => (
        <WorkRecordItem key={record.id} record={record} />
      ))}
    </ul>
  );
});

// 正确：把 memo 用在列表项组件上，控制渲染粒度
const MemoWorkRecordItem = memo(WorkRecordItem);

function WorkRecordList({ records }: { records: WorkRecord[] }) {
  return (
    <ul>
      {records.map((record) => (
        <MemoWorkRecordItem key={record.id} record={record} />
      ))}
    </ul>
  );
}
```

**为什么会失败：** 当 memo 包裹整个 `WorkRecordList` 时，缓存的粒度是整个列表组件。父组件任何状态变化导致 `WorkRecordList` 重渲染，memo 都会判断其 props（即 `records`）是否变化。即使 `records` 引用未变，列表内部的筛选、排序等逻辑可能生成新的数组引用，导致 memo 判定 props 变化而整体重渲染。更关键的是，即使 `records` 引用不变，`WorkRecordList` 重渲染时会重新执行 `records.map()`，每次 map 都会创建新的 React 元素，内部的 `WorkRecordItem`（未被 memo 包裹）会无条件重新渲染。memo 只缓存了外层组件，内层每个列表项的渲染完全不受控制。正确的做法是将 memo 用在列表项组件上，让每个 `WorkRecordItem` 独立判断自己的 props 是否变化，实现细粒度的渲染控制。

---

## 总结

memo 是 React 提供的最常用的组件级性能优化手段：

- **作用**：props 未变化时跳过组件重新渲染，直接复用上一次渲染结果
- **原理**：基于 `Object.is` 对 props 做浅比较，对象和函数比较的是引用而非内容
- **适用**：列表项等展示型组件，父组件频繁重渲染但子组件 props 稳定的场景
- **限制**：内联对象、内联回调会破坏缓存；频繁变化的 props 让 memo 失去意义
- **实践**：与 useCallback、useMemo 配合使用，先确认性能问题再优化，避免滥用
