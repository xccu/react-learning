## ADDED Requirements

### Requirement: 用户能够查看用户列表
系统必须显示所有用户的列表，每条记录展示用户名、角色和创建时间。

#### Scenario: 显示用户列表
- **WHEN** 用户访问用户管理页面
- **THEN** 系统渲染用户列表，展示用户名、角色标识和创建时间

#### Scenario: 空状态显示
- **WHEN** 没有任何用户记录
- **THEN** 显示"暂无用户数据"的提示信息

#### Scenario: 用户列表分页
- **WHEN** 用户记录数量超过每页条数
- **THEN** 使用 Ant Design Pagination 组件展示分页控件，默认每页 5 条

### Requirement: 用户能够按条件查询用户
系统必须支持按用户名和角色过滤用户列表；无查询条件时显示全部记录。

#### Scenario: 按用户名查询
- **WHEN** 用户在查询表单中输入用户名点击"查询"
- **THEN** 列表仅显示用户名匹配的用户

#### Scenario: 按角色查询
- **WHEN** 用户在查询表单中选择角色点击"查询"
- **THEN** 列表仅显示角色匹配的用户

#### Scenario: 组合查询
- **WHEN** 用户同时输入用户名和选择角色点击"查询"
- **THEN** 列表仅显示同时满足用户名和角色条件的用户

#### Scenario: 清空查询条件
- **WHEN** 用户点击"清空"按钮
- **THEN** 查询条件清空，列表恢复显示全部用户

#### Scenario: 无查询条件时显示全部
- **WHEN** 查询条件为空
- **THEN** 列表显示全部用户

### Requirement: 用户能够查看用户详情
系统必须允许用户查看某条用户记录的详细信息，详情页为只读展示。

#### Scenario: 查看详情
- **WHEN** 用户点击用户列表中的"详情"按钮
- **THEN** 系统导航到用户详情页，只读展示用户的所有字段

#### Scenario: 详情页字段展示
- **WHEN** 用户详情页渲染
- **THEN** 展示用户名、角色、创建时间等字段，使用纯文本展示，不可编辑

#### Scenario: 从详情页返回列表
- **WHEN** 用户在详情页点击"返回列表"按钮
- **THEN** 系统导航回用户列表页

#### Scenario: 从详情页进入编辑
- **WHEN** 用户在详情页点击"编辑"按钮
- **THEN** 系统导航到用户编辑页，并预填现有数据

#### Scenario: 用户不存在时显示提示
- **WHEN** 用户访问一个不存在的用户 ID 的详情页
- **THEN** 系统显示"未找到该用户"提示，并提供返回列表入口

### Requirement: 用户能够新增用户
系统必须允许用户通过独立表单页面新增用户，包含用户名和角色选择。

#### Scenario: 打开新增页面
- **WHEN** 用户在用户列表页点击"新增用户"按钮
- **THEN** 系统导航到用户新增页面，显示空表单

#### Scenario: 成功新增用户
- **WHEN** 用户在新增表单填写用户名、选择角色后点击"提交"
- **THEN** 系统创建用户记录，导航回用户列表页，列表刷新显示新用户

#### Scenario: 用户名必填校验
- **WHEN** 用户未填写用户名点击"提交"
- **THEN** 系统提示"请输入用户名"，不执行新增操作

#### Scenario: 角色必填校验
- **WHEN** 用户未选择角色点击"提交"
- **THEN** 系统提示"请选择角色"，不执行新增操作

#### Scenario: 取消新增返回列表
- **WHEN** 用户在新增页点击"取消"或"返回列表"按钮
- **THEN** 系统导航回用户列表页，不执行新增操作

### Requirement: 用户能够编辑用户
系统必须允许用户通过独立表单页面编辑已有用户信息，编辑时预填现有数据。

#### Scenario: 进入编辑模式
- **WHEN** 用户点击某条用户记录的"编辑"按钮
- **THEN** 系统导航到用户编辑页，表单预填该用户的现有数据

#### Scenario: 成功编辑用户
- **WHEN** 用户修改表单数据后点击"提交"
- **THEN** 系统更新用户记录，导航回用户列表页，列表刷新

#### Scenario: 用户不存在时显示提示
- **WHEN** 用户访问一个不存在的用户 ID 的编辑页
- **THEN** 系统显示"未找到该用户"提示，并提供返回列表入口

#### Scenario: 取消编辑返回列表
- **WHEN** 用户在编辑页点击"取消"或"返回列表"按钮
- **THEN** 系统导航回用户列表页，不执行编辑操作

### Requirement: 用户能够删除用户
系统必须允许用户删除用户记录，删除前须二次确认。

#### Scenario: 删除用户
- **WHEN** 用户点击某条用户记录的"删除"按钮
- **THEN** 系统弹出 Ant Design Popconfirm 确认弹窗，用户确认后该记录从列表中移除

#### Scenario: 取消删除
- **WHEN** 用户在确认弹窗中点击"取消"
- **THEN** 记录保持不变，不执行删除

### Requirement: 用户角色使用下拉选择
系统必须使用 Ant Design Select 组件选择用户角色，角色为固定选项。

#### Scenario: 角色选项展示
- **WHEN** 用户在新增或编辑用户表单中查看角色字段
- **THEN** 角色字段显示下拉选择框，选项包括"管理员"和"普通用户"

#### Scenario: 角色标识展示
- **WHEN** 用户列表或详情页展示用户记录
- **THEN** 角色列使用 Ant Design Tag 组件展示角色标识，管理员=蓝色，普通用户=绿色

### Requirement: 用户列表页包含查询表单
系统必须在用户列表页顶部展示查询表单，包含用户名输入、角色选择和查询/清空按钮。

#### Scenario: 查询表单展示
- **WHEN** 用户访问用户列表页
- **THEN** 页面顶部显示查询表单，包含用户名输入框、角色下拉选择、查询按钮、清空按钮和新增用户按钮

#### Scenario: 查询表单使用 Ant Design 组件
- **WHEN** 用户列表页渲染查询表单
- **THEN** 使用 Ant Design Form（layout="inline"）、Input.allowClear、Select.options、Button、Space 组件
