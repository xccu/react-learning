## ADDED Requirements

### Requirement: 驳回工时编辑时显示提示横幅
当工时状态为"已驳回"时，编辑界面必须在表单顶部显示 Alert 提示横幅，告知用户此工时已被驳回，保存后将重新提交审批。

#### Scenario: 驳回状态的工时显示提示横幅
- **WHEN** 用户进入状态为"已驳回"的工时编辑页面
- **THEN** 表单顶部显示 Alert 提示横幅，内容为"此工时已被驳回，保存后将重新提交审批"

#### Scenario: 非驳回状态的工时不显示提示横幅
- **WHEN** 用户进入状态为"待审批"或"已通过"的工时编辑页面
- **THEN** 表单顶部不显示提示横幅

### Requirement: 驳回工时编辑时按钮文案变化
当工时状态为"已驳回"时，编辑界面的保存按钮文案必须变为"保存并重新提交"。

#### Scenario: 驳回状态的工时按钮文案变化
- **WHEN** 用户进入状态为"已驳回"的工时编辑页面
- **THEN** 保存按钮文案显示为"保存并重新提交"

#### Scenario: 非驳回状态的工时按钮文案不变
- **WHEN** 用户进入状态为"待审批"或"已通过"的工时编辑页面
- **THEN** 保存按钮文案显示为"保存修改"

### Requirement: 点击保存并重新提交后重置状态
当用户在驳回状态的工时编辑页面点击"保存并重新提交"按钮时，系统必须将工时状态重置为"待审批"并清空驳回原因。

#### Scenario: 点击保存并重新提交后状态重置
- **WHEN** 用户在驳回状态的工时编辑页面点击"保存并重新提交"按钮
- **THEN** 工时状态变更为"待审批"，驳回原因（rejectReason）被清空

#### Scenario: 点击保存并重新提交调用submitEntry API
- **WHEN** 用户点击"保存并重新提交"按钮
- **THEN** 系统调用 submitEntry API（PUT /time-entries/:id/submit）或 dispatch submitEntry action
