## 6. 快捷登录链接点击后未自动填充密码

**现象：** 点击登录页的 admin/user1/user2 超链接后，表单未自动填充用户名和密码

**原因：** 两步问题：
1. 修改 `QUICK_LOGIN_USERS` 为只含 `{ username, label }` 后，`useEffect` 中仍尝试读取 `user.password`，导致 `undefined`
2. `useEffect` 只在依赖变化时执行，首次从 `/login/admin` 进入时 `location.pathname` 没有变化，effect 不会触发

**解决方案：**
1. 新增 `QUICK_LOGIN_MAP` 对象存储 username → password 映射
2. `useEffect` 改为 `useLayoutEffect`，在 DOM 渲染后立即执行

**文件：** `src/pages/LoginPage.tsx`

```tsx
// 修复前：QUICK_LOGIN_USERS 不含密码，useEffect 读取 user.password 为 undefined
const QUICK_LOGIN_USERS: { username: string; password: string; label: string }[] = [
  { username: 'admin', password: 'admin123', label: '管理员' },
  { username: 'user1', password: 'user123', label: '普通用户' },
  { username: 'user2', password: 'user123', label: '普通用户' },
]

// 修复后：分离密码映射和账号列表
// ← 修复行：新增 QUICK_LOGIN_MAP 存储密码映射
const QUICK_LOGIN_MAP: Record<string, string> = {
  admin: 'admin123',
  user1: 'user123',
  user2: 'user123',
}

// ← 修复行：QUICK_LOGIN_USERS 只保留显示信息
const QUICK_LOGIN_USERS: { username: string; label: string }[] = [
  { username: 'admin', label: '管理员' },
  { username: 'user1', label: '普通用户' },
  { username: 'user2', label: '普通用户' },
]

// 修复前：useEffect 首次渲染不触发
useEffect(() => {
  const path = location.pathname
  if (path.startsWith('/login/')) {
    const username = path.replace('/login/', '')
    const user = QUICK_LOGIN_USERS.find((u) => u.username === username)
    if (user) {
      form.setFieldsValue({ username: user.username, password: user.password })  // ← 修复行：user.password 为 undefined
    }
  }
}, [location.pathname, form])

// 修复后：useLayoutEffect + 使用 QUICK_LOGIN_MAP
// ← 修复行：useEffect 改为 useLayoutEffect，DOM 渲染后立即执行
useLayoutEffect(() => {
  const path = location.pathname
  if (path.startsWith('/login/')) {
    const username = path.replace('/login/', '')
    // ← 修复行：从 QUICK_LOGIN_MAP 读取密码，而非 user.password
    const password = QUICK_LOGIN_MAP[username]
    if (password) {
      form.setFieldsValue({ username, password })
    }
  }
}, [location.pathname, form])
```

## 8. 详情页面一直显示"加载中"

**现象：** 访问工时详情页后一直显示"加载中..."，控制台报 antd `destroyOnClose` 废弃警告，直到刷新浏览器才正常

**原因：** `useEffect` 中先调用 `getEntryById`，然后 `.finally(() => setLoading(false))` 立即执行，`loading` 变为 `false` 后页面跳到"未找到该工时记录"状态。同时 `entry` 从 Redux store 读取，如果 store 中已有该记录，`useEffect` 中 `if (entry) return` 会跳过，但 `loading` 初始值仍为 `true`，永远显示加载中

**解决方案：** 删除 `loading` state，改为从 Redux store 同步读取（`useSelector` 是同步的，不需要 loading 状态）

**文件：** `src/pages/TimeEntryDetailPage.tsx`

```tsx
// 修复前：使用 loading state 导致永远显示加载中
function TimeEntryDetailPage() {
  const { id } = useParams()
  const [entry, setEntry] = useState<TimeEntry | null>(null)  // ← 修复行：删除此 state
  const [loading, setLoading] = useState(true)  // ← 修复行：删除此 state
  const [error, setError] = useState<string | null>(null)
  const dispatch = useDispatch<AppDispatch>()

  // 从 Redux Store 读取所有工时记录
  const entries = useSelector((state: RootState) => state.timesheet.entries)
  const entry = entries.find((e) => e.id === id) ?? null  // ← 修复行：改为从 Redux 读取

  // 修复前：loading 永远为 true
  useEffect(() => {
    if (!id) return
    if (entry) return
    setLoading(true)  // ← 修复行：删除
    setError(null)
    getEntryById(id)
      .then((data) => setEntry(data))
      .catch((err) => setError(err instanceof Error ? err.message : '加载失败'))
      .finally(() => setLoading(false))  // ← 修复行：删除
  }, [id])

  // 修复前：loading 永远为 true，永远显示加载中
  if (loading) {  // ← 修复行：删除此判断
    return <p className={styles.status}>加载中...</p>
  }

  // 修复后：直接从 Redux 读取，无需 loading
  if (error || !entry) {
    return (
      <div className={styles.status}>
        <p className={styles.errorText}>{error === '记录不存在' ? '未找到该工时记录' : '加载失败'}</p>
        <Link to="/" className={styles.backLink}>返回列表</Link>
      </div>
    )
  }
}
```

## 10. 工时列表点击驳回/通过后，详情页状态没有更新

**现象：** 在工时列表页点击"通过"或"驳回"按钮后，审批状态在 Redux store 中已更新，但详情页仍显示"待审批"

**原因：** 详情页通过 `getEntryById(id)` 从 mockApi 的内存数组读取数据，而审批操作更新的是 Redux store，两者数据不同步

**解决方案：** 详情页和编辑页改为从 Redux store 读取数据（`useSelector`），审批/驳回后自动更新

**文件：** `src/pages/TimeEntryDetailPage.tsx`

```tsx
// 修复前：从 API 读取，与 Redux store 不同步
const [entry, setEntry] = useState<TimeEntry | null>(null)
useEffect(() => {
  if (!id) return
  setLoading(true)
  setError(null)
  getEntryById(id)  // ← 修复行：改为从 Redux 读取
    .then((data) => setEntry(data))
    .catch((err) => setError(err instanceof Error ? err.message : '加载失败'))
    .finally(() => setLoading(false))
}, [id])

// 修复后：从 Redux Store 读取，审批/驳回后自动同步
const entries = useSelector((state: RootState) => state.timesheet.entries)
const entry = entries.find((e) => e.id === id) ?? null

useEffect(() => {
  if (!id) return
  if (entry) return  // ← 修复行：如果 Redux 中已有，跳过 API 请求
  setError(null)
  getEntryById(id)
    .then((data) => dispatch(setEntries([data])))
    .catch((err) => setError(err instanceof Error ? err.message : '加载失败'))

```

## 12. 登录页添加用户名/密码校验

**现象：** 用户输入不存在的用户名或错误密码时，API 返回错误但前端没有针对性提示

**原因：** 登录逻辑直接调用 API，API 失败后才显示通用错误，缺少前端快速校验

**解决方案：** 在 `handleFormSubmit` 中先校验用户名密码是否正确（查 `QUICK_LOGIN_MAP`），不正确时通过 `form.setFields` 设置字段级错误信息，校验通过后才调用 API

**文件：** `src/pages/LoginPage.tsx`

```tsx
// 修复前：直接调用 API，失败后才显示通用错误
const handleFormSubmit = async (values: LoginFormValues) => {
  try {
    const user = await loginApi(values.username.trim(), values.password)  // ← 修复行：添加前端校验
    // ...
  } catch (err) {
    message.error(err instanceof Error ? err.message : '登录失败')
  }
}

// 修复后：先前端校验，再调用 API
const handleFormSubmit = async (values: LoginFormValues) => {
  // ← 修复行：新增前端快速校验
  const username = values.username.trim()
  const password = values.password
  const expectedPassword = QUICK_LOGIN_MAP[username]
  if (!expectedPassword) {
    form.setFields([
      { name: 'username', errors: ['用户名不存在'] },
      { name: 'password', errors: [] },
    ])
    return
  }
  if (password !== expectedPassword) {
    form.setFields([
      { name: 'username', errors: [] },
      { name: 'password', errors: ['密码错误'] },
    ])
    return
  }

  try {
    const user = await loginApi(username, password)
    // ...
  } catch (err) {
    message.error(err instanceof Error ? err.message : '登录失败')
  }
}
```
